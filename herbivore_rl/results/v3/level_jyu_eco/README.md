# 팀 생태계 맵에서 우리 시험 (10-25) — `/Game/EcoTest/Maps/LV_EcoV3_JYUEcosystem`

사용자 지시(10-24): "그 사람 레벨디자인을 그대로 복사해와서 우리 레벨에서 테스트하자 — 우리가 하던 방식의 테스트를 그사람 맵을 받아와서 하자".
맵은 조연우 님 `LV_JYU_Ecosystem` 의 우리 복사본이다(`f46685d`, [`../jyu_map/README.md`](../jyu_map/README.md)).
레벨·C++·팀 에셋·게임 기본 두뇌(R1b-F)·기본 설정은 바꾸지 않았다. 있던 코드에서 바꾼 것은 파이썬 변환기 한 곳뿐이다(아래 '바꾼 것').

## 결론 먼저 (쉬운 말)

- **두 길 두뇌(R7e)는 팀 맵에서도 더 잘 숨는다.**
  - 팀 기능을 끈 대조 모드다. 늑대에게 쫓긴 일 100 번 가운데 끝에 은신처에 숨은 것이 약 12 번에서 약 21 번으로 늘었다(11.55% → 20.90%).
  - 우리 맵에서 잰 값(11.47% → 20.69%)과 거의 같다.
  - 잡힌 몫·도망 시작 횟수는 거의 그대로다.
- **파이썬 거울과 맞는다.** 같은 지형·나무(없음)·은신처·날씨로 만든 파이썬 세계도 10.65% → 20.28% 였다.
  - 늘어난 크기(+9.35 %p 대 +9.63 %p)가 파이썬을 여러 번 돌린 폭 안이다.
  - 다섯 지표 모두 같은 방향이고, 크기 차이도 모두 폭 안이다(크기 z 가 모두 ±0.71 안).
  - 확인 470 칸이 모두 맞았다. 같은 시드를 다시 돌리면 지역 기록이 모두 똑같다.
- **팀 기능을 모두 켠 전체 모드에서는 숨음 이득이 더 크다(언리얼만, 판정 아님).**
  - 17.1% → 32.9% (+15.9 %p)이고, 잡힌 몫은 대조 모드의 절반쯤(2.6%)이다.
  - **이 차이는 거의 다 팀 life 에서 온다.** 팀 기능을 하나씩 끈 판에서 life 만 끄면 숨음 비율·잡힌 몫·도망 시작이 대조 모드 값으로 돌아온다
    (숨음 비율 11.0% → 20.5%, 잡힌 몫 5.3%). 식생·날씨·이주만 끈 판은 전체 모드와 비슷하다.
  - Highland 의 먹이는 240 초에 처음의 2~3% 까지 줄고 사슴 기운이 거의 바닥이다. 이것은 팀 식생(soil-v1) 때문이다. 식생만 끄면 49~60% 가 남는다.
  - 팀 날씨는 고지의 눈을 비·맑음으로 바꾼다(팀에는 눈이 없다).
  - 전체 모드는 같은 시드라도 판마다 값이 꽤 흔들린다. 팀 날씨를 실제 시간으로 읽기 때문이다.
- **식생 끄기는 레벨·C++ 를 고치지 않고 풀었다.**
  - 실행 때 엔진 콘솔 명령 한 줄(`setnopec EcoCreatureIntegrationSpawner bEnableVegetation False`)로 이번 Play 의 값만 끈다.
  - 그러면 스냅숏이 써진다. 먹이 지도가 C++ 처음 지도와 0 차이로 같으니, 식생이 정말 꺼졌다는 뜻이다.
- **실시간 고리도 이 맵에서 끝까지 돈다.** 다만 보통 속도에서는 팀 날씨가 너무 자주 바뀐다.
  - 보통 속도에서는 팀 비가 1 초마다 조금씩 바뀌어 환경 판이 150 초에 92 번 올라간다.
  - 그래서 판(약 38 초)을 끝내기 전에 새 스냅숏이 와서, 네 판 가운데 세 판이 중간에 그만뒀다. 게임 안에서는 한 번도 두뇌가 바뀌지 않았다.
  - 게임을 0.15 배속으로 돌리면 판이 끝난다. 환경 바뀜 → 스냅숏 → 이어 배우기 → 관문 → 두뇌 바꿈이 두 번 끝까지 돌았다.
    - 관문은 두 번 다 기각이었다. 시험 크기라 예상된 결과이고, 시험 내보내기(`--force-export`)로 교체 경로만 확인했다.
- **촬영**: 이 맵에서 사슴 떼가 은신처로 모여드는 장면과 화면 줄(길·도망·먹이·두뇌·환경 바뀜 알림)을 확인했다.
  - 정지 화면 5 장은 `week8_assets/level_jyu/` 에 있다(저장소 밖).
  - 늑대·사슴을 따라가는 방식은 이 맵의 팀 몸(BP_JYU)을 찾지 못해 쓰지 못했다.

## 2. 식생 끄기 (남은 것 1 풀이)

- 식생 켬은 v3 무대를 만들 때 한 번만 읽는다(`EcoPolicyV3IntegratedSubsystem.cpp`, `Config.Vegetation.bEnabled = 요청 || Spawner->bEnableVegetation`).
  - 무대는 8 프레임에 만들어지고 `-ExecCmds` 는 0 프레임에 들어간다.
  - 그래서 `setnopec EcoCreatureIntegrationSpawner bEnableVegetation False` 를 `-ExecCmds` 에 더하면 이번 Play 의 조정자 값만 꺼진다.
  - `setnopec` 은 엔진 기본 콘솔 명령이다. 편집 알림 없이 값만 바꾼다.
  - 이 값을 읽는 곳은 무대 만들기와 날씨 보기 연출 한 곳(시작 때 읽음, 그리기만)뿐이다. 팀 BP 그래프는 이 값을 읽지 않는다(에셋에서 이 이름이 나오는 것은 조정자 액터 하나뿐).
- 확인:
  - `[EcoVegetation] Enabled` 줄 0, 스냅숏 거부 0 이다.
  - 스냅숏 20 개 모두 먹이 용량이 C++ 난수로 다시 만든 처음 지도와 최대 차이 0 이다(`convert.json` 확인 줄).
  - 같은 인수로 따로 띄운 판끼리 스냅숏이 같다.
- 전체 모드는 이 명령을 쓰지 않는다(맵 값 그대로 켬).

  - 무리 이주는 큰 차이를 만들지 않았다. 이주가 일어난 세션이 10 개 가운데 3 개뿐이다.
  - 전체 모드의 흔들림(다시 돌림 차이)이 있어 작은 차이(±1 %p 안팎)는 읽지 않는다.
  - 끈 것이 정말 꺼졌는지 기록으로 확인했다(두뇌마다 10 판 합): life 만 끈 판의 `[EcoLife]` 줄 0, 식생만 끈 판의 식생 켬 줄 0, 환경 감시만 끈 판의 환경 바뀜 0,
    이주만 끈 판의 이주 계획 0 이다. 나머지 기능은 켜진 채였다. 모든 판에서 은신처 안 잡힘·지형 막힘·EcoV3I 경고는 0 이다.
