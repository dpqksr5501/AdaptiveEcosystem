# 야생 1단계 — 언리얼 통합 v3 와 파이썬 거울 견줌 (10-16)

사람 결정 10-15 (7) 이식(C++ c6f1c7f·c464229·496bbec·857da45) 뒤, 통합 v3 기본값(야생 규칙 다섯 개 켬)으로 팀 레벨을 머리 없이 돌린 기록을
파이썬 거울(`configs/v3_wild1_mirror.yaml`)과 견줬다.

## 결론

- **산·잡힘·굶음은 언리얼과 파이썬이 거의 같다.** 60·120·180·230초 모두 차이가 0.2%p 안이다(128마리 230초 96.9·3.1·0.0 대 97.0·3.0·0.0,
  64마리 94.1·5.9·0.0 대 94.0·6.0·0.0). 두 쪽 모두 240초 안에 굶어 죽는 사슴이 없다.
- 표본 흔들림 안이다. z 는 대부분 |z| < 2 이고, 넘는 곳은 128마리 180초 잡힘 하나(z +2.3)다. 그 차이는 지역 하나에 0.25마리꼴(0.2%p)이다.
  포만 때문에 늑대가 지역마다 거의 늘 4마리를 잡아서 파이썬 세션 편차가 아주 작고, 그래서 z 가 커졌다.
- **규칙 수치도 같다.** 약함(비축으로 사는 몸)·늑대 배부름·먹는 중·경계·도주·웅크림·도주 시작 수·은신처에서 끝난 도주·도망·숨기 행동·남은 비축이
  모두 |z| < 2 다. 예외는 128마리 독립 지도의 늑대 배부름(z +3.2)·먹는 중(z +2.9) 둘이다. 이것은 집계 구간 차이다. 언리얼은 230초까지만
  더했고 파이썬은 240초까지 더했다. 늑대·스텝 분모를 맞추면(× 1800/1725) 파이썬 49.2%·4.1%, 언리얼 51.2%·4.3%(z 약 +1.6·+1.7)다.
- **하나 지켜볼 것: 사슴 에너지 평균이 언리얼에서 4~6점 낮다**(z 약 −1, 시각마다 같은 방향). 야생 규칙 전 거울 비교에서는 언리얼이 0~4점 높았다.
  짝 비교에서는 지도 Barren@20001 의 차이가 가장 크다. 128·64마리 모두 그 지도에서 언리얼 사슴이 덜 먹는다. 64마리 첫 1분의 '먹기 중
  실제로 먹은 비율'은 46~67%다. 같은 시각 Barren@20000 은 62~84%, 야생 규칙 전 같은 지도는 47~99%였다. 그래서 먹이는 남는데 약한 사슴이 많다
  (약함 33%·26% 대 파이썬 반복 범위 8~20%·5~20%, 120초 에너지 29·40 대 52~65·48~73).
  이식 코드에서 뜻이 다른 곳은 찾지 못했다. 약함 속력·경계 걸음·포만 셈은 파이썬 식과 줄마다 대조했다. 비축 계산은 골든 시험(채움·꺼냄 14가지, 굶는 시점)이 맞다.
  원인은 아직 모른다. 지도 하나에서 두 판이 같이 벗어났지만, 짝 비교 지도 9개 가운데 하나라 우연일 수도 있다.
  240초 동안 굶음·잡힘에는 드러나지 않는다. 비축이 바닥나는 긴 판(16분 = 게임 8일)에서는 굶음 차이로 커질 수 있으니 거기서 다시 잰다.
- 그래서 이식은 파이썬과 같다고 본다. 바로 고칠 이식 버그는 없다. 다만 시작 설정 줄 하나의 글이 틀렸다. `[EcoV3I] 사슴 얼기: … | 늑대 식사: …`
  줄이 포만을 켜도 "끝나면 곧바로 사냥 (… 포만 없음)"이라고 적는다. 동작에는 영향이 없다. 바로 다음 줄 `[EcoV3I] 늑대 포만: 켬 …` 이 맞는 내용이다.

## 무엇을 돌렸나

- 언리얼: `/Game/Map/LV_Ecosystem_IntegrationTest -game -EcoIntegratedV3 -EcoV3DeerPerRegion=<128|64> -EcoV3Seed=<s> -benchmark -fps=60
  -seconds=240 -NullRHI -NoSound -unattended -nosplash -nopause -DisablePlugins=Bridge,Fab`. 야생 규칙은 통합 v3 기본값 그대로 켰다
  (지방 비축·늑대 포만·시야 300°·발소리·도주 반사 거리). 옛 경계 거리 실험(KeepAway)은 857da45 에서 없어졌다. `-EcoV3KeepAway=` 는 이제 도주 반사를 끄는 옛 이름이라 넘기지 않았다.
  세션 시드는 20000~20005다. 세션 하나 = 지역 무대 3개(Barren·Forest·Highland)다. 짝 비교는 파이썬이 같은 먹이 지도를 만들 수 있는 20000~20002 만 쓴다.
  오류·ensure 는 0이고 EcoV3I 경고도 0이다(산 사슴이 학습 밀도 하한 아래로 내려가지 않았다).
- 기록: `unreal_logs/s20000-20002/`, `unreal_logs/s20003-20005/`. 이름은 `d<사슴>_s<세션 시드>_k0.log` 이다. 비교에 쓰는 줄만 남겼다(`trim_unreal_log.py`).
- 파이썬(시드 탐색 범위만): 독립 지도 `runs/d128_wild1.json`(32000~32089)·`runs/d64_wild1.json`(33000~33089)은 `run_all.sh` 의 결과를 그대로 쓴다.
  짝 비교 `runs/pairdiag_d<사슴>_wild1_u20000-20002_k10_s…json` 은 언리얼 지도 9개 × 반복 10이다. `--diag` 를 붙여도 기록 줄은 붙이지 않은 판과 같았다(90/90).

```
# herbivore_rl/ 에서
python results/v3/mirror/run_mirror.py --diag --config configs/v3_wild1_mirror.yaml --deer 128 --unreal-maps 20000-20002 --replicates 10 \
    --seeds 32000-32089 --out-dir results/v3/wild1/runs --name pairdiag_d128_wild1_u20000-20002_k10_s32000-32089
python results/v3/mirror/run_mirror.py --diag --config configs/v3_wild1_mirror.yaml --deer 64 --unreal-maps 20000-20002 --replicates 10 \
    --seeds 33000-33089 --out-dir results/v3/wild1/runs --name pairdiag_d64_wild1_u20000-20002_k10_s33000-33089
W=results/v3/wild1
python results/v3/mirror/compare_unreal.py --unreal-dir $W/unreal_logs --python $W/runs/d128_wild1.json $W/runs/d64_wild1.json
python results/v3/mirror/compare_unreal.py --unreal-dir $W/unreal_logs/s20000-20002 --python $W/runs/pairdiag_*.json
python $W/compare_unreal_wild.py --unreal-dir $W/unreal_logs --python $W/runs/d128_wild1.json $W/runs/d64_wild1.json
python $W/compare_unreal_wild.py --unreal-dir $W/unreal_logs/s20000-20002 --python "$W/runs/pairdiag_*.json"
```

- 표 읽기(정의는 `results/v3/mirror/compare_unreal.py`·`compare_unreal_wild.py` 머리 주석): 산·포획·굶음 %는 처음 사슴 대비이고 세션(지역 3개 합)의 평균이다.
  z 는 (언리얼 평균 − 파이썬 평균) ÷ (파이썬 표준편차 ÷ √언리얼 표본 수)다. |z| < 2 면 언리얼 표본 수만큼 뽑을 때 흔히 나오는 차이다.
  규칙 수치 표의 표본은 지역 하나(= 파이썬 세계 하나)다. 언리얼은 0~230초 합이고 파이썬은 0~240초 합이다.
