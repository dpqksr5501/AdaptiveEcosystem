1장. AdaptiveEcosystem 주간 진행 보고 (약 40초)
저희는 Mass 기반 동물 생태계에 환경과 자원, PPO 행동, Social과 감각, 이동, 네트워크 표현을 연결하는 4인 팀 프로젝트를 진행하고 있습니다. 이번에는 제가 맡은 Social과 감각을 중심으로 보고드리겠습니다. 아래 실선은 현재 동물 통합 경로에서 연결한 부분이고, 점선은 앞으로 연결할 환경 공급자입니다. 기존 PPO가 만든 행동에 위험 정보와 은신처 의도를 보정하고, 기존 이동 계층이 이를 실행하도록 연결했습니다. 늑대도 별도의 감각으로 먹잇감을 추적합니다. 왼쪽은 실제 사슴 표현을 확인한 초기 평면 테스트 화면입니다. 현재 적용 대상은 팀의 3지역 레벨이며, 판단은 서버가 하고 Client는 전달받은 결과를 표현합니다.

2장. 행동 의도를 이동과 동물 표현까지 연결했습니다 (약 40초)
지난 발표에서는 지속적인 무리 구성, 무리 경보, 차폐를 고려한 은신처 평가와 슬롯 예약을 설명했습니다. 이번 목표는 그 결과가 실제 게임 동작으로 이어지게 하는 것이었습니다. 은신처 목적지를 이동 계층에 넘기고 도착과 실패 결과를 돌려받아, 이동 중과 점유 상태를 구분하도록 연결했습니다. 또 사슴과 늑대의 BP, 방향 정렬, 애니메이션과 발소리까지 적용했습니다. 제 직접 구현 범위는 감각과 무리·경보·은신처입니다. PPO 학습과 가중치, 실제 위치 계산, 서버 복제 transport는 기존 담당 시스템을 사용했습니다. 그래서 이번 기여는 Social 구현과 기존 시스템을 연결한 통합 작업으로 나누어 보시면 됩니다.

3장. 사슴은 위험을 공유하고, 늑대는 감지한 단서를 추적합니다 (약 45초)
같은 시야·청각·기억을 사용해도 사슴과 늑대의 목적은 다릅니다. 사슴은 시야와 차폐를 확인해 위협을 인지하고, 그 정보를 무리 경보와 대피 의도로 연결합니다. 늑대는 살아 있는 먹잇감을 직접 보고 추적하거나, 사슴의 논리 발걸음 소리를 약한 단서로 사용합니다. 예를 들어 사슴이 늑대의 시야에서 사라지면, 늑대가 사슴의 현재 좌표를 계속 아는 것이 아니라 마지막으로 감지한 위치를 향합니다. 기억은 감쇠하고 도착하거나 만료되면 잊습니다. 소리만 듣고 가까워졌다는 이유로 포식하지 않도록, 최근 직접 시야와 현재 차폐 확인을 요구합니다. 후각은 이번 범위에서 제외했고, 늑대는 PPO 학습 모델이 아닌 기존 포식자 이동 규칙을 사용합니다.

4장. 은신처의 선택·도착·점유·해제를 연결했습니다 (약 45초)
은신처는 목적지만 정하면 끝나는 기능이 아니었습니다. 여러 사슴이 같은 자리를 사용할 수 없게 예약하고, 실제로 도착했는지 확인한 뒤 점유 상태로 바꾸어야 했습니다. 위 흐름에서 감지와 무리 경보, 은신처 선택과 예약, 점유와 반환은 제 Social 영역입니다. 회색의 실제 이동은 기존 계층이며, 제가 목적지와 보정 행동을 전달하고 이동 결과를 돌려받는 연결을 만들었습니다. 이동에 실패하거나 위험에 따른 은신 요구가 끝나면 자리를 반환하고, 죽음·삭제·이주도 정리합니다. 현재 팀 레벨 PIE에서 이동 후 점유와 사망 시 반환을 확인했습니다. 다만 물이나 장애물을 만나 멈추는 가드는 있고, 자동으로 돌아가는 경로 탐색은 아직 없습니다.

5장. 3지역 레벨에 동물 표현과 표면별 발소리를 적용했습니다 (약 45초)
팀의 황무지·숲·고지대 레벨에 논리 지역과 먹이 분포 힌트, 은신처와 동물 런타임을 배치했습니다. 처음에는 사슴 16마리와 늑대 3마리이고, 은신처는 숲에 두 곳입니다. 동물 BP는 실행 중 생성되어 Mass 결과를 표현합니다. 실제 속도 방향에 몸을 맞추고, 속도와 좌우 회전량을 2D BlendSpace에 넣어 재생했습니다. 발소리는 발 접촉 Notify에서 지형의 물리 재질을 검사해 Grass 또는 Dry를 선택합니다. 서버의 AI 소음은 실제 이동 거리로 만들고, Client의 발소리는 로컬 재생만 해서 서로 분리했습니다. 현재 화면은 배치와 표현 흐름을 설명한 도식이고, 3지역 실제 화면과 감각 디버그 캡처는 추가로 확보해야 합니다.

6장. 연결 동작을 확인했고, 환경·학습·운영 검증은 남았습니다 (약 45초)
현재 확인된 결과는 10월 8일 구현 작업에서 남긴 기록을 기준으로 합니다. 직접 UBT 빌드와 전체 자동화 43개가 통과했고, 팀 레벨 PIE에서 늑대 감지와 발소리 출력, 표면 선택, 은신처 이동과 점유·반환을 확인했습니다. 같은 전용 서버에 Client를 두 번 접속해 표현과 Notify 재생 초기화도 확인했습니다. 다만 이것으로 전체 프로젝트가 완성됐다고 보지는 않습니다. 현재 늑대의 감각과 포식 조건은 Python 기본 학습 시나리오와 다르고, 지역 날씨가 식생이나 감각으로 이어지는 공급자 연결도 남아 있습니다. 물은 진입 방지까지이며 마시기 행동은 없습니다. production 플레이어 이동, 장시간·지연·대규모 운영과 패키징 검증도 후속 범위입니다.

7장. 다음 주에는 환경 입력과 학습 조건을 함께 정하겠습니다 (약 40초)
다음 주 계획은 팀과 아직 합의하지 않은 제안입니다. 첫째, 학습 담당과 감각과 포식 조건의 차이를 같은 장면으로 비교하고, 기존 관측을 유지할지 확장할지 정하겠습니다. 둘째, 레벨·환경 담당과 지역 날씨와 논리 낮밤 입력의 공급 지점을 확인하고, 합의한 환경 입력 하나를 연결해보겠습니다. 저는 그 입력을 감각과 은신처 소비 지점에서 확인하겠습니다. 셋째, 네트워크 담당과 실제 플레이어 이동을 통한 관찰 범위 변화와 재진입을 검증하겠습니다. 완료 기준은 비교표와 연결 로그, 동일 장면의 서버·Client 기록으로 남기겠습니다. 교수님께는 환경 입력 하나의 완결을 다음 목표로 잡아도 될지, 그리고 청각을 우선 Social과 추적 계층에서 유지할지 의견을 받고 싶습니다.

[교수님 예상 질문과 답변]

1. 지난 발표와 비교해 이번에 실제로 달라진 것은 무엇인가요?
답변: 지난 자료는 Herd/Alarm/Shelter 의도와 예약 중심이었습니다. 현재 opt-in 동물 경로에서는 그 목적지·보정 행동을 기존 이동이 소비하고, 도착·실패 Feedback으로 점유·반환까지 이어집니다. 사슴·늑대 BP, 감각 추적, 발 접촉음과 팀 레벨 적용도 추가했습니다.

2. PPO가 동물의 감각과 늑대 행동도 전부 학습한 건가요?
답변: 사슴은 기존 7개 관측·4개 행동과 가중치를 유지합니다. 감각은 Social 보정과 늑대의 기존 추적 규칙에 연결했습니다. 늑대 PPO 학습은 이번 구현이 아니며, opt-in 감각·포식 조건의 Python 시나리오 반영 여부는 학습 담당과 합의해야 합니다.

3. 수풀에 들어가면 무조건 안전한가요?
답변: 은신처 평가에는 품질·슬롯과 실제 LOS 차폐를 사용하지만 모든 수풀 Mesh가 시야를 막지는 않습니다. 실제 도착 후 점유를 관리하는 것과 생존을 보장하는 것은 다릅니다. 포식 판정은 직접 시야와 현재 LOS를 요구합니다.

4. 비와 밤낮, 물이 이미 행동을 바꾸나요?
답변: 논리 낮밤 clock을 읽는 경로와 환경 multiplier 소비 지점은 있으나 감각 기본 배율은1입니다. 지역 날씨 공급자·식생 자원 반영·시각 하늘 동기화는 남아 있고, 물은 현재 진입 방지까지입니다. 갈증·마시기 행동이나 야행성 학습 완료로 보지 않습니다.

5. Client에서 소리를 만들면 서버 AI 판단과 어긋나지 않나요?
답변: 서버 AI 소음은 권위 Mass의 실제 이동 거리에서 발생합니다. Client Notify는 수신 표현의 로컬 오디오만 재생하며 AI 소음을 보고하지 않습니다. 같은 서버에 두 번 접속하는 기록은 확인했지만 장시간·지연·대규모와 production 플레이어 검증은 남아 있습니다.
