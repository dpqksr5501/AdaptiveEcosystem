# 08. 공통 폐루프 이후 확장

상태: Deferred. [기본 출생·이주·환경·이동·검증](../README.md) 이후 별도 계약으로 진행한다.

## 필요한 기능과 구현 방향

| 기능 | 전체 구조·구현 방향 | 필요한 기술 |
| --- | --- | --- |
| 시체 자원 | 공통 Death receipt → 시체 자원 생성 → 섭취 예약 → 실제 지급·잔고 감소 → 소멸 | 자원 원장·요청 중복 방지·Smart Object |
| 다종 먹이사슬 | SpeciesId와 식성/역할을 구분하고 위협·먹이 관계표를 감각·공격·섭식에 공통 적용 | 공유 설정·관계 필터·지역×종 집계 |
| 물·체온·stamina | 개체별 생존 상태와 환경 영향을 추가하고 정책 관측·보상·학습을 함께 갱신 | 대사 모델·정책 버전·파리티 |
| 원거리 집계 생태 | 정밀 Mass ↔ 집계 상태 전환 시 개체·자원·시간 보존 | Simulation LOD·상태 변환·통계 모델 |
| 영속 월드·두 대륙 | 작성 Actor 수명과 논리 생태 수명을 분리하고 저장·언로드·복원을 계약화 | World Partition·Save/Load·스키마/epoch |

## 적용 원칙과 완료 기준

늑대 협동 사냥과 장애물 규칙은 v3 PR에 이미 있으므로 신규 공통 기능과 구분해 재사용을 검토한다. 현재 보이는 시체·음식 표현은 위 시체 자원 장부의 완료 증거가 아니다.

개체는 StableAgentId로 복원하며 MassEntityHandle·런타임 인덱스를 저장 식별자로 쓰지 않는다. 비동기 결과는 요청 revision·world epoch 등 수명 검사를 설계한 뒤 적용한다.

확장마다 자원·인구 보존과 Client 읽기 전용 경계를 유지한다. 기본 시나리오의 미검증 항목을 남긴 채 모든 확장을 동시에 진행하지 않는다.
