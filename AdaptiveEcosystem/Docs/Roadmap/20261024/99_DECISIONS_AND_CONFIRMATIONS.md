## 1. 검토 방법

각 항목에 선택, 적용 맵/backend·빌드, 담당, 결정일, 근거, 영향받는 계약·재검증 범위를 기록한다. 원준이 답할 수 있는 제품 선택과 다른 담당자의 규칙 확인을 구분한다. 명시적인 선택 전에는 현재 Source 기본값을 유지한다.

미결 항목이 모든 개발을 막지는 않는다. 읽기 감사·기준선·기존 기능 회귀는 진행할 수 있다. 다만 해당 선택이 바꾸는 gameplay·공통 데이터 형식·실제 에셋 변경은 결정 후 구현한다. 현재 문서 작성 작업은 이 답을 기다리지 않고 완료한다.

- 확인: 1차/후속 분리, 필수 T업무, 대표 맵·backend, 동시 접속/기능 조합, soak 시간·최소 규모를 정한다.
- 권고: G1 소규모 정합성→G2 환경→G3 출생/이주→G4 패키지·성능 순서로 완료를 나누고 T09 같은 선택 기능은 별도 표시한다.
- 담당 확인: 원준 + 전원 일정/기능 합의.
- 의존: T03/T11 전체 완료 선언. 미실행을 Pass로 바꾸지 않는다.
