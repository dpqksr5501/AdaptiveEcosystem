# 02. 영속 식별자 및 초기 데이터 계약 (Identifiers & Base Contracts)

> 본 문서는 프로젝트 전반에서 사용하는 영속 식별자 체계와 기본 데이터 계약의 원칙을 정리한 문서입니다.  
> 세부 C++ 정의는 `Source/AdaptiveEcosystem/Core/EcoIds.h` 및 `Core/EcoRegionTypes.h`를 참조하십시오.

---

## 1. 영속 식별자 원칙 (Persistent Identifiers)

Mass Entity의 내부 핸들, 액터 포인터, ISM 인스턴스 인덱스는 개체가 이동하거나 LOD가 변할 때 수시로 변경되므로 영속 ID로 사용할 수 없습니다. 따라서 다음의 불변 논리 식별자를 사용합니다:

```text
StableAgentId (int64)  : 전역에서 유일하며 개체의 생애주기 동안 보존되는 불변 ID
RegionId (FName)       : 지역 식별자 (예: "Forest_A", "Desert_B")
SpeciesId (FName)      : 종 식별자 (예: "Wolf", "Deer")
WorldEpoch (int32)     : 월드 리셋 또는 주요 상태 전이 시점의 세대 번호
```

### Hot-Path Compact Index
MassEntity의 고속 프로세서 루프에서는 `FName` 해시 연산 비용을 줄이기 위해 캐싱된 컴팩트 인덱스를 병용합니다:
```cpp
int32 RegionRuntimeIndex;
int32 SpeciesRuntimeIndex;
```
- 컴팩트 인덱스와 FName 간의 매핑은 서브시스템/레지스트리 경계에서만 수행합니다.

## 2. 크리처 스폰 및 표현 계약 (Creature Spawn Contract)

논리 엔티티가 플레이어 시야에 들어와 액터로 실체화될 때 전달되는 최소 DTO입니다:

```cpp
USTRUCT(BlueprintType)
struct FCreatureSpawnData
{
    GENERATED_BODY()

    int64 StableAgentId = 0;
    int32 WorldEpoch = 0;
    FName RegionId;
    FName SpeciesId;
    int32 RandomSeed = 0;
};
```

- 액터(`ACreatureCharacter`)는 `InitializeCreature(SpawnData)`를 통해 주입받으며, 서버 생태계 내부의 복잡한 연산 과정을 알 필요 없이 전달받은 스탯과 외형을 표출합니다.
