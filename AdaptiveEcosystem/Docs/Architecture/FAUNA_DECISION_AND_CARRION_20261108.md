# 다종 먹이 선택과 사체 실행 계약

전용 `/Game/JYU/Maps/LV_JYU_Fauna`에서 사냥 자격, 먹이 선택, 위협 반응을 분리한다. 다종 설정이 있는 서버 월드에서만 새 규칙을 실행한다. Native 사슴 PPO와 늑대는 기존 실행 경로를 사용한다.

이 문서는 최초 실행 계약을 기록한다. 사체 단계와 수명은 [쥐·사체 통합](FAUNA_RAT_AND_CARCASS_20261108.md), 살아 있는 먹이와 사체의 비교·냄새·접촉 반격은 [후속 실행 점검](FAUNA_RUNTIME_AUDIT.md#출생-예산과-포획-후속)을 따른다.

## 실행과 데이터 소유권

| 단계 | 실행 규칙 |
| --- | --- |
| 사냥 자격 | 명시적 관계, 같은 지역, 성숙·체급·건강, 지상 여부, 성체 방어, 거리·시야각·차폐를 검사한다. 접촉 순간에 다시 검사한다. |
| 표적 선택 | 자격을 통과한 가시 후보만 거리 비용, 관계 선호도, 건강, 직전 표적 유지 보정으로 비교한다. 동점은 StableAgentId로 결정한다. 공격 대상이 결정됐다고 해서 피식자의 행동을 강제로 바꾸지 않는다. |
| 위험 감지 | 새 동물은 자체 감지 시각에 가까운 활성 추격자를 확인한다. 차폐와 자기 방향을 검사하고 가까운 위협은 방향 범위를 완화한다. 위험 시 식사나 접근을 중단한다. 성숙 까마귀는 에너지와 수직 공간, 지역 내 착륙 후보가 있으면 비상 이륙할 수 있다. 조건을 통과하지 못하면 지상 도주를 사용한다. |
| 사체 생성 | 생존 처리와 M4 사망 영수증이 확정된 뒤 StableAgentId당 한 번 생성한다. Native 늑대의 배정량은 기존 함수의 실제 지급값을 읽는다. Native 생명 이력의 영양 1.0을 공용 장부의 활력 에너지 100으로 환산한다. 새 종은 성숙도와 체급에서 총량을 정한다. 포획자의 직접 지급도 남은 한도 안에서 차감한다. |
| 탐색과 섭식 | 여우·까마귀·돼지는 종별 배고픔 문턱, 거리, 접근 시점에 남을 유효 시간, 차폐, 남은 양을 확인한다. 동종 사체는 기본 후보에서 제외한다. 포획 직후에는 짧게 접근을 보류하고, 지형 이동에 막힌 목표는 해당 개체가 잠시 제외한다. 이동을 멈춘 상태에서 섭식 거리와 차폐를 다시 검사한 뒤, 개체가 실제로 받을 수 있는 양만 차감한다. |
| 번식과 먹이 | 새 육식종은 본인 시야 거리 두 배 이내의 사냥 가능한 먹이 두 개체나, 지난 25초 내 실제로 먹은 사체를 먹이 확보의 근거로 사용할 수 있다. 기존 체력·에너지·짝·지역 상한과 출생 시 재검사도 적용한다. |
| 고갈과 폐기 | 현재 규칙은 생성 뒤 20초 또는 고갈 시 먹이 후보에서 제거한다. 죽은 몸의 기존 표현 수명과 별개다. 사체 소비는 식생 장부에 쓰지 않는다. 지상에 닿기 전에 사망한 새는 현재 공용 먹이로 등록되지 않는다. Native 개체에 이미 배정된 몫을 공용 사체로 되돌리려면 Native의 미섭식·만료 영수증과 재배정 계약이 필요하다. |

## 현장 자료와 적용 범위

- 옐로스톤 관찰에서 늑대가 남긴 몫은 사체 이용 동물의 먹이가 됐다. 데날리 조사에서는 사체 이용에 경쟁과 경계 행동이 관찰됐다. 포획자 몫 이후 남은 양과 짧은 접근 보류를 모델링하는 근거다. 현장 관찰을 3초 접근 보류나 20초 폐기 수치로 환산하지 않았다. [옐로스톤 사체 연구](https://escholarship.org/uc/item/0h09s21c) · [데날리 사체 경쟁 관찰](https://www.nps.gov/articles/000/scavenging.htm)
- 붉은여우 식이 조사에는 작은 포유류·새·유제류 사체가 포함됐고, 미국까마귀도 사체를 먹는다. 현재 레벨의 여우 살아 있는 먹이 관계에는 착지한 까마귀가 있다. 공용 사체는 별도 후보로 사용한다. 작은 포유류는 실제 지역 자원이나 개체가 authoring된 뒤 추가할 수 있다. [붉은여우 식이 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC3109248/) · [Cornell 까마귀 생활사](https://www.allaboutbirds.org/guide/american_crow/lifehistory)
- 표범 관찰에서 먹이 밀도보다 포획 용이성이 중요했다. 현재 규칙은 거리와 건강·방어를 사용한다. 매복 위치와 실제 돌진 경로를 비교하는 단계는 서식지 입력과 별도 검증이 필요하다. [표범 사냥 서식지 연구](https://doi.org/10.1016/j.anbehav.2006.12.014)
- 독일의 야생 멧돼지는 신선한 동종 사체와의 직접 접촉을 대체로 피했다. 일부 관찰에서는 다른 유제류 사체를 먹었다. 짧은 수명의 신선 사체를 다루는 이 맵에서는 동종 섭식을 기본 후보에서 제외한다. [멧돼지 사체 접근 현장 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC5451812/)

## 시스템 경계와 남은 작업

| 영역 | 현재 계약과 다음 적용 조건 |
| --- | --- |
| 식생·서식지 | 공유 식물 셀은 기존 거래를 사용한다. 뿌리·씨앗·풀·어린 가지를 나누려면 계절과 식생에 따라 재생되는 실제 양을 먼저 정의한다. 둥지·횃대·진흙목욕은 명시적 장소 입력과 진입 가능 검증이 필요하다. |
| 학습·Native | 기존 사슴 관측·행동·가중치는 기존 모델 계약을 사용한다. 새 규칙의 가시 후보와 실행 결과를 구분한다. 향후 학습 입력으로 쓰려면 관측 계약과 Python mirror를 검증한다. |
| 복제·저장 | 기존 죽은 몸과 `Investigate`·`Eat` 표현 상태를 사용한다. 사체 잔량은 서버에만 있다. 다종 맵 체크포인트는 기존대로 거부하며, 지원 시 잔량·만료 시각·개체 표적을 같은 시점에 직렬화해야 한다. |
| 규모·행동 확장 | 현재 후보 검사는 opt-in 맵 규모에서 수행한다. 대형 레벨은 지역·공간 인덱스와 감지 예산이 필요하다. 큰 먹잇감 협동 사냥과 어미의 실제 가로막기는 참여 개체, 이탈, 부상과 접촉의 권위 계약이 필요하다. |
| 애니메이션 | 전용 일곱 표현 BP에서 급회전 속도를 제한하고 진행 방향과 몸이 크게 어긋날 때 보행 Blend Space 입력을 줄인다. 사망·이동 권위 위치와 기존 순간이동 스냅을 사용한다. |

자세한 종별 authoring과 기존 실행 이력은 [다종 생태계 테스트 맵과 팀 인계](../조연우/JYU_FAUNA_INTEGRATION_20261108.md)를 따른다.

## 실행 검증

- UE 5.8 직접 UnrealBuildTool 빌드와 전체 `AdaptiveEcosystem` 자동화 297개가 통과했다. 새 사체 회귀 테스트는 지역, 접근 보류, 만료, 동종 접근 설정, 부분 지급, 경쟁 요청의 초과 차감을 검사한다.
- R7e로 300 게임초, 304번째 자원 경계까지 실행했다. 다섯 새 종의 자연 출생을 기록했다. 사체 12개에서 사망별 총량과 초기 배정·잔량을 대조했고, 섭식마다 이전 잔량에서 실제 지급만 차감되는 것을 확인했다. 1개는 고갈됐고 11개는 잔량을 남기고 만료됐다. 까마귀와 돼지가 함께 먹은 42번 사슴 사체는 Native 몫을 떼고 남은 40에서 시작했고 마지막 요청에는 1.5를 지급했다. 동종 사체 섭식은 0건이었다.
- 까마귀의 위험 회피 이륙 16회와 지표 위 최대 약 12.56 m를 관측했다. 최종 실행에서는 까마귀와 돼지의 사체 섭식을 관측했다. 여우의 실제 사체 섭식은 동종 제외 조건을 추가하기 전 실행에서 관측했다. 최종 R7e 실행의 여우는 자연 출생을 포함한 3개체가 모두 기아로 죽었다. 후보 탐색과 사체 장부는 실행됐으며, 이 시드의 공간 배치와 먹이 공급으로는 여우 개체군을 유지하지 못했다.
- 최종 D3D11 PIE의 일곱 표현 모두 180° 강제 방향 전환에서 한 프레임 최대 약 6.0° 회전했다. 이전 재현에서는 약 164°였다. 평지·12° 경사 보행, 달리기·정지·섭식·공격·휴식·사망을 재생했고, 까마귀는 비행 세 단계의 지면 IK 해제를 확인했다. 이 회전 테스트는 합성 표현 입력을 사용한다.
- 내장 R1b-F로 로컬 Dedicated 서버를 80초 실행했다. 시간차 접속한 Client에 일곱 종이 표시됐고 권위 개체와 생태계 스텝은 각각 0이었다. 두 프로세스가 정상 종료했다. `Saved/Logs/FaunaCarrionFinalServer.log`, `FaunaCarrionFinalClient.log`, `Saved/FaunaAudit/CarrionFinalClient.json`을 확인할 수 있다.

로컬 실행 기록은 `Saved/Logs/FaunaCarrionFinalStandalone.log`, `FaunaCarrionFinalMotion.log`, `FaunaCarrionFinalAutomation.log`에 있다. 개체·프레임 수치와 이미지의 경로는 `Saved/FaunaAudit/CarrionFinal300.json`, `CarrionFinalMotionMetrics.json`, `CarrionFinalMotion_turn.png`, `CarrionFinalMotion_feed.png`, `CarrionFinalMotion_fly.png`다.
