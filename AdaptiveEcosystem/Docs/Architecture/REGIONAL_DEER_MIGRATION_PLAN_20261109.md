# 지역 생태 기반 사슴 순차 이주 개발 계획

2026-11-09 첫 구현 후속: [실제 구현·간단 테스트·검증 한계](REGIONAL_DEER_MIGRATION_IMPLEMENTATION_20261109.md)를 먼저 대조한다. 아래는 목표 계약이며 전체 완료 기록이 아니다. opt-in 첫 경로와 자동화13개/Editor 빌드는 통과했고 실제 맵·저장 왕복·멀티 및 일부 상세 진단은 남았다. 구버전 저장 이전은 제공하지 않고 새 체크포인트 v2에서만 순서/episode를 보존한다.

작성일: 2026-11-09. **계획 문서이며 런타임 미구현·미검증이다.** 사용자 요청: 지역 생태 상태를 평가하고, 각 지역에 등록된 사슴의 배열 순서대로 이주 여부를 처리하며, 일정 선에서 추가 이주를 중단한다. 다음 구현 세션은 이 문서를 사슴 이주 판단의 우선 계약으로 읽는다. 기존 풀 패치 개발 전체를 완료하거나 늑대 이주를 구현했다는 뜻은 아니다.

## 1. 현재 구현과 변경 목적

- [현재 이주 코드](../../Source/AdaptiveEcosystem/Mass/EcoHerdMigration.cpp)는 Mass 조회 결과를 StableAgentId 순으로 정렬하고 Persistent Herd별로 묶는다. `Members.Num()<2`이면 지역 부족 평가 전에 제외한다. 이는 사용자 요구와 불일치하므로 새 지역 기반 경로의 자격 조건에서 제거한다.
- 부족 지속 시간도 현재 Herd별이다. 새 경로는 **지역별 부족 상태 → 출발 가능 인원 산정 → 지역 등록 순서의 개별 사슴 선택 → 기존 이동 실행/도착 거래**로 바꾼다. 현재 허기와 무리 크기를 지역 부족 평가의 필수 조건으로 사용하지 않는다.
- 현재 계획 저장 구조는 Herd 중심이므로 최소 인원 가드 한 줄만 삭제하는 것으로 완료하지 않는다. 같은 Herd에서 일부만 출발하거나 서로 다른 목적지로 갈 때의 계획 충돌도 해결해야 한다.
- [11-09 무계획 진단](JWJ_HERD_MIGRATION_NO_PLAN_DIAGNOSIS_20261109.md)의 이번 Standalone 가뭄 적용은 성공했다. 동일 맵/seed의 이전 관측에서는 12마리 모두 singleton이었다. 최신 사용자 세션의 실제 Herd 구성까지 확정한 것은 아니다.

## 2. 판단 단위와 이번 범위

**지역 생태가 이주 필요성을 결정하고, 사슴별 순차 승인이 출발 인원을 제한한다.** Herd는 정체성·경보·이동 조율 정보이며 이주 허가의 필수 단위가 아니다. 첫 구현에서 등록 순서를 건너뛰어 무리 전체를 한꺼번에 승인하지 않는다. 공동 이동 최적화는 개별 승인과 목적지가 일치하는 경우에만 후속 확장한다.

이번 대상은 기존 통합 Native v3 사슴이다. 기존 1102 4지역/경로/자원 장부/Travel/Native context 인계를 재사용한다. V1·SpeciesAI·늑대에 자동 적용하지 않는다. SocialControl=0, 기존 단일 movement/metabolism writer, Client 표현 전용 계약을 보존한다. PPO 관측·가중치·Python을 변경하지 않으며 ON 세계 재학습/전체 궤적 파리티 완료를 주장하지 않는다.

## 3. 지역 등록 배열의 순서 계약

구현 첫 단계에서 실제 Native/Mass 등록·출생·도착·삭제 경로를 조사한다. **Mass chunk 순회 순서, TMap 순서, 매 프레임 정렬한 StableAgentId 순서를 지역 등록 순서라고 부르지 않는다.**

기존에 안정적인 지역 사슴 등록 배열이 있으면 재사용한다. 없다면 권위 측 지역별 `StableAgentId` 순서 목록과 단조 증가 등록 순번을 둔다. 아래 이름은 설계용이며 아직 존재하는 API가 아니다.

- 초기 등록: 해당 지역에 실제 등록되는 순서대로 뒤에 추가한다. 실행마다 초기 등록 순서가 달라지는 경우 먼저 원인을 기록하고 결정적인 초기 등록 절차를 정한다.
- 출생/외부에서 실제 도착: 그 지역 배열 끝에 추가한다. 목적지 예약만으로 등록하지 않는다.
- 사망/실제 지역 이탈: 제거하되 남은 개체의 상대 순서를 유지한다. swap-remove로 순서를 바꾸지 않는다.
- 같은 ID 중복 등록을 금지한다. 배열 index는 영속 ID가 아니다. 평가 snapshot에서 ID를 읽고 승인 직전에 생존/현재 지역/기존 계획을 다시 확인한다.
- 저장/복원: 등록 순서·지역별 다음 순번을 보존한다. 구버전 저장에는 원래 순서가 없으므로 한 번만 StableAgentId 순으로 초기화하는 명시적 이전 규칙과 진단을 둔다. 이를 원래 등록 순서 복원이라고 기록하지 않는다.
- 매 평가에서 앞에서부터 순차 검사한다. 이미 승인/이동 중이거나 cooldown 중인 개체는 이유를 남기고 건너뛴다. 이후 개체가 먼저 승인되면 앞선 개체의 건너뛴 이유가 관측 가능해야 한다.

고정 순서의 앞쪽 개체가 먼저 기회를 얻는 것은 이번 사용자 요청의 의도된 정책이다. 무작위 셔플이나 round-robin으로 조용히 변경하지 않는다.

## 4. 중단선: 생태 목표 + 부족 기간 누적 한도

한 번의 지속적 부족을 `ShortageEpisode`로 관리한다. 부족 진입, 회복, 출발 승인 시각은 기존 시뮬레이션 시간 기준을 사용한다. 아래 값은 **첫 검증용 제안값**이며 검증된 생태 균형 상수가 아니다. 설정화하고 실제 단위/로그로 조정한다.

| 항목 | 첫 검증용 제안 | 의미 |
|---|---|---|
| 부족 진입 | 지역 FoodFraction < 0.25가 8초 지속 | 기존 기준을 초기 출발점으로 사용 |
| 회복 종료 | FoodFraction >= 0.35 및 지속 가능 인원 조건이 15초 유지 | 잠깐 회복으로 출발 예산이 재충전되지 않게 함 |
| 평가 간격 | 3초 | 프레임마다 계획 생성 방지 |
| 승인 간격 | 지역당 최소 3초, 한 평가에서 최대 1마리 | 같은 지역의 일제 출발 방지 |
| 최소 잔류 비율 | episode 시작 생존 사슴의 25%, 올림 | 출발로 지역 전체가 비는 것을 제한 |
| 최소 잔류 절대 수 | 0 | 한 마리뿐인 지역도 이주 가능하게 함 |
| 단독 예외 | 시작 인원 1이면 잔류 하한 0, 승인 한도 1 | singleton을 다시 묶어 두지 않음 |
| 최대 누적 승인 | 시작 인원에서 잔류 하한을 뺀 수 | 부족이 지속되는 동안 매 평가마다 재설정하지 않음 |

`N0`는 episode 시작 시 현재 지역에 살아 있는 등록 사슴 수다. 다른 지역행 기존 활성 계획이 있으면 시작 예산에 이미 사용된 몫으로 포함한다. `N0>=2`이면 `KeepFloor=ceil(N0*0.25)`, `N0=1`이면 0이다. episode 중 출생/유입으로 N0나 승인 한도를 늘리지 않는다. 회복 종료 후 새로운 부족 episode에서만 새 기준을 잡는다.

**지역당 1마리 제한만으로는 충분하지 않다.** 매 3초마다 계속 한 마리씩 내보내면 결국 전부 떠난다. 누적 승인 한도와 잔류 하한을 반드시 함께 적용한다. 이 한도는 과도한 유출 방지 정책이며, 먹이 0인 지역의 잔류 개체 생존을 보장하지 않는다. 잔류 개체를 무적화하거나 먹이를 생성하지 않는다. 완전 고갈 시 전원 피난을 허용하는 별도 정책은 이번 범위에서 자동 추가하지 않는다.

### 4.1 생태 목표 인원

비율 상한에 도달하기 전이라도 남은 인원이 지역의 예상 공급으로 버틸 수 있으면 추가 이주를 중단한다. 계획용 추정은 다음과 같다.

```text
BudgetFood = max(0, 현재 이용 가능한 지역 먹이 + H 동안의 보수적 순공급 예상 - 안전 여유분)
SupportedDeer = floor(BudgetFood / (사슴 1마리의 초당 예상 먹이 수요 * H))
```

H는 첫 시험에서 60초를 후보로 사용하되 Native 먹이/대사 단위를 확인한 후 확정한다. 수요는 현재 실제 섭취량만 사용하면 굶주린 개체의 섭취 0을 수요 0으로 잘못 계산하므로, 기존 몸 상태·대사/섭식 계약에 맞춘 필요량 추정치를 사용한다. 영양/에너지와 Food 단위 변환을 명시하고 중복 계산하지 않는다. 예측에는 같은 먹이를 쓰는 다른 소비자의 수요·기존 공급/손실도 반영한다. 불확실한 성장량을 확정 먹이로 간주하지 않는다.

`SupportedDeer`는 아직 존재하는 완성 API가 아니다. 단위와 수요 추정을 검증하지 못하면 `EcologyEstimateUnavailable`로 기록하고 기능 완료를 선언하지 않는다. `FoodFraction`은 인원이 줄어도 즉시 증가하지 않으므로 그 비율 하나만 반복 검사하는 것을 중단선 구현으로 대체하지 않는다.

### 4.2 승인 직전 적용할 중단 조건

각 후보 승인 전 아래 조건을 다시 계산한다. 하나라도 해당하면 그 지역의 이번 추가 승인을 멈춘다.

1. 부족 상태가 해소됐거나 episode가 종료됐다.
2. 기존 출발 예약을 뺀 예상 잔류 인원이 `SupportedDeer` 이하이다.
3. 한 마리를 더 승인하면 `KeepFloor` 아래로 내려간다.
4. episode 누적 승인 한도에 도달했다.
5. 지역 승인 간격 또는 이번 평가의 1마리 제한에 도달했다.

출발 지역 예상 잔류 인원은 **현재 지역 생존 사슴 수 - 아직 지역을 떠나지 않은 유효 출발 예약**이다. 실제 떠난 개체는 현재 수에 이미 없으므로 다시 빼지 않는다. 미도착 유입은 출발 지역의 잔류 보장에 사용하지 않는다. 사망 때문에 하한 아래로 떨어질 수 있지만 그런 경우 신규 출발을 중단하며 인구를 인위적으로 보충하지 않는다.

## 5. 목적지와 전 지역 공통 예약

지역은 결정적인 RegionId 순서로 처리하고 각 지역 안에서는 등록 배열 순서를 사용한다. 후보는 기존 알려진 인접 지역/보고 신선도/유효 지면 경로를 통과한 목적지 중 유리한 곳을 선택한다. 동점 목적지는 RegionId로 결정한다. 서버의 최신 모든 정보를 개체가 아는 정보로 취급하지 않는다.

목적지는 **현재 실제 사슴 + 미도착 승인 사슴 + 이번 평가에서 먼저 승인된 사슴**의 수요를 감당할 수 있어야 한다. 다른 지역이 같은 목적지를 선택해도 예약은 즉시 공유한다. 아직 도착하지 않은 출발 예정 인구 감소를 근거로 목적지 자리를 과도하게 먼저 확보하지 않는다. 기존 Population이 전체 종인지 종별인지 확인하고 늑대 수를 사슴 먹이 수요에 그대로 더하지 않는다.

출발/도착 예상량 예약은 서버의 계획 장부다. 실제 Population이나 Food를 변경하지 않는다. 실제 지역 인계가 일어났을 때만 기존 Migration receipt를 한 번 기록한다. 목적지 불가이면 후보별 이유를 남기고 다음 후보를 검사하며, 예약 없는 가짜 계획을 만들지 않는다.

## 6. 계획 식별·취소·저장 계약

- 계획은 고유 PlanId로 식별하고 개체별 활성 PlanId를 연결한다. 현재 Herd 키의 단일 계획 구조를 감사해 같은 Herd 일부 출발/서로 다른 목적지/단독 및 Herd 미할당 개체도 충돌 없이 표현하도록 변경한다. PersistentHerdId는 삭제/강제 변경하지 않는다.
- 한 개체는 활성 이주 계획을 하나만 가진다. Native 이동 훅·Travel·디버그 선택·반환/실패 처리·저장 로더의 Herd 키 의존을 모두 확인한다.
- episode 누적 승인은 **서로 다른 승인 StableAgentId 수**로 센다. 실패/사망/취소로 이 숫자를 감소시키지 않아 반복 실패로 출발 예산을 재충전하지 않는다. 같은 개체 재시도는 cooldown 후 같은 슬롯을 재사용하며 중복 승인 수를 늘리지 않는다.
- 활성 출발/도착 예약은 실패·취소·사망·삭제 시 한 번 해제한다. episode 승인 이력과 활성 예약은 서로 다른 데이터다. 기존 승인 개체의 재시도도 현재 잔류 하한/목적지 여력/승인 간격을 다시 검사한다.
- 실제 도착은 예약→실제 인구로 전환하고 중복 산입하지 않는다. 부분 도착·복귀·도착 직후 사망·누락 Entity도 처리한다. 되돌아가는 개체도 실제 위치와 기존 receipt 계약으로 처리하며 순간이동하지 않는다.
- 저장 시 지역 등록 순서, episode N0/하한/승인 ID 집합/시간, 활성 PlanId 및 예약 관계를 보존한다. 복원 시 활성 계획을 기준으로 예약을 재구성·대조해 중복 계산을 막는다. snapshot schema/version 및 구버전 이전이 필요하다.

## 7. 예상 동작 예시

지역 A 등록 순서가 `[D1, D2, …, D12]`이고 기존 예약이 없다고 가정한다. N0=12, KeepFloor=3, 누적 승인 한도=9이다. 목적지 여력이 충분하고 모든 경로가 유효하다고 가정한다.

- 공급 추정상 8마리 유지 가능: D1부터 한 평가에 한 마리씩 D4까지 승인하고 예상 잔류가 8이 되면 중단한다. 네 마리가 아직 A에 있어도 예약을 반영하므로 D5를 추가 승인하지 않는다.
- 공급 0: 최대 D9까지 순차 승인 후 3마리 잔류 하한으로 중단한다. 다음 평가에서도 예산은 다시 생기지 않는다. 잔류 위험은 HUD에 표시한다.
- 목적지가 2마리만 추가 수용 가능: D1·D2 승인 후 목적지 한도로 멈추거나 다른 알려진 목적지를 검토한다.
- D1이 이동 중/경로 불가: 그 이유를 기록하고 D2부터 검토한다. 단독 지역의 D1은 목적지가 유효하면 혼자 출발할 수 있다.
- D1 승인 후 사망: 활성 예약은 해제하지만 episode 승인 사용량은 유지한다. 남은 생존 수로 잔류 하한을 다시 검사한다.

## 8. 구현 순서와 관측

1. **기준선/단위 감사**: [현재 Source](../../Source/AdaptiveEcosystem/Mass/EcoHerdMigration.cpp), [기존 계약](../조연우/HERD_MIGRATION_AND_SIGNAL_CONTRACT.md), Core/AI/Policy/Mass 계약, 실제 등록/삭제/저장/소비 단위를 확인한다. 1102의 지역별 등록 순서·사슴 수·singleton·현재 경로를 기록한다.
2. **등록 순서와 지역 상태**: 안정적 지역 배열, 부족 episode, 단위가 명확한 공급/수요 추정을 구현한다. 필요 데이터를 기존 서비스에 연결하고 별도 ecology writer를 만들지 않는다.
3. **순차 승인과 예약**: 등록 순서, 생태 목표, 누적 한도, 간격, 전 지역 공유 목적지 예약을 연결한다. Herd 키 의존을 PlanId 기반으로 정리하고 기존 Native 실행 경로로 소비한다.
4. **생명주기/저장/디버그**: 취소·사망·도착·복귀·로드의 예약 보존을 검증한다. 기존 HUD에 지역 등록 인원/예상 잔류/지원 가능 인원/하한/누적 승인/다음 평가 시각/마지막 중단 이유를 표시한다.
5. **회귀와 실행**: 아래 검증을 통과한 범위만 완료로 기록하고 quick-test 문서의 명령·관찰값을 갱신한다. 기존 맵 기본값을 무조건 ON으로 바꾸지 않는다.

진단은 `RegionId, EpisodeId, StableAgentId, RegistrationOrder, PlanId, SourceLive, OutgoingReserved, SupportedDeer, KeepFloor, ApprovedCount, DestinationIncoming, Reason`을 포함한다. `RegionSustainable`, `RetentionFloor`, `EpisodeBudgetReached`, `DepartureInterval`, `NoKnownDestination`, `NoValidRoute`, `DestinationCapacity`, `AlreadyTraveling`, `Cooldown`, `EcologyEstimateUnavailable` 등을 구분한다. 변화/평가 요약 중심으로 기록해 프레임별 로그 폭증을 피한다. **계획이 0인 이유도 반드시 보인다.**

## 9. 필수 검증과 완료 기준

| 시험 | 통과 기준 |
|---|---|
| 지역 등록 순서 | 출생·삭제·도착·저장 복원 후에도 상대 순서 보존, 앞선 후보 제외 이유 추적 가능 |
| 단독/동일 Herd 일부 출발 | 1마리도 계획 생성 가능, 여러 승인 개체가 같은 Herd여도 PlanId 충돌 없음 |
| 12→8 목표 | D1~D4만 승인, 아직 실제 도착 전에도 D5는 중단 |
| 완전 고갈 장기 유지 | 최소 여러 평가/실제 도착을 거쳐도 episode 9명 상한 유지, 시간 경과만으로 전원 유출하지 않음 |
| 일시 부족/회복 진동 | 8초 미만 부족에 출발 없음, 회복 유지 전 예산 재충전 없음 |
| 다지역 경쟁 | A/B가 같은 목적지를 선택해도 공유 예약 반영, 목적지 허용 수요 초과 승인 없음 |
| 실패·사망·복귀 | 활성 예약 해제 정확히 한 번, 누적 승인 상한 우회 없음, 중복 ID/receipt 없음 |
| 실제 이동 | 동일 StableAgentId가 Native 단일 writer로 이동·RegionId 변경·MigrationIn/Out·종별 Population 일치 |
| 저장/복원 | 평가 중/예약 중/부분 도착 상태 복원 후 등록 순서·예산·예약·인구 일치 |
| Client/기존 OFF | Client에 이주 판단/장부 writer 없음, 기존 비활성 경로·정책 golden 회귀 보존 |

순서/예산/예약에 대한 결정적 자동화와 실제 1102 Standalone 테스트를 모두 수행한다. 자연 소비에 의한 부족과 개발 Drought fixture를 별도 기록한다. C++ 변경 후 Root AGENTS 규칙에 따라 실행 중 Editor/UBT/dotnet/Live Coding 등의 존재를 먼저 확인하고, 경쟁 실행 없이 직접 UBT Editor 빌드를 완료한다. 관련 이주/생명주기/저장 테스트와 Dedicated+Client 검증을 수행한다. 실제 완료 전 성공 수치나 생태 균형 달성을 기록하지 않는다.

## 10. 이번 문서 작업의 결과

새 소스·에셋·설정 변경 없이 구현 방향과 초기 제안 수치, 실패 관측, 다음 검증을 정했다. 새 UBT/PIE/Standalone 실행은 수행하지 않았다. [기존 1102 계획 D](JWJ_1102_FOOD_MIGRATION_SATIETY_PLAN_20261108.md)의 사슴 이주 상세는 이 문서로 보완하며, 다른 풀/포만/늑대 단계는 기존 범위를 유지한다.
