## 1. 이번 요청과 진행 방식

우리가 기획한 MMORPG용 동적 생태계를 실제로 구현해줘. 조연우가 학습 이외의 시스템과 통합을 최대한 직접 만드는 작업이다. 남은 개발 기간은 약 **6주**다. 이번에는 기획을 다시 정리하는 데서 끝내지 말고, 이미 있는 구조를 조사한 뒤 필요한 아키텍처·연결부·기능·표현·검증까지 진행해줘.

간단한 시연용 점수 변화, 빈 함수, 사용되지 않는 인터페이스만 만들어서 완료로 처리하지 마. 환경이 바뀌면 자원과 행동이 달라지고, 실제 이동·섭식·포식·출생 결과가 다시 생태계에 반영되어야 해. 각 단계를 실행 가능한 상태로 완성하면서 다음 단계로 이어가줘. 범위가 크다는 이유로 임의로 핵심 기능을 빼거나 계획만 제시하고 멈추지 말고, 남은 항목과 실제 한계를 기록해 이어갈 수 있게 해줘.

다른 팀원이 작성한 구조도 개선해도 된다. 담당자별 폴더를 수정 금지 구역으로 취급하지 말고 중복·잘못된 소유권·미연결·불필요한 결합을 해결해줘. 다만 현재 구현을 확인하지 않은 전면 교체, 기존 작업 삭제, 계약의 조용한 변경으로 해결하지 마. 이유와 영향, 호환 경로와 검증을 남겨 팀원이 자기 작업을 이어갈 수 있게 해줘. 일상적인 리팩터링마다 허락을 다시 묻지는 않아도 돼.

필요하면 MCP 연동을 활성화하거나 컴퓨터 사용 플러그인으로 Unreal Editor를 확인·조작해도 된다. 이미 이용 가능한 API·CLI·전용 도구를 먼저 확인하고 목적에 맞는 수단을 사용해줘. 사용할 수 없는 도구를 사용했다고 기록하지 마. 유료 구매·계정 비밀정보·외부 배포·다른 사람에게 메시지 보내기까지 허용한다는 뜻은 아니다. 플러그인 설치나 기능 선택은 로컬 UE 5.8 지원 여부와 실제 필요를 확인해 결정해줘.

## 3. 만들려는 전체 흐름

플레이어가 없어도 몬스터들이 먹고, 쉬고, 사냥하고, 경쟁하고, 무리로 이동하며 생태계가 변해야 한다. 플레이어는 방문·소음·사냥으로 그 안에 영향을 주는 존재다. 관찰 전용이나 플레이어 압력만의 시스템으로 축소하지 마.

```text
권위 날씨·낮밤·지형·수원
 → 토양 수분·식생·먹이량·차폐·서식 적합성
 → 실제 감각·욕구·경험·지역/무리 기억
 → 개인 선택 + 공동 계획 + 정책의 유효한 제안
 → 개체별 단일 실행 경로
 → 실제 이동·섭식·공격·사망·이주·조건부 출생
 → 자원/개체군 장부·경험·후손 분포 갱신
 → 다음 판단과 클라이언트 표현
```

사슴·늑대는 현재 검증 예시다. 식성·적대 관계·사회성·감각·이동·전투·생활 리듬·체형/리그·실행 backend를 분리해서 다른 몬스터를 추가할 수 있게 해줘. 모든 육식종이 항상 적대하거나 무리 사냥하는 것은 아니고, 초식/비섭식 몬스터도 영역 방어를 할 수 있다. 지원하지 않는 수영·비행·원거리 공격이 설정만으로 작동하는 척하지 마.

## 5. 먼저 마련할 공통 기반과 팀 작업 안내

전체 설계만 길게 쓰지 말고 실제 첫 기능에 필요한 범위부터 구현해줘. 각 항목을 사용하는 producer와 consumer를 함께 연결한다.

- 불변 DA/Curve/설정과 개체·지역·무리의 변경 가능한 상태를 분리한다. 유전·기억·정책 출력은 개체별이다.
- Snapshot → Request/Intent → 실제 Outcome → 권위 Receipt의 소유자·단위·시간/epoch·ID/sequence·TTL·취소/실패·재시도·중복 방지 계약을 적는다. 모든 작은 값에 과한 추상화 계층을 만들 필요는 없다.
- 종/능력/서식 프로필은 기존 SpeciesAI와 Native 설정을 조사한 뒤 통합 또는 adapter로 확장한다. 미지원 조합은 authoring 검증에서 이유와 함께 거절한다.
- 긴급 위협/안전 제약, 이주/무리 의도, 개인 욕구, 정책 제안이 충돌할 때 최종 결정 지점을 둔다. Raw Request·보정 의도·실제 행동과 거절 이유를 구분한다.
- 서버 시뮬레이션 시간·실제 플레이 시간·출생/세대 시간을 구분한다. 일시정지·시간 배속·긴 프레임·로드 이후 복구가 자원과 기억을 폭증시키지 않게 한다.
- 영속 ID와 런타임 handle/instance index를 분리하고 삭제·재사용·streaming·이주·서버 재시작 때 정리/재연결한다.
- feature flag와 설정 검증, 읽기 전용 진단, 제한된 원인 이력, 실제 단계별 성능 계측을 연결한다.

다른 팀원용 문서에는 기능별 담당 계층, 입력 제공 방법, 소비 시점, 결과 회수 방법, 수정할 파일/피할 중복, 간단한 호출 예, 에셋 설정, 실행 절차, 실패 확인법, 테스트·미완료 목록을 담아줘. 기존 담당 문서를 갱신하고 새 중앙 문서에서는 링크로 안내해줘. 사람별 이름만 적은 역할표로 끝내지 마. 팀의 실제 분담은 기존 문서를 확인하고 변경된 작업 범위를 구분해줘.

## 6. 구현할 기능과 실제 완료 조건

### A. 날씨·수분·땅에서 자라는 식생과 먹이

권위 강수·기온/낮밤·지형/수원 입력 → 제한된 토양 수분 모델 → 식물별 성장/쇠퇴 → 실제 남은 먹이 → 섭식 → 재성장으로 연결해줘. 물가 거리만으로 성장 배수를 주지 말고 도달 가능성·높이·배수·침수·식물별 최적 구간을 고려해줘. 초기에는 단순하고 조절 가능한 모델로 충분하다.

개별 풀마다 Tick BP를 만들기보다 논리 patch/cell과 ISM/HISM 등 지면 표현을 검토해줘. PCG는 배치 수단이며 자원 권위가 아니다. 지면 높이·경사·수면·streaming·늦은 등록/제거를 처리하고 먹으면 해당 장소의 양/외형이 실제로 줄어야 한다.

기존 FoodGrid와 M4의 관계를 먼저 정해줘. patch를 추가하면서 같은 먹이를 두 번 보유하지 말고 기존 공간 식량의 분할 또는 명시적인 교환으로 구현해줘. 기존 `RegisterSpatialFood`/`CommitSpatialFood`/`AdjustSpatialFoodHabitat` 계약을 대조하고 단위/순서를 유지해줘. 동시 섭식의 부분 지급·잔고 0·재시도에서 자원을 복제하지 마. 차폐를 식생에 연결하면 감각·은신처 공급자와 별도로 확인해줘.

완료 장면: 같은 땅에서 강수/건조에 따라 식생과 먹이가 달라지고, 여러 개체가 먹은 양이 정확히 차감되며, 이후 회복 차이가 행동/분포에 영향을 준다. 개발 fixture와 자연 회복 결과를 구분한다.

### B. 장소 선호·활동 시간·무리 이주

먹이량뿐 아니라 회복 전망·수분 접근·위험·은신/휴식·밀도·이동 비용·종 능력을 장소 평가에 반영해줘. 밤 활동형과 낮 활동형은 환경 시계의 같은 입력을 다르게 소비하도록 해줘. 무리가 항상 동시에 같은 행동을 하게 만들지는 마.

이미 구현된 Persistent Herd 공동 이주와 Travel/Native context 인계·M4 receipt를 확장해줘. 출발 임계값·지속시간·도착지 예상 혼잡·계획 유효기간·예약/재평가·왕복 방지·개인 휴식/위협 회피·뒤처짐·사망·복귀·실패 정리가 필요하다. 도착지의 현재 정답 정보를 모든 개체가 전지적으로 알지 않도록 authoring 지식/관측/공유 정보 범위를 정해줘.

완료 장면: 실제 부족/악화로 공동 계획이 생기고, 몸이 경로를 따라 이동해 실제 지역/인구가 이전된다. 지역 진입과 경로 끝 정착을 구분한다. 막힘·목적지 악화·일부 구성원 손실에도 계획이 정리/변경되고 무한 재시도하지 않는다.

### C. 경험·플레이어 관계·호기심과 회피

무해 방문/근접·소음·공격/피해·죽음 목격·포식·급습/추격을 관측 가능한 사건으로 분리해줘. 친숙함·호기심·공포·적대성을 한 수치의 양끝으로 처리하지 마. 무해 접촉은 조건부 호기심/접근, 반복 사냥은 해당 지역/무리의 사람 일반에 대한 경계/회피로 이어지게 해줘.

공격자나 공격 방식을 개체가 모르면 Unknown을 유지해줘. 급습·추격 분류는 실제 감지/피해 전후 맥락으로 판단하고 검증 정답을 AI 입력에 넣지 마. 급습 경험은 가림 지형 접근/경계, 추격 경험은 거리·탈출 선택 등 다른 반응으로 연결하되 원인을 확정한 것처럼 과장하지 마.

개인 기억·Herd 공유·지역 집계의 전파 속도/범위·증거 시각/수신 시각·TTL·회복·표본/노출량·중복 방지·상한을 둬. 한 유저가 신호를 반복해 영구 공포를 만들거나 몬스터를 무한 추격시키는 악용도 확인해줘. 가까워지는 행동은 안전 거리와 도달 가능성을 지켜줘.

완료 장면: 같은 초기 조건에서 무해 방문, 급습, 추격의 반복 후 선택과 원인 기록이 다르고, 시간이 지나면 기억이 약해진다. 감지 안 된 사실과 먼 지역의 사실은 즉시 공유되지 않는다.

### D. 흔적 조사·탐색·공동 사냥과 몬스터 간 상호작용

실제 사건에서 생성한 시간 제한 흔적을 공간 인덱스로 조회하고, 마지막 확인 위치 → 조사 → 재확인 → 접근/추격 → 실제 공격 또는 포기로 연결해줘. 현재 플레이어가 명시적으로 제외했던 후각을 기본 도입하지 말고 시야·소리·목격/이동 흔적부터 사용해줘. 전지적 대상 현재 위치 추적은 금지한다.

공동 사냥은 필요한 종/무리만 사용하고, 표적 근거·역할/lease·접근 위치·개인 능력·중단/포기·표적 소실·지원 불가를 처리해줘. 모든 육식 개체가 상시 사냥하지 않도록 에너지·포만·휴식·동시 참여·성공 비용과 cooldown을 둬. 과도한 상호 사냥으로 단시간 멸종하지 않는 제한을 명시해줘.

실제 공격은 선택 backend의 단일 검증 경로에서 생존·거리/LOS·cooldown·권위 결과를 확인해줘. 포식과 일반 전투·영역 방어를 분리하고 기존 instant reward를 사체 자원으로 전환한다면 둘을 중복 지급하지 마. 역할/먹이 자리 예약은 사망·실패·취소 때 반환해줘.

완료 장면: 숨은 표적을 즉시 따라가지 않고 유효 흔적을 조사하며, 두 개체 이상의 협동과 역할 변경이 실제 실행된다. 근거 만료/접근 불가 시 포기하고 사망/영양/인구 결과는 한 번만 반영된다.

### E. 개체 다양성·조건부 출생·세대 변화

개체 생성 시 재현 가능한 변이, 성장/영양 상태, 경험을 분리해줘. 복잡한 교미/출산 연출 없이 **조건을 만족한 출생 스폰**으로 구현해줘. 초기 배치·자연 출생·복구 공급·테스트 스폰·Actor 표현 재생성을 구분하고 인구/원인 장부에 남겨줘.

개체 사망이나 respawn마다 세대를 증가시키지 마. 성숙·부모/부모 집단 기여·번식 비용/기간·먹이와 공간·최소 표본/출생 집단·시뮬레이션 시간 조건을 사용해 세대 교체가 너무 빠르지 않게 해줘. 태어날 자리와 인구/자원 예약은 스폰 실패 때 정리하고 request를 반복해도 자식이 중복 생성되지 않게 해줘. 이주 유입을 현지 출생으로 세지 마.

선택 압력은 생존과 실제 후손 기여를 통해 다음 출생 집단의 분포에 반영해줘. 피해 한 번에 기존 개체 유전자가 바뀌거나 모든 후손 속도를 일괄 가산하는 구현은 피해야 해. 속도·체형·유지 비용·성장 등 제한된 trade-off와 범위를 두고, 작은 표본과 우연·이주 효과를 구분해줘. 실험용 세대 가속은 명시적 옵션으로만 제공해줘.

완료 장면: 개체별 차이를 안정 ID로 확인할 수 있고 조건부 출생이 인구 장부에 반영된다. 저장/로드 후 특성이 유지되며 반복된 선택 압력 아래 여러 출생 집단의 변화와 비용을 비교할 수 있다. 관찰 시간이 부족하면 장기 변화 검증 대기로 정확히 적는다.

### F. 체형·애니메이션·보이는 변화

유전/성장 → 계산된 신체 특성 → 실제 능력·충돌/접근 가능성 → Mesh/ABP 표현을 하나의 의미로 연결해줘. 단순 전체 Scale뿐 아니라 리그가 지원하는 제한된 Morph/Bone 비율을 검토하고 땅 접촉·발 미끄러짐·stride/turn·IK·시각 LOD를 맞춰줘.

Virtual Bone은 보조 기준이지 그것만으로 체형을 바꾸는 수단은 아니다. Control Rig·Warping·Mutable 같은 선택지는 현재 리그/플러그인 상태·배포·비용을 검증한 뒤 필요한 것만 사용해줘. 먼저 기존 에셋에서 실제 작동하는 안전 범위를 완성해줘. 구현 안 된 리그/능력을 데이터로 지원한다고 표시하지 마.

행동 Activity, 먹이 감소/건조, 경계/호기심, 흔적 조사, 무리 목적지/역할, 다른 체형이 화면에서 구분되어야 한다. Client와 late join에서도 같은 결과가 보이고 AnimNotify나 표현용 Actor가 논리 섭식/공격을 다시 실행하지 않아야 한다.

### G. 규모·저장·멀티·지속 가능한 게임 규칙

환경/식생·감각·판단·흔적·무리 계획·애니메이션에 맞는 서로 다른 주기와 공간 질의/후보 상한을 둬. 모든 개체가 모든 대상을 매 Tick 전수 조사하지 않게 해줘. 제한된 기억·혈통·흔적·원인 이력과 큐 상한/과부하 정책을 두고, 거래 자체를 누락시키는 방식으로 최적화하지 마.

관심 영역/표현 LOD와 논리 생태계를 구분해줘. 보이지 않는 지역이 항상 정지하거나 플레이어 접속 수만큼 논리 계산이 중복되지 않아야 한다. 원격 집계 시뮬레이션은 필요하면 별도 호환 계약으로 도입하고 기존 장부와 맞춰줘.

저장할 항목·버전·복구 순서·ID 재결합·중단된 의도/예약 처리·재시작 후 중복 receipt를 정의하고 실제 저장 복원 경로에 연결해줘. 미지원 저장 버전은 조용히 자원/개체를 새로 만들어 해결하지 마.

지역 위험 상한·과밀·멸종/복구·빈 사냥터·퀘스트 개체·loot 악용을 고려해줘. 운영 보충은 자연 회복과 분리해서 출처를 기록해줘. 이번 범위는 MMO에 맞는 생태계이지 완전한 MMO 서비스나 분산 서버 전체 구현은 아니다.

## 7. 학습 담당과의 경계 — 연결부만으로도 실행 가능하게

PPO 재학습·보상 튜닝·새 가중치 생산을 임의로 수행하지 말고 RL 담당 연결 작업으로 남겨줘. 다만 학습이 없다는 이유로 환경·행동·결과 구현까지 멈추지는 마.

1. 기존 V1 7관측/4출력과 v3 18관측/5행동·mask2, Raw Action/Request, 현재 가중치와 Golden 기준은 보존한다.
2. 새 환경/경험/신체/행동이 기존 정책 의미를 바꾸는 지점을 목록화한다. 기존 관측 슬롯에 다른 의미를 몰래 채워 넣거나 차원을 임의로 늘리지 않는다.
3. 학습 교체 지점은 실제 producer → 입력 계약 → 결정 adapter → 소비자 → Outcome 경로에 연결한다. 유효한 모델이 없을 때는 명시적인 규칙/Utility 기준 동작으로 실제 기능을 실행한다. 현재 정책과 같은 개체에서 동시에 최종 결정을 덮어쓰지 않게 한다.
4. 규칙 결과를 PPO가 학습한 결과로 설명하지 않는다. 모델 버전·활성 backend·fallback 이유를 진단에 표시하고 잘못된 모델/schema는 거절한다.
5. RL 전달에는 입력 순서·단위·정규화·결측/Unknown·action/mask 의미·물리 시간·설정/seed·학습 환경에서 바뀌어야 할 세계 규칙·예제 snapshot/기대 결과·평가 재현법을 남긴다.
6. C++ 계약/adapter 검증과 engine-free 평가 연결을 준비하되, Python mirror와 재학습·Golden parity가 안 된 세계는 명확히 구분한다. 새 세계에서 기존 가중치가 적합하다고 가정하지 않는다.

학습 외 연동·개체/자원 실행·저장·표현은 가능한 한 완성해줘. 외부 가중치를 나중에 제공해도 설정/검증된 adapter를 통해 교체할 수 있어야 한다. 빈 `TODO` 함수나 성공만 반환하는 mock을 production 경로에 두지 마.

## 8. 권장 순서와 6주 계획

6주를 기다리며 작업하라는 뜻은 아니다. 의존성과 팀 분담을 정하는 일정이며, 현재 채팅에서는 가능한 작업을 계속 진행해줘. 규모에 따라 세부 순서는 바꿔도 되지만 핵심 범위를 조용히 삭제하지 말고 이유와 남은 작업을 남겨줘.

| 순서/참고 주차 | 실행 가능한 결과 | 다음 단계에 넘길 것 |
|---|---|---|
| 1 / 1주 | 현재 구조 감사·중복 개선·첫 환경→자원→섭식 흐름 | source 근거, 소유권/순서/단위, 팀별 연결 표 |
| 2 / 2주 | 수분/식생·지면 표현·자원 경합·장소 평가 | 환경/자원 snapshot과 backend 소비 경로 |
| 3 / 3주 | 경험/사람 일반 반응·생활 리듬·원인 표시 | 관측 증거·공유/TTL·기준 행동·RL 전달 |
| 4 / 4주 | 흔적 조사·협동 사냥·이주 확장·실패 정리 | 실제 결과/거래·역할/예약·취소 계약 |
| 5 / 5주 | 다양성·조건부 출생·제한된 체형·저장 복원 | 부모/집단/세대·신체/리그/복제 계약 |
| 6 / 6주 | 전체 연결·장기/멀티/성능·팀 인계·실제 장면 | 재현 가능한 통합 증거와 남은 학습/에셋 작업 |

팀이 동시에 작업할 수 있게 계약을 먼저 작게 닫고, producer가 없는 값은 실제 환경 입력 또는 명시적 개발 fixture로 연결해줘. fixture를 실제 기능/자연 생태계로 포장하지 마. 독립 작업 경계와 공통 파일 충돌 지점을 문서화하고 다른 작업자의 미커밋 변경을 보존해줘. 이 문서는 다른 채팅에 자동 메시지를 보내거나 새 채팅을 만들라는 요청은 아니다.

## 9. 검증과 완료 판정

테스트 레벨은 기존 레벨 또는 팀원이 만든 대형 레벨을 먼저 조사해 사용해줘. 현재 시작점은 `/Game/JYU/Maps/LV_JYU_HerdMigration`이다. 원본 팀 레벨은 보존하고 필요하면 owned 복사에서 통합해줘. 맵 재생성 스크립트로 수동 작업을 확인 없이 덮어쓰지 마.

현재 기본 `SocialControl=0`, 기존 맵 이주 OFF·owned 이주 맵 ON을 보존해줘. 새 기능은 설정 검증과 opt-in 통합으로 시작한다. 기본값 변경이 필요하면 영향·회귀·새 기준을 명시해서 바꾸고, 조용히 전체 맵에 켜지 마. ShelterSafe와 ProtectedRefuges는 안전 규칙을 중첩하지 않는다.

최소한 다음을 실제 검증 범위와 연결해줘.

- 단위/계약: 자원 보존과 부분 섭식, 중복 거래/출생/피해, 오래된 요청·ID 재사용·TTL, 역할/자리 lease와 죽음/취소, feature OFF 회귀, 지원하지 않는 능력 거절.
- 무인 세계와 무해 방문/반복 사냥을 분리한 대조군, 비/건조/침수·밤낮, 먹이 고갈→이주→정착/실패, 표적 소실/흔적 만료, 출생 제한·저장/재시작.
- 실제 Editor PIE에서 논리 값과 몸/식생/애니메이션이 일치하는 장면. 콘솔 로그만으로 시각 검증 완료라 하지 않는다.
- Dedicated + 복수 Client/late join/재접속에서 Client 논리 writer가 없고 같은 지역·활동·자원 표현·체형을 받는지 확인.
- 현재 허용 개체 상한과 실제 서버/클라이언트 예산을 먼저 확인하고 점진적으로 성능 측정. 기존 제한을 무작정 늘리거나 500/1000마리 지원을 측정 없이 주장하지 않는다.
- 여러 seed/시간대에서 생존·먹이 수지·이주 성공/복귀/실패·사냥 비용·출생/사망·세대 분포, p95 CPU/메모리/대역폭을 기록. 짧은 성공 장면과 장기 안정/패키징 검증을 구분한다.

C++/빌드 입력 변경 후 엔진의 **직접 `UnrealBuildTool.exe`**로 `AdaptiveEcosystemEditor Win64 Development`를 빌드하고 끝까지 기다린다. UBT·dotnet·Unreal Editor·Live Coding·MSBuild·ShaderCompileWorker가 실행 중이면 빌드를 겹쳐 시작하거나 중단하지 마. 예외 창이 뜨면 첫 UBT/compiler 오류와 Windows Application Event Log부터 확인한다. 빌드가 길다는 이유로 강제 종료하지 마.

Server/Standalone만 논리 권위를 갖고 Subsystem을 복제 transport로 사용하지 마. worker 처리 중 UObject/Actor/World 질의나 Mass 구조 변경을 무단 추가하지 말고 기존 실행 단계·GT gather·buffer/commit 경계를 확인해줘. 런타임 Python 추론이나 LLM 의존은 추가하지 마.

검증할 수 없는 도구/환경 문제는 정확히 보고하고 나머지는 진행해줘. 실행하지 않은 PIE·네트워크·학습·패키징을 완료라고 적지 말고, 막힌 조건과 재현 명령/절차를 남겨줘. 문서만 변경한 턴에는 UBT를 실행했다고 기록하지 않는다.

## 10. 작업하면서 남길 산출물

문서 이름은 기존 구조와 겹치지 않게 조정해도 된다. 문서를 쓰는 것 자체가 기능 완료 기준은 아니다.

1. **구현 상태표**: 전체 기획 항목, 현재 Source, 활성 맵/backend/flag, 연결/미연결, 검증 범위, 남은 의존성.
2. **실행 아키텍처/계약**: producer → consumer → 단일 writer → receipt → 저장/복제/표현, 순서·시간·단위·실패 정리·변경 이유.
3. **팀 연결 안내**: 분야별 실제 수정/확장 지점, API/설정 예, 호환성, acceptance test, 다른 사람이 이어서 할 항목. 기존 문서와 공통 맥락/README에서 찾을 수 있게 링크.
4. **RL 인계 묶음**: 실제 연결된 입력/출력 adapter와 fallback, 계약/샘플·평가 절차·새 세계와 기존 parity 차이·학습 요청. 다른 담당자의 완료로 허위 표시하지 않는다.
5. **실제 동작과 증거**: Source/필요 에셋/owned 레벨, 자동화 결과, PIE/멀티·저장/성능 조건과 수치, 성공·실패 장면, 남은 제약.
6. **다음 채팅 인수인계**: 기준 commit/dirty 상태, 지금 되는 것, 실행 방법, 직전 실패와 다음 행동, 필요한 외부 입력. 작업이 길어져도 매번 처음부터 재설계하지 않게 갱신한다.

추가로 놓친 요소가 있으면 목적·비용·기존 연결·완료 장면을 함께 제안하고, 이번 핵심 흐름에 필요한 보완은 구현해줘. 질병·완전한 계절/재해·종분화·수중/비행·분산 서버 같은 큰 확장은 핵심 연결을 먼저 완성한 뒤 지원 범위를 따로 판단해줘.

개인 PPT·발표 캡처·계획서와 제작 산출물은 바탕화면의 외부 발표자료 폴더에 보관하고 Git에 넣지 마. 팀 공유 소스·계약·검증 근거는 저장소 규칙을 따라줘.

**시작은 현재 구조와 실제 연결 상태를 확인하는 것부터다. 짧게 조사 결과와 첫 구현 범위를 알린 뒤, 기반 정리와 첫 실제 동작 구현을 바로 진행해줘.**
