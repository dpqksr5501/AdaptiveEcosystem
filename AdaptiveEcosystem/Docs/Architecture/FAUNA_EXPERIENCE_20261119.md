# 다종 생태계의 경험 기반 추정

## 적용과 책임

`182a0503` 기준 최신 JYU 섬의 시작 설정은 일반 경험 `0`, 먹이 방문 `2`, 종간 행동 반영 `0`이다. 세 모드는 독립적이며, 일반 경험을 꺼도 먹이 방문 모드 2는 다음 먹이 후보 선택에 영향을 준다. 여우의 먹이·사냥·도주에는 기존 규칙 실행기를 사용한다. 이 문서는 게임 안에서 개체가 쌓은 증거를 기존 후보에 반영하는 규칙과 상태 저장을 다룬다. [섬 실행 기준](../Team/JYU_ISLAND_ECOSYSTEM_HANDOFF_20261105.md#2026-11-22-작업-브랜치-기준)

소유 복사 맵의 통합 코디네이터에서 **Creature → Fauna → Fauna Experience Mode**를 사용한다. `0`은 기본 동작, `1`은 경험 기록, `2`는 기록과 체형 표현 및 규칙 종의 후보 선택 반영이다. 개발 빌드에서는 `-EcoFaunaExperience=0|1|2`로 세션만 바꾼다. 기존 맵이나 팀 원본의 저장 에셋을 편집할 필요가 없다. [설정](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoCreatureIntegrationSpawner.h)

경험은 전용 서버 또는 Standalone의 개체 안정 ID에 속한다. 서버가 이미 확정한 결과와 기존 실행기의 실제 접근 실패를 사용한다. 맵 전체 재고, 다른 개체의 기억, 관찰하지 않은 공격자의 정체는 새 정책 입력으로 제공하지 않는다. 플레이어 위협과 우호의 계산·직접 반응은 담당 경로에서 처리한다. 규칙 종의 지상 이동에서 위험을 새로 감지하여 가까운 먹이 접근을 포기한 사례는 해당 자리의 경험으로만 반영한다.

## 기억과 선택

개체마다 최대 16개 장소·활동 항목을 보관한다. 낯선 후보의 보정은 1이다. **완료·경로 차단·시간 초과**는 반감기 120게임초의 접근 경험에 쓴다. 성공 1·실패 1의 초기 기준으로 희소한 표본을 완화하고, 시간 초과는 확인된 경로 차단의 절반만 반영한다. **감지된 위협 중단**은 반감기 45초, **자원 고갈이나 수위로 인한 이용 불가**는 반감기 30초의 별도 기억에 기록한다. 섭식 직후 위협을 만나면 성공과 위험을 같은 시점에 보관할 수 있다. 서로 다른 기억은 독립적으로 약해진다. 이는 게임용 튜닝이며 실제 종의 기억 시간을 추정한 값은 아니다. 접근 증거는 총량 16, 각 추정식 및 수륙 섭식의 합성 경험 보정은 0.75~1.25 한도로 둔다. 같은 항목·기억 종류의 2초 이내 반복 적립을 제한한다. 빈 슬롯이 없으면 항목이 가장 많은 활동에서 가장 오래 갱신하지 않은 기록을 교체한다. 피해를 받은 개체나 직접 위협을 감지한 개체가 선택해 근처까지 온 먹이만 일시적 위험으로 갱신한다.

## 장기 발달과 관계

서버가 이미 확정한 개체별 에너지를 10게임초마다 표본으로 삼아 최근 에너지 균형을 추정한다. 첫 관측은 시각만 등록하고, 이후 각 표본은 120게임초 반감기의 지수 가중 평균에 반영한다. 누락된 간격은 새 관측으로 채우지 않는다. 모드 2는 이 값으로 종의 기존 메시 로컬 X·Y 비율을 최대 ±12.5% 조절한다. 16종 모두 같은 경로를 사용한다. 성장률·유전자·충돌·타격·질량·대사와 서버 발소리에는 기존 값이 쓰인다. 초기 발달은 중립이고 시체는 마지막 체형을 유지하다 기존 시체 수명이 끝날 때 함께 정리된다. 자손은 새로운 장기 경험을 쌓으며 유전 절차는 기존 계약을 따른다.

| 장기 성향 | 관찰한 증거 | 실제 소비 |
| --- | --- | --- |
| 탐색 성향 | 통로·수변·횃대의 도착, 차단, 시간 초과. 위협과 일시적 이용 불가는 단기 장소 기억에 사용 | 규칙 종의 평상시 지상·수중 배회 범위 ±20%. 기존 지형·수심·도주·사냥 게이트 적용 |
| 사회적 접근 | 기존 무리 행동에서 가까이 있는 동종을 시야로 확인하고 같은 지면에 있는 안정 상태를 확인. 새끼의 영양 지급과 실제 출생도 기록 | 지원하는 규칙 종의 평상시 무리 간격과 끌림에서 최대 15% 보정 |
| 개체 친숙도 | 상대 StableAgentId마다 위와 같은 가까운 접촉·급이·공동 출생. 장소를 옮겨도 동일한 살아 있는 개체에 적용 | 기존 무리 이웃 평가와 규칙 종의 번식 후보 순서. 거리·시야·성별·혈연·먹이·산란장·둥지 자격은 기존 검사를 통과해야 함 |

탐색·접근 성향은 300게임초, 친숙도는 420게임초 반감기로 중립에 가까워진다. 한 개체의 관계는 최대 6개다. 평상시 접촉은 상대별 20초, 확정 급이·출생은 상대별 5초 간격으로 제한한다. 새로운 관계가 한도를 넘으면 마지막 관측이 가장 오래된 관계를 교체한다. 수치는 플레이 튜닝이다. 사용자 공격과 팀원의 위협·우호 판정은 장기 성향의 입력으로 직접 소비하지 않는다. ### 16종의 교류 선택과 응답

서버는 자원 처리 경계에서 같은 종·지역·이동 매질의 개체를 찾는다. 16종별로 최대 교류 거리, 다시 교류하기까지의 시간, 익숙한 상대를 선호하는 정도를 정한다. 지상은 층고, 수중은 실제 수심과 연결 경로, 비행은 같은 공중 상태와 3D 거리가 필요하다. 교전·도주·수변 전환·이동 중인 개체나 위협 신호를 쓰는 개체는 참여 자격에서 빠진다. 이 때문에 익숙한 개체가 벽 뒤에 있거나 분리된 수역에 있으면 그 개체를 선택할 수 없다. 지역 전체의 다른 위치를 알려주거나 따라가는 새 이동 경로는 만들지 않는다. [종별 프로필](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFaunaSocial.h) · [서버 교류 로직](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoCreatureSocialExperience.cpp) · [구피의 익숙한 무리 선택 실험](https://pubmed.ncbi.nlm.nih.gov/9710476/)

서버가 한 쌍을 고르고 다음 처리 경계에서도 조건이 맞으면 응답을 확정한다. 멀어지거나 자격을 잃으면 기억 적립 없이 제안을 폐기한다. 교류와 기존 양육·공동 출생 결과는 상대 ID의 친숙도와 사회적 접근 성향을 바꾼다. 이전 경험에 따라 다음 교류 상대와 참여 가능 시각이 달라지며, 사슴·늑대를 포함한 기존 번식 경로는 자격이 맞는 상대를 검사하는 순서에 이 기억을 사용한다. 기존 출생 예약·사망·먹이 장부와 정책 및 이동 경로를 사용한다. 모드 1은 가까이 지낸 결과만 기록한다. 현재 포맷 24는 마지막 교류 시각을 복원한다. 아직 응답하지 않은 제안과 일시 표시는 복원 시 초기화한다.

전용 서버는 기존 Mass Fast Array로 체형 1바이트와 교류 역할·방향을 담은 2바이트를 전달한다. 클라이언트는 상대 쪽으로 몸이 향하는 표현을 하고 움직이는 동안에는 이동 방향에 대한 추가 회전을 15도로 제한한다. 기존 위협 초점이 표시 우선권을 갖는다. 상대 ID, 관계 기록, 판단은 서버에 둔다. 게임 세션의 `EcoProtocol`은 3이며 서버와 클라이언트는 같은 빌드를 사용한다. ## 실행 비교

Editor에서 소유 섬 `/Game/JYU/Maps/LV_JYU_IslandEcosystemRefreshed`를 열고 `py Tools/Editor/audit_island_fauna_experience.py`를 실행한다. 고정 시드를 지정하고 각 프로세스의 `-EcoFaunaExperience=0|1|2`를 바꾼다. 모드 2의 저장 복원은 같은 고유 `-EcoExperienceSlot=<이름>`으로 `-EcoExperienceAudit=Save`와 새 프로세스의 `Load`를 비교한다. 보고서는 `Saved/FaunaExperienceAudit`에 기록하며 맵을 저장하지 않는다.

일반 시작 조건에서 모든 종을 포함하되 짧은 관찰에 자연적으로 일어나지 않은 포획·이주·부화는 해당 제어 장면에서 따로 검증한다. 행동 변경 여부는 각 시도에 실제 지급·도착·해제 기록을 함께 맞춰 판단한다. PPO 학습 파일과 가중치는 기존 계약을 사용한다. 향후 전 종의 행동 반영 범위를 늘릴 때는 각 실행기의 정책 및 입력 계약을 별도로 확인한다.

## 종간 사냥과 자원 경쟁

경험 모드 1은 서버에서 증거를 기록한다. 모드 2는 같은 증거로 기존 후보의 점수를 조정한다. 규칙 동물은 지상·수중·공중 사냥 대상과 이용 가능한 식생·먹이터·사체를 비교할 때 사용한다. Native 사슴은 방목 중 기존 식생 후보를, Native 늑대는 청소섭식 중 기존 사체 후보를 비교할 때 사용한다. 늑대의 포획 결과도 기록한다. Native 추격, PPO 요청·마스크·관측 스키마와 플레이어 위협·우호 계약은 기존 소유자가 결정한다.

- 사냥 기록은 사망 장부에 반영된 포획 또는 실제 공격·추격의 확인 가능한 실패에서 만든다. 후보 탐색에서 보이지 않았거나 개체가 사라진 경우는 실패로 집계하지 않는다.
- 자원 경쟁은 같은 셀·먹이터·사체에서 최근에 실제 소비한 다른 종을 감각 범위 안에서 확인한 경우 기록한다. 기존 잔량으로 충족하지 못한 수요 가운데 그 상대의 소비로 설명되는 부분만 낮은 수확의 증거로 사용한다. 사체 기록은 이후 같은 지역과 매질에서 같은 종류의 사체를 다른 종이 먹는 모습이 확인되면 재사용할 수 있다.
- 위험은 기존 감각이나 실제 공격에서 확인한 다른 종과의 조우로 기록한다. 방금 본 위험이 해소된 뒤 해당 위치에 증거를 남긴다. 그 위치에서 방해 없는 섭식이 반복되면 점수가 중립으로 회복된다.

## 먹이 방문과 재방문

`FaunaFoodVisitMode`는 기존 경험 모드와 독립적이다. 에디터 설정 또는 개발 실행의 `-EcoFaunaFoodVisits=0|1|2`를 쓴다. 0은 기본, 1은 기록, 2는 조건을 통과한 후보에 기록을 반영한다. 기존 섭식 코드가 실제로 처리한 요청량과 지급량을 사용한다. 같은 자원에서 2.5권위초 이내에 이어지는 시도는 한 방문의 표본으로 묶는다. 저장하는 기간은 첫 섭식 시도부터 마지막 섭식 시도까지다. 목적지로 이동하는 시간이나 방문 전에 감지한 실패는 기존 접근·위협 기록으로 남는다.

식생 셀, 지상·수중 패치, 사체가 같은 관측 구조를 쓴다. 패치의 여러 접근점이 같은 재고를 사용하면 같은 방문 기억을 공유한다. 사체는 한 방문 안에서는 개별 사체를 구분하며, 이후 비교에서는 같은 지역·매질·종류·장소의 소비를 기억한다. 낮과 밤의 방문량을 다르게 추정하고 최근 결과의 영향은 150권위초 반감기로 줄인다. 몇 번 못 먹었다는 이유로 후보를 제외하지 않는다. 반복해서 적게 먹은 방문은 이후 선택에서 경쟁력이 줄어들고, 가까운 대체 장소가 더 가치 있을 때 기존 이동기가 선택할 수 있다. 급한 허기에는 새 방문 보정을 건너뛴다.

풀의 재생, 사체 소실, 섭식 지급과 영양·체형·개체군 갱신은 기존 실행 경로에서 처리한다. 새 방문 모델의 직접 효과는 먹이 후보 비교다. Native 사슴은 방목의 식생 후보, 늑대는 청소섭식의 사체 후보에서 읽는다. 정책 관측·행동·가중치와 플레이어 위협·우호 기능은 기존 계약을 따른다. 현재 포맷 24는 완료된 방문 추정값을 복원한다. 저장 당시 진행 중이던 방문 표본은 세션에서만 유지되고, 새 실행의 확정된 다음 섭식부터 다시 묶는다. ## 종간 경보·방어·사체 이용

`LV_JYU_IslandEcosystemRefreshed`를 Play할 때 실행 인자 `-EcoFaunaInteractions=2`를 넣으면 반영한다. 코디네이터의 `FaunaInteractionMode`는 끔 0, 기록 1, 반영 2를 지원한다. 기존 섬의 기본 설정은 0이다. 경험과 먹이 방문 모드는 독립적으로 선택한다. 서버가 감지·행동·재고를 결정하며 클라이언트는 기존 개체 표현 패킷의 경보 표시를 받는다. 실제 경보음은 개체의 애니메이션 프로필에 음원이 등록되어 있을 때 기존 공간 음원 재생기로 재생한다. 잠깐의 경보는 저장하거나 접속 시 재생 목록으로 보내지 않는다.

- 포식자가 추격 중이고 목표가 그 포식자를 직접 감지하면 주변의 다른 종에게 경보나 움직임 단서가 생긴다. 지상·공중에서는 거리, 차폐, 시야를 사용한다. 수중에서는 연결된 수역 안에서 실제 도주 움직임을 볼 수 있어야 한다. 주변 개체가 반응만 보고 다시 경보를 발신하는 경로는 없다. 수신자가 포식자를 별도로 감지한 경우에만 경보 제공 종의 신뢰도를 높이고 시간이 지나면 중립으로 돌아간다.
- 경보만 들은 지상 개체는 잠깐 멈추고, 도주를 본 규칙 개체는 매체에 맞는 이동 경로를 사용한다. 기존 직접 위협, 발사된 공격, 이주와 상륙 검사를 적용한다. 실제 먹이 지급이 생겨야 식사 복귀가 기록된다. Native 사슴·늑대는 각각 기존 방목·사체 선택 안에서 후보 가치 보정을 읽는다. 정책 네트워크의 입력·출력 형식과 학습 경로를 공유하지 않는다.
- 체력과 스태미나가 남은 성체 방어자는 지역의 현재 공격에 한해 짧게 이동 목표를 받고, 공격선에 몸이 들어가야 포획을 막을 수 있다. 규칙 포식자의 실제 공격을 가로막으면 스태미나를 쓰고 회복 시간이 생긴다. Native 늑대는 기존 포획 후보 검사에서 막힌 공격선을 건너뛴다. 보호받은 규칙 개체는 평상시에 주변의 건강하고 보이는 보호종을 조금 더 선호할 수 있다. 이 효과는 기존 종별 사회 거리와 지상 이동 조건을 사용한다.
- 다른 종이 남긴 사체에서 실제로 섭취하면 생산종과 장소를 기록한다. 이후 같은 장소의 접근 가능한 사체가 소폭 유리하다. 같은 사체와 섭식 자리를 기존 장부에서 차감한다. 출처 기록은 포식자의 현재 위치를 알려주지 않는다.

포맷 24는 확인된 종간 경험과 사체 출처를 저장한다. 경보 재생, 임시 회피, 진행 중인 방어는 복원 후 새로 관측한다. 포식자 추격 거리, 엄폐·공격 가능 여부, 물·땅 경로 및 실제 재고가 각 행동의 전제다. 영구 공생 관계, 협동 사냥, 집단 몰아내기, 씨앗·분해물·영양염 순환은 각각의 공간·자원 계약을 연결해야 한다.

- UE 5.8 직접 Editor 빌드와 관련 NullRHI 자동화 83건을 통과했다. 말의 경보 중 식사 보류와 재개, 공격선 안과 밖의 물소, 방어 뒤 회복 시간과 이웃 선호, 시야를 돌려 도망치는 어류와 수중 장애물, 다른 종이 남긴 사체의 실제 섭취를 통제해서 확인했다. 경보 경험이 기존 먹이·위험 기억을 밀어내지 않는지도 검사했다. 기존 v3 GoldenParity·MaskNotNetInput·Contract를 포함한다. 빌드에서 기존 `StructUtils` 플러그인 사용 중단 예정 알림이 남아 있다. 원본은 `Saved/Automation/FaunaInteractionsRegression/index.json`과 `Saved/Logs/Build_FaunaInteractionsRegression.log`다.
- 소유 섬 시드 20000의 끔·반영 모드 모두 16종 120개체로 시작했다. 반영 모드의 130게임초에서 사슴 경보 4건이 있었고, 여우와 산토끼가 쥐의 도주를 관찰한 뒤 각각 위협을 확인했다. 여우의 실제 섭식 복귀가 한 건 관측됐다. 끔 모드에서는 새 사건이 없었다. 포맷 24를 별도 프로세스에서 복원하자 도주 기억 2건을 포함한 전체 종간 기억 171행이 모두 일치했다. 단일 시드의 관찰이며 생존율을 비교할 근거로 쓰지 않는다. 원본은 `Saved/FaunaExperienceAudit/IslandInteractionsV24_2_*.json`과 `Saved/FaunaExperienceAudit/IslandInteractionsOff_2_Observe.json`이다.
- 기본 전용 서버 관찰에서 쥐의 경보 발신, 산토끼의 청각 반응과 여우의 시각 반응을 확인했다. 두 클라이언트의 접속 중첩은 36.4초였고 권위 개체와 Native Step은 각각 0이다. 새 경보 플래그는 기본 관찰 동선에서 수신이 잡히지 않았다. 원본은 `Saved/FaunaInteractionsV24Net/Relevance.json`이다.
- 경보 관찰 실행에서는 추격 반경으로 관찰 카메라를 옮기고 서버 0.15초, 클라이언트 0.20초 주기로 경보 표시만 따로 읽었다. 두 클라이언트가 88.6초 동안 겹쳐 접속했다. 일반 접속과 늦은 접속에서 각각 경보 5건을 수신했고, 서버의 발신 또는 표시 기록과 각각 5건과 4건이 일치했다. 늦은 접속의 남은 1건에는 대조할 서버 표본이 없었다. 권위 개체와 Native Step은 두 클라이언트에서 각각 0이었으며 세 프로세스가 정상 종료했다. 음소거 상태에서 표시를 대조했다. 원본은 `Saved/FaunaInteractionsV24AlarmTicker/Relevance.json`과 각 프로세스 보고서다.
