# 공유 풀 패치와 실제 위치 섭식 개발 명세

작성: 2026-11-08. 상태: **단계별 구현 착수: S0 writer 조사/로컬 기준선, 기본OFF S1 공통 배치·권위 지면 첫 구현**. 실제 결과와 한계는 [S0/S1 기록](FOOD_PATCH_GRAZING_S0_S1_20261108.md)을 따른다. 패치별 먹이/예약/도착 소비와 S2~S6는 미완료다. 기존 코드 감사 기준은 `jwj-1024`, HEAD `395992ab`와 현재 미커밋 변경이다. 재개할 때 반드시 실제 diff와 대조한다.

이 문서는 [1102 후속 계획](JWJ_1102_FOOD_MIGRATION_SATIETY_PLAN_20261108.md)의 B-2 구현 계약이다. 이전의 ‘셀당 단일 군락으로 모으기’ 제안을 대체하여 **셀 안에 여러 고정 패치를 유지하는 방식**을 채택한다. 전체 진행과 기존 검증 증거는 [PROGRESS.md](../../../PROGRESS.md)에 기록한다.

## 1. 목표와 범위

사슴이 서버가 확정한 풀 패치까지 이동하고, 섭식 가능한 자세와 거리에 도착했을 때 그 패치의 먹이만 소비한다. 클라이언트는 같은 패치의 잔량을 표시한다. 예약은 접근 자리의 경합을 관리하며 먹이를 미리 차감하지 않는다.

- Smart Objects 플러그인·Subsystem·컴포넌트를 추가하지 않는다. 공간 검색, 슬롯 예약, 접근, 상호작용의 원리만 기존 구조에 적용한다.
- 기존 1102 레벨, Region, Spawner, Field/ISM, Native 이동·섭식, Inspector/환경 디버그, 체크포인트를 확장한다. 새 레벨·게임모드·플레이어·풀마다 Actor/Entity를 만들지 않는다.
- 서버 FoodGrid/M4 권위와 단일 Native 이동/자원 writer를 유지한다. 렌더러·클라이언트·예약 관리자는 먹이와 에너지를 직접 변경하지 않는다.
- 위치와 식용 잔량은 플레이어 위치/시야와 무관하다. 카메라는 렌더 상세도와 작업 우선순위에만 영향을 준다.
- 이번 명세는 위치 섭식과 비용 검증을 다룬다. 포만 행동, 사슴 부족 이주, 늑대 추적 이주의 전체 구현은 후속 계획 C~F에서 계속한다. 이번 목표/예약 상태가 그 행동을 방해하지 않는 연결 지점은 포함한다.

## 2. 현재 동작과 바꿀 동작

| 항목 | 현재 Source | 이번 구현 |
|---|---|---|
| 풀 배치 | `RefreshPlants`가 셀 seed로 같은 후보 XY/yaw를 반복 계산 | 초기화/배치 변경 시 공통 함수로 고정 후보를 생성하고 캐시 |
| 위치 | 셀 중심에서 X/Y 각각 ±0.42×셀 폭, 클라이언트 지면 trace | 같은 XY를 유지하고 서버가 패치 지면·유효성 확정 |
| 잔량 | 셀 하나의 잔량과 후보 개수 | 기존 셀 잔량의 공간적 배분을 패치별로 보관 |
| 소비 | C4에서 이동 후 body가 속한 셀의 수요 배분 | 도착 조건을 통과한 목표 PatchId의 수요만 배분 |
| 풀 감소 | 후보 개수 감소에 따라 끝 번호부터 제거 | 실제 소비된 패치의 양/외형 감소, 다른 패치 유지 |
| 목표/경합 | 패치 단위 목표·예약 없음 | 목표 유지, 제한된 근접 검색, 접근 자리 예약/해제 |

현재 근거리 후보 설정은 9개이며 상한은 25개다. 기본 4m 셀의 후보 XY 범위는 각 축 ±1.68m다. 현재 알고리즘은 균등 난수 분산이며 최소 간격을 보장하지 않는다. 첫 구현에서 분산 알고리즘 변경까지 섞지 않는다. 겹치는 무더기는 접근 슬롯 간 간섭 검사로 처리하고, 배치 개선이 필요하면 별도 LayoutVersion으로 시험한다.

## 3. 데이터 계약과 소유권

아래 이름은 구현할 개념명이다. 이미 존재하는 API나 실행 명령으로 오해하지 않는다.

| 데이터 | 소유/수명 | 계약 |
|---|---|---|
| LayoutDescriptor | 기존 지역 Native context → Field 읽기/복제 | RegionId, Seed, LayoutVersion, LayoutEpoch, 원점/변환, 셀 크기/격자, PatchCount, 설정 hash |
| PatchStatic | Native context의 연속 배열 | 지역 상대 좌표, 지면 normal/유효성, 지형 revision. 실제 UObject/FTransform은 패치마다 보관하지 않음 |
| PatchFood/Capacity | 기존 FoodGrid 내부 배분 배열 | double 등 기존 권위 정밀도 유지. 셀 총량과 함께 같은 거래에서 갱신 |
| AgentTarget | 기존 개체 runtime fragment/context | PatchId, SlotId, LeaseGeneration, 상태, 마지막 진행/검색 step. 임시 Native index를 영구 식별자로 사용하지 않음 |
| SlotLease | 서버의 활성 예약만 희소 보관 | 소유 개체 stable ID, 기한, 세대, 접근 위치. 비활성 패치마다 큰 예약 객체를 만들지 않음 |
| PatchVisual | 기존 Field FastArray 확장 | 정량화 잔량/용량, 배치/상태 revision, 권위 위치 보정·유효 마스크, NativeStep |
| LocalRenderCache | 기존 Field/ISM | PatchId→instance index 매핑과 로컬 표시 캐시. 렌더 index는 게임 ID가 아님 |

논리 PatchId는 `(RegionId, LayoutEpoch, CellId, CandidateIndex)`다. 배열 내부에서는 셀/후보 offset으로 압축 접근하되 외부 목표·복제·저장은 epoch를 검증한다. LayoutVersion은 생성 알고리즘 버전, Epoch는 해당 지역 배치의 수명이다. 엔진 버전/설정이 다른 경우 seed만으로 일치를 가정하지 않는다.

게임플레이 `PatchCount`와 거리별 렌더 개수는 분리한다. 카메라가 멀어져도 패치 수와 잔량은 바뀌지 않는다. 기존 CandidatesPerCell 설정은 명시적 이전 절차로 초기 PatchCount에 반영하고, 디테일 옵션 변경이 자동으로 장부를 재분배하지 않게 한다.

### 3.1 셀 장부와 패치 배분

패치 배분은 별도 생태 자원이 아니라 **기존 셀 먹이의 위치별 내역**이다. 외부 자원 집계는 계속 셀/지역 총량을 사용한다.

```text
Food[cell] = Σ PatchFood[cell, p]
Capacity[cell] = Σ PatchCapacity[cell, p]
0 ≤ PatchFood[p] ≤ PatchCapacity[p]
EndFood = StartFood + Growth + Supply - Intake - EnvironmentLoss - ExplicitRemoval
Σ Agent.LastIntake = Σ 실제 패치 소비 = 해당 거래의 FoodEaten 증가량
```

모든 합은 같은 권위 step/revision에서 비교한다. 수치 오차 허용치는 `max(1e-8, 1e-9 × max(1, 해당 셀 용량))`을 초기 기준으로 하며 기존 수치 형식/누적 규모에 맞춰 검토한다. 전송용 uint16 잔량을 역산해 권위 장부를 덮어쓰지 않는다.

FoodGrid 안의 한 갱신 경로가 패치와 셀 합을 함께 commit한다. Field는 결과를 받는다. 기존 코드가 셀 Food를 직접 쓴 뒤 다음 tick에서 패치에 추측 반영하는 방식은 금지한다. 먼저 모든 Food/Cap 쓰기 경로를 조사하여 아래 거래에 대응시켜야 한다.

| 거래 | 처리 규칙 |
|---|---|
| 초기화/이전 셀 전용 저장 불러오기 | 설정된 고정 capacity 가중치로 나누고 마지막 유효 offset에 반올림 차이를 보정. 같은 입력은 같은 배분 |
| 섭식 | 도착·예약 검증에 성공한 목표 패치에서만 소비. 다른 패치에서 부족분을 보충하지 않음 |
| 자연 재생/공급 | 기존 모델이 산출한 셀 증가량만 빈 용량 비례로 배분. 패치 수만큼 재생을 중복 실행하지 않음 |
| 가뭄/환경 감소 | 기존 셀 손실량을 패치 현재 잔량 비례로 분배. 섭식 감소와 원인을 별도 기록 |
| 용량/서식지 변경 | 새 capacity 배분을 계산하고 초과 먹이는 기존 손실/조정 영수증 경로로 명시 처리. 몰래 삭제/생성하지 않음 |
| 기후 디버그/수동 공급·고갈 | 기존 서버 명령과 거래 경로를 이용하고 영향 지역/원인/step를 기록 |
| 배치 epoch 변경 | 소비를 잠시 중단하고 예약 해제 → 같은 셀 총량을 보존해 새 배분 생성 → 한 revision으로 교체 |
| 저장/복원 | 배분 자체를 저장. 현재 셀 총량만으로 다시 균등 분배하면 먹힌 위치가 복구되므로 허용하지 않음 |

지면이 아직 확인되지 않았거나 일시적으로 언로드된 패치는 접근 불가로 표시하되 배분량을 보존한다. 지면 부재 자체를 먹이 손실로 간주하지 않는다. 모든 패치가 접근 불가면 섭취는 0이고 진단에 `GroundUnavailable`을 표시한다. 영구적으로 식생 불가인 지형은 기존 habitat/capacity 거래로 처리한다. 접근 가능한 먹이 합과 지역 총먹이는 별도 수치로 제공하여 후속 이주 판단이 ‘보유량은 있지만 접근 불가’ 상태를 구별하게 한다.

### 3.2 동시 소비

같은 step에 패치 p에 도착한 개체 i의 수요를 `Want[i]`라 하면 `D[p]=Σ Want[i]`, `Taken[p]=min(PatchFood[p],D[p])`, `Gain[i]=Want[i]×Taken[p]/D[p]`다. D=0이면 Gain=0이다. 기존 비례 분배와 에너지/비축 계산을 유지하되 집계 대상만 셀에서 패치로 바꾼다.

예약과 소비는 분리한다. 예약만으로 잔량을 줄이지 않으며 예약이 만료된 개체는 해당 step 수요에 들어갈 수 없다. 결정적 순서와 작은 반올림 차이 처리를 정의해 순회 순서에 따른 초과 소비를 막는다. 미도착이어도 기존 대사/피로/비축 소모는 계속한다.

## 4. 초기화와 실행 흐름

### 4.1 고정 위치 생성

1. 기존 spawner/context가 지역 설정과 배치 descriptor를 확정한다.
2. 공통 순수 함수가 셀/후보의 XY/yaw를 생성한다. 기존 CRC/hash/FRandomStream 호출 순서를 첫 LayoutVersion에서 보존하고 golden 좌표를 저장한다.
3. 기존 Field 지면 수집 경로를 확장하여 서버가 후보 지면/normal/경사·접근 유효성을 검사한다. UObject/World trace는 게임 스레드, Native에는 확정 snapshot만 전달한다.
4. 검증된 좌표를 지역 상대 좌표로 캐시한다. 셀 중심 높이를 모든 후보의 최종 높이로 복사하지 않는다.
5. 패치 배분을 초기화하고 렌더 descriptor와 위치 보정을 게시한다. 초기화 중인 패치를 목표로 선택하지 않는다.

지면 검사는 World 전체 예산을 공유해 프레임에 분산한다. 클라이언트마다 같은 trace를 무조건 반복하지 않는다. 서버가 확인한 식용 패치 anchor는 클라이언트 충돌 결과로 이동시키지 않는다. 충돌/지형 준비가 늦으면 임시 표시를 보류할 수 있지만 서버 위치는 유지한다.

기본 배치 생성·trace는 캐시 miss 또는 명시적 설정/지형 revision 변경 시 수행한다. 매 프레임 전수 재생성/trace는 금지한다. 이동 지형 등 지원하지 않는 경우 명확히 진단한다. World Partition의 표시 언로드와 Native 시뮬레이션 수명은 분리하여 오프스크린 먹이/패치를 삭제하지 않는다.

### 4.2 개체 상태 흐름

```text
섭식 의도 있음 → 제한된 주변 검색 → 목표/접근 슬롯 선택·예약
             → 기존 Native 조향으로 접근 → 이동 후 도착 검증
             → C4에서 실제 수요·소비 commit → 동일 PatchId 외형 갱신
종료/실패/위험/이주/포만 → 예약 해제 → 기존 행동 또는 재탐색
```

1. 현재 목표가 유효하면 유지하고 O(1) 검증한다. 매 tick 전체 후보를 다시 검색하지 않는다.
2. 검색은 현재 셀과 이웃 8셀부터 수행한다. 후보를 거리, 식용 잔량, 접근 가능성, 경합 비용으로 평가한다. 점수 가중치는 기존 설정 객체에 노출한다.
3. 후보가 없으면 다음 ring을 나중 step에 확장한다. 탐색 반경/후보 검사 예산/재시도 간격을 제한하며, 한 개체가 예산을 독점하지 않도록 순환 처리한다. ‘이번 예산에서 못 찾음’을 ‘지역 먹이 고갈’로 보고하지 않는다.
4. 접근 슬롯을 원자적으로 예약한다. 슬롯 transform은 패치 중심/반경, 개체 몸 크기와 입 오프셋에 따라 계산한다. 실제 식용 영역과 접근 자리를 구별한다.
5. 이미 예약된 인접 패치 슬롯과 body 공간이 겹치면 거절/다른 슬롯 선택한다. 같은 패치에만 중복 금지해도 겹친 두 패치의 개체 충돌은 남기 때문이다.
6. 목표는 기존 Native 이동 입력 훅에 전달한다. 위치를 직접 보간/텔레포트하는 두 번째 이동 writer를 만들지 않는다. 기존 위험 회피/피난/이주 우선순위가 섭식보다 높다.
7. 이동 결과로 도착을 판정하고 C4가 소비를 결정한다. 다음 step의 목표 재선택에 현재 소비 결과를 반영한다.

탐색 캐시를 위한 슬롯 점유 마스크는 선택 최적화일 뿐 권위 예약 검증을 대신하지 않는다. TTL은 서버 시뮬레이션 시간 기준으로 갱신하며 실제 접근 진행이 없으면 갱신을 거절한다. timeout/경로 실패 후 짧은 재시도 억제와 다른 후보 선택으로 같은 막힌 자리를 반복 점유하지 않는다. 기아 개체도 공정하게 재시도할 수 있게 실패 횟수·대기 시간을 계측한다.

초기 동시 슬롯 수는 패치당 1을 기본으로 하되 설정으로 확장한다. 작은 패치에 여러 슬롯을 만들려면 몸 크기/식용 반경상 실제 공간이 있는지 검증한다. 죽음·despawn·context 이동·지역 이주·포만 취소·위험 반응·epoch 교체·복원 시 목표와 예약을 해제한다. 슬롯 재사용에는 generation을 붙여 이전 소유자의 지연 해제/소비 요청이 새 예약에 영향을 주지 않게 한다.

### 4.3 도착 판정과 화면상 일치

섭취를 허용하려면 다음 조건을 **같은 Native step의 이동 후 상태**에서 모두 만족해야 한다.

- 목표 PatchId/epoch와 예약 소유자/generation이 유효하고 먹이가 양수다.
- 기존 행동이 섭식을 허용하며 이주/피난/포식 회피 등이 선점하지 않았다.
- 서버 body와 heading, 종/크기 설정의 mouth offset으로 계산한 섭식점이 패치 식용 범위에 들어온다.
- XY 거리, 높이차, 방향 오차, 이동 속도가 각각 설정 허용치 이하다. 2D 셀 거리만으로 절벽 위/아래에서 먹지 않는다.
- 접근 지면이 유효하고 몸이 슬롯 도착 범위에 있다. Dedicated 서버의 애니메이션 socket tick은 요구하지 않는다.

Native 위치 단위와 UE cm 변환은 기존 adapter 한 경로를 사용한다. body가 이웃 셀에 있어도 입이 유효한 목표 패치에 닿으면 그 **목표 셀**을 차감한다. body 셀로 다시 대체하지 않는다.

클라이언트는 같은 step/target의 확정 섭식 상태로 머리 방향과 먹기 연출을 표시한다. 이동 보간과 풀 감소 시점을 함께 대조하고, 오래된 target으로 새 패치의 먹기 연출을 재생하지 않는다. 잎 끝의 바람 변형 대신 안정적인 식용 footprint를 기준으로 판정한다. 입의 실제 표시 위치 오차는 별도로 측정하며 조향·애니메이션 정렬이 끝나야 시각적 일치 완료로 판정한다.

## 5. 복제·렌더·저장

- 기존 Field FastArray를 확장한다. descriptor/권위 지면 정보는 초기 또는 revision 변경 때 보내고, 잔량은 변경된 패치만 전송한다. 셀 단위 변경 마스크+압축 payload와 패치 단위 항목 중 실제 serializer bytes를 측정해 선택한다.
- 후보 위치 계산이 동일한 경우 XY/yaw는 descriptor로 재구성할 수 있다. Z/normal/유효성은 서버 결과 또는 확인된 권위 캐시가 기준이다. seed만 보내고 서로 다른 지면 trace가 같은 결과라고 가정하지 않는다.
- NativeStep, LayoutEpoch, state revision을 포함한다. 여러 항목으로 나뉜 초기 snapshot은 staging 후 일관된 revision으로 적용한다. 누락/재접속은 전체 snapshot으로 회복하고 오래된 epoch/update는 거절한다.
- 근거리에서는 잔량이 양수인 실제 패치를 각각 표시한다. 셀 전체 Density에 따른 prefix 후보 삭제를 제거한다. 개별 잔량에 따라 높이/폭/custom data를 바꾸고 정확한 0에서 해당 패치를 제거한다.
- 원거리 통합 표현은 유지 가능하나 섭식 관찰 범위에서는 활동 PatchId를 정확한 위치에 표시한다. 카메라 회전/LOD 전환의 여유 구간과 유지 시간을 설정하고 동일 패치 중복 표현을 막는다.
- 먹는 개체가 보이는데 필요한 Field가 relevance 밖인 경우를 시험한다. 기존 relevancy/전송 우선순위로 활동 패치를 함께 수신하게 하고, 전송되지 않은 가상 잔량을 클라이언트가 생성하지 않는다.
- 클라이언트 표시 OFF 또는 플레이어 부재에서도 Native 진행/소비/재생 결과가 동일해야 한다.
- 체크포인트 버전을 명시적으로 올리고 배치 descriptor·지면 권위 정보·패치 잔량을 저장한다. 임시 슬롯 예약은 저장하지 않고 복원 후 재탐색한다. 구버전 셀 전용 저장의 결정적 배분 이전과 새 버전의 checksum/경계값 검사를 추가한다. 복원 검증 실패 시 현재 월드에 일부만 적용하지 않는다.

## 6. 설정과 기존 디버그 확장

## 9. 비용 검증 설계

**최적화 성공을 미리 가정하지 않는다.** 기존 셀 소비는 간단하다. 정확한 위치/예약 기능은 추가 비용이며, 캐시·근접 검색은 그 추가 비용을 제한하는 수단이다. CPU 절약이 GPU draw/삼각형 감소를 뜻하지 않는다.

### 9.1 산술 예측과 계측 구분

1102 기준 후보수는 `4지역 × 900셀 × 9후보 = 32,400`이다. 후보당 16/32bytes라면 원시 배열만 각각 `518,400 / 1,036,800bytes ≈ 0.49 / 0.99MiB`다. 이는 위치 등 **단일 레코드의 가정**이며 double 잔량/용량, scratch, 예약, 컨테이너, 복제 이력, ISM/GPU를 합친 메모리가 아니다. `sizeof`, 배열 capacity/allocated bytes와 엔진 측정을 기록해야 한다. 25후보 시험은90,000개다.

첫 9셀 검색의 후보 상한은 기본81, 최대 설정225다. 이는 첫 ring만의 상한이고 넓은 검색 전체의 상한은 아니다. 개체별 유지 검사는 별도 O(1), 추가 ring은 예산 이내로 이월한다.

### 9.2 비교 모드와 동일 조건

| 모드 | 비교 목적 |
|---|---|
| A 현재 기능 OFF/셀 소비 | 신규 기능 전체의 추가 비용 및 기존 회귀 기준 |
| B 정확한 패치+캐시+목표 유지+예약 | 제품 후보의 총 비용/정확성 |
| C B와 같은 입력, 순수 배치 계산만 반복 | 캐시의 좌표 계산 절약. 지면 trace를 일부러 전수 반복하지 않음 |
| D B와 같은 후보 snapshot, 제한된 QA에서 전수검색 대 근접검색 | 검색 결과 품질·검사수·시간 비교. 제품에 무제한 전수검색 경로를 노출하지 않음 |

A와 B는 행동/경로가 달라지므로 같은 seed가 동일 작업량을 보장하지 않는다. 총 시스템 결과 비교와, 고정 query/배치 snapshot을 재생하는 C/D 미세 측정을 구분한다. 예약은 같은 경합 입력에서 활성/비활성 실험으로 예약 자체 시간과 중복 접근·실패 재시도 수를 비교한다. 예약 OFF의 동작이 기능 합격 조건을 충족한다고 간주하지 않는다.

같은 PC/CPU/GPU, 엔진·빌드 종류, 해상도/카메라 경로/메시/그림자/seed·기후·배포 설정으로 비교한다. 정식 측정은 엔진/다른 빌드와 동시 실행하지 않는다. 모드 순서를 교대하고 tracing ON/OFF 오버헤드를 별도 확인한다.

### 9.3 부하와 수집

- 기본: 1102 4지역, 사슴48/늑대16, 후보9, Dedicated+Client2 및 Standalone을 분리.
- 확장: 사슴192 및384/늑대16. 기존 지역별/전체 개체 제한을 먼저 확인하고 기존 설정으로 수용 가능한 경우만 실행한다. 생성 거절/실제 수가 다르면 그 결과를 표에 기록한다.
- 후보 상한25, 같은 패치 집중 경쟁, 지면 초기화, late join, 지역 반복 방문을 별도 최악 조건으로 수집한다.
- 각 정식 조건은 warmup30초 + 측정180초, 고정 seed3개로 반복한다. 초기화/late join 비용은 warmup 밖이라도 별도 계측하여 숨기지 않는다. F12는 별도30분 실행이다.
- 서버 Native step(현재 약7.5Hz)의 실행시간과 게임 frame 시간을 혼합하지 않는다. 비활성 frame을 포함한 평균으로 active 처리의 스파이크를 숨기지 않는다.

| 계측 | 필수 수치 |
|---|---|
| 서버 CPU | 배치 생성, trace 적용, 목표 유지, 검색, 예약, C4, 게시 각각 count/total/mean/p50/p95/p99/max ms. Native 전체/게임 frame 병행 |
| 작업량 | 검색 개체수·후보 검사수·검색/초, 목표 유지율, 예약 실패/timeout/재탐색, trace/frame, 초기 준비 시간 |
| 메모리 | static/dynamic/scratch/lease/cache의 allocated bytes·peak, 컨테이너 용량. 연결별 복제 상태/이력과 Client ISM/GPU를 분리 |
| 네트워크 | 연결별 초기 snapshot bytes, steady delta bytes/s와p95, 실제 serializer bits, 전체 socket bytes/s, patch 변경수/초 |
| Client | render update CPU/frame p95/p99, 게임/렌더 스레드, GPU frame ms, instance/draw 수, 시각 반영 지연/누락 |
| 정확성 | 장부 오차 최대, 잘못된 위치 소비수, stale target/lease, 서버/Client anchor 오차, 슬롯 초과 동시 소유수 |

정확성용 상세 JSON은 성능 capture와 분리하거나 샘플링 비용을 명시한다. 기존 NetAudit가 구분한 payload/소켓 총량·카운터 wrap 검증을 유지한다. 과거 JYU/다른 설정의 숫자를 새로운 1102 A 기준선으로 대체 사용하지 않는다.

### 9.4 초기 성능 판정 예산

아래는 **구현 전 제안 예산**이며 실측 결과/성능 보증이 아니다. S0에 PC/빌드·설정을 기록하고 예산을 동결한다. 실패하면 원인과 변경 근거를 남겨 예산 수정/최적화를 결정하며 결과에 맞춰 조용히 완화하지 않는다.

| 항목 | 초기 목표 |
|---|---|
| B의 패치 기능 서버 CPU 합(탐색·예약·배분·게시, 초기화 제외) | 기본48마리 active Native step p95≤1ms/p99≤2ms, 384마리 p95≤2ms/p99≤4ms |
| 초기화/재검사 지면 trace | World 합산≤96회/frame. 시간도 기록하고 초과 시 작업 이월 |
| 후보 검사 | 개체당 first ring≤9×PatchCount, World 합산≤4096검사/Native step. 이월 지연과 기아도 같이 검증 |
| 서버 패치 추가 상주 메모리 | 32,400후보에서 Native 배치·배분·scratch·lease 합≤8MiB. 복제/렌더 포함 총량은 별도 공개 |
| B steady Field payload/연결 | 같은1102 A 대비≤1.5배를 초기 목표. A≈0인 구간은 비율 제외하고 실제bytes/s 명시 |
| B Client frame | 같은 카메라의 A 대비 CPU/GPU p95 악화 각각≤10%를 초기 목표. 다른 instance 수 영향 병기 |
| 장기 누수/정확성 | F01~F12 필수. 비용 예산을 맞추려고 잘못된 원격 섭취를 허용하지 않음 |

캐시/근접검색의 효과는 `절감률=(비교모드시간-B시간)/비교모드시간×100`과 절대 ms를 함께 보고한다. 미세한 차이가 반복 변동 범위 안이면 ‘효과 불명’으로 기록한다. 예약의 성공은 CPU만이 아니라 중복 접근·정체·재탐색 수 감소와 추가 메모리를 함께 평가한다.

결과 파일은 `Saved/FoodPatchGrazing_<실행일시>/`에 manifest, 기능 결과, 성능 CSV/trace, 네트워크 요약, 화면 증거를 보관한다. manifest에는 commit/diff 요약·설정 hash·실제 개체수·실행시간·프로세스 종료코드를 넣는다. 결과표의 미실행 칸은 ‘미측정’으로 남긴다.
