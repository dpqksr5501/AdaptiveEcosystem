# 16종 생태계 공존·형질 적응 구현 목표

2026-11-22 · 등록한 구현 목표와 완료 기준

현재 구현과 실행 증거는 [형질·계보 첫 통합 기록](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md)에서 확인한다. 아래 작업표는 16종 전체의 종료 기준이다.

## 1. 최종 완료 상태

**최신 소유 섬의 16종이 플레이어·환경·다른 동물과 하나의 권위 생태계에서 상호작용하고, 종마다 최소 한 가지 유전 형질이 실제 능력과 플레이어가 읽을 수 있는 표현에 연결된다.** 플레이어의 관찰·이동·소음·접근·추격·사냥과 날씨·낮밤·먹이·수위·지형이 기존 감각과 실행을 통해 개체·지역의 변화를 일으킨다. 실제 생존·번식·이주가 다음 세대의 형질 분포에 주는 영향을 기존 생명주기와 장부에서 추적할 수 있어야 한다. 첫 2종과 초기 PPO 대상 6종은 공통 구조를 검증하는 단계다. 최종 완료는 이 문서의 16종 증거와 공통 회귀로 판정한다.

- **같은 개체의 현재 변화**는 나이·성장·피로·부상·영양·기억에서 설명한다. **세대 변화**는 출생 때의 유전값, 실제 부모 기여, 후손의 성숙 및 지역 분포에서 확인한다. 사냥·공격·도주 횟수를 유전값 가산으로 사용하지 않는다.
- **모든 종의 완료 증거**는 ① 기존 실행기와 지원 능력, ② 부모·새끼·유전값, ③ 최소 한 가지 실제 성능 차이와 그 비용, ④ 환경이나 플레이어 사건으로 달라진 행동·결과, ⑤ 그 몸과 행동을 읽을 수 있는 표현·단서다. 도주·은폐·섭식·상륙·이륙 등 종에 맞는 능력을 택한다.
- **지역의 완료 증거**는 출생·사망·유입·유출·가용 자원·실제 지급을 기존 장부와 대조하고, 플레이어 교란·자연 포식·자원 부족·이주에 따른 결과를 구분할 수 있는 것이다. 관찰·사냥·안전한 접근이 어떤 차이를 만드는지 확인할 대표 장면을 둔다.
- **세대에서의 선택 효과**는 첫 통제 장면에서 플레이어 압력과 연결된 부모 번식 편차와 후손 분포를 여러 독립 시드로 비교한다. 16종에서 유전 인계와 실제 능력을 확인하되 특정 종·지형의 선택 결과는 그 조건으로 기록한다.
- **개발과 팀 경계**는 기존 서버 권위, 개체별 단일 이동·대사·자원 writer, V1/v3/R9 관측·행동·모델과 팀 원본 맵의 설정을 유지하는 것이다. 먼저 소유 맵에서 검증하고, 새 외형·학습 변경·팀 맵 반영은 각자의 승인 및 검증 범위를 따른다.

### 공통 계약

- **정책 인수.** PPO 장착을 유전·체형·표현의 선행 조건으로 두지 않는다. 받은 팩의 종·출처·몸 해시·관측·행동·mask·단위·보상·환경과 섬의 실제 권위 호출을 확인한다. 기존 V1/v3/R9와 RL 평가 시드를 보존한다. 바뀐 물리·피로·감각이 학습 조건을 벗어나면 RL 담당과 mirror·Golden 비교·재학습 범위를 정한다. [R9 인수와 검증](../RL_Policy/R9_CLOUD_TRAINING.md)
- **플레이어와 지역.** 감지→선택→실제 결과→사망·섭취·이주·출생을 연결한다. 목격·추격·피격의 증거, 온화한 방문과 반복 사냥, 가까운 무리와 다른 지역의 기억 범위를 구분한다. 위험이 낮아진 뒤 상류↔강변에서 현지 출생과 이주 유입을 따로 본다.
- **표현과 지속성.** 기존 BodyScale·Maturity·CoatTone·접지를 우선 사용한다. 신규 사지·발톱은 종의 행동과 실제 접촉을 짝지어 검증한다. 서버가 세대·형질·장부를 확정하며 Client는 필요한 표현만 받는다. 풀 재사용, 저장 복원, 늦은 접속 뒤 이전 개체의 표현이나 재고가 이어지지 않아야 한다. ## 4. 빌드와 검증을 묶는 방식

| 실행 | 묶어서 확인할 범위 |
| --- | --- |
| **읽기 전용과 저비용 검사** | 작업 전후 계약·의존성·변경 경로를 확인한다. 문서만 바뀌면 링크와 diff를 점검한다. C++을 바꾸기 전에 기존 기준 바이너리·계측·리그 결과를 사용할 수 있는지 확인한다. |
| **직접 UBT** | C++/빌드 입력을 검토하고, **실행 가능한 변경 묶음**이 준비되면 직접 `UnrealBuildTool.exe`로 `AdaptiveEcosystemEditor Win64 Development`를 빌드한다. 지상·공중·수중/수륙의 관련 변경을 의존성에 맞춰 묶는다. 종마다 반복하거나 동일 빌드를 불필요하게 다시 만들지 않는다. 수정으로 바이너리가 바뀌면 영향 있는 회귀를 다시 확인한다. [루트 UBT 규칙](../../../AGENTS.md#3-작업-전후-확인-절차) |
| **집중 자동화·PIE** | 같은 바이너리의 한 실행에서 기본값과 opt-in, 출생·사망·이주·자원 수지, 감각과 실제 실행을 연결한다. 종마다 에디터를 따로 시작하지 않고 대표 장면 묶음에서 16종 결과를 집계한다. 시드별 독립 초기 상태가 필요한 대조에는 같은 빌드를 재사용한다. 공통 경계를 바꿨거나 집중 검사에서 위험 신호가 나오면 더 넓은 suite를 실행한다. |
| **대표 전용 서버·복원** | 실제 표현은 대표 지상·공중·수중 리그를 확인하고 장부·감각은 Headless를 활용한다. Dedicated + 두 Client 대표 장면에서 동시 히트·사체 지급, 이탈/재진입, 늦은 접속을 묶는다. 새 프로세스 복원은 같은 빌드에서 대표 복원 한 묶음으로 확인한다. 종별 성공 증거는 각각 남기되 같은 공통 회귀를 16번 반복하지 않는다. |
| **쿠킹·패키징** | 일반 구현·회귀에는 기본 제외한다. 배포본 검증이 별도로 요청되거나 에셋 누락·Shipping 등 배포 빌드에서만 재현되는 문제가 확인된 경우에만 목적과 범위를 정한다. PIE·에디터 바이너리 전용 서버 결과는 패키지 검증과 구분한다. |

UBT·dotnet·Unreal Editor·Live Coding·MSBuild·ShaderCompileWorker 실행 중에는 기존 작업이 끝날 때까지 기다린다. 빌드를 중단하거나 동시에 더 실행하지 않는다. dotnet 예외는 최초 UBT/컴파일 오류와 Windows Application Event Log를 확인한다. 읽기 전용 코드 검토와 결과 JSON 분석은 빌드를 진행하지 않는 독립 작업으로 처리할 수 있다.

[섬 검증 실행기](../../Tools/Editor/run_jyu_island_audit.ps1)는 소유 섬과 시드·Headless·개체군 비교에 사용한다. [개체 수지 검증](../../Tools/Editor/check_island_population_receipts.py), [저장 결과 검증](../../Tools/Editor/check_island_checkpoint_receipts.py)은 입력 형식·버전을 맞춰 재사용한다. [사냥 네트워크 실행기](../../Tools/Editor/run_player_hunting_network.ps1)는 에디터 바이너리로 서버와 Client를 띄우지만 현재 JWJ 맵을 연다. 소유 섬의 멀티플레이에는 맵과 초기 조건이 맞는 실행을 사용한다. [기존 팀 패키지 검증](../../Tools/Editor/test_jwj_multiplayer.ps1)은 패키지 바이너리를 요구하므로 기본 검증에 포함하지 않는다.

소유 섬의 전용 서버 검증에는 [공용 표적 실행기](../../Tools/Editor/run_jwj_rifle_network.ps1)의 `-SavedIsland -SharedTarget`을 사용한다. 두 Client의 피해 영수증·동일 개체의 생사·사체 수지를 대조하고, 한 Client가 남아 있는 동안 다른 연결의 이탈과 새 연결을 확인한다. 이 실행의 사체에서는 실제 섭식이 없었다. [두 클라이언트의 사냥과 연속 관찰](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#두-클라이언트의-사냥과-연속-관찰)

실제 서버 피해를 같은 지역에서 직접 본 규칙형 지상 개체가 기존 도주 경로에 반응한다. 맑은 낮 소유 섬 PIE에서 멧돼지 사냥과 물소의 목격·권위 도주 상태·사체 수지를 확인했다. 등진 개체·차폐·기록 전용과 야간 시야의 통제는 자동화에서 확인했다. 이 변경은 종간 상호작용 반영 모드에서 적용한다. [플레이어의 공격을 직접 본 지상 개체](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#플레이어의-공격을-직접-본-지상-개체)

지상 표범의 플레이어 잠행 옵션을 켠 저장 섬 PIE에서 낮·밤과 맑음·비를 조합했다. 맑은 낮에는 8초 동안 잠행·공격 준비·피해가 없었고, 비 오는 낮과 밤의 두 조건에서는 잠행 뒤 서버 피해 20을 확인했다. 별도 강우 전용 서버에서는 두 플레이어 중 가까운 한 명에게 피해가 한 번 적용됐고, 양쪽 클라이언트가 같은 개체의 잠행과 공격을 수신했다. 시야 반대편·접촉 전 이탈은 집중 자동화로 대조했다. 기존 표범의 먹잇감 사냥과 한 이동기를 사용한다. [강우에서 표범의 플레이어 잠행과 접촉](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#강우에서-표범의-플레이어-잠행과-접촉)

기록 전용과 반영 모드의 실제 소총 대조에서 같은 물소의 권위 위치·속도·행동을 수집했다. 반영 모드의 첫 도주 표본은 총성 감지보다 앞섰고, 기록 전용에서는 총성 감지 뒤에 도주가 관찰됐다. 이후 궤적에는 후속 소음 반응도 들어 있다. [총성이 감지되기 전의 실제 도주 이동](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#총성이-감지되기-전의-실제-도주-이동)

물소 보호자의 유전 체격을 실제 공격선 차단 반경에도 연결했다. 통제 접촉에서 같은 위치의 큰 보호자는 새끼를 막아 주고 스태미나를 썼다. 소유 섬의 물소 먹잇감 대조에서는 표범이 추격을 잠시 놓친 동안 보호자가 시야를 유지해 재개된 공격을 차단했고, 자연 출생 새끼의 체력을 보존했다. 저장 배치의 먹이망과 물소 2세대 유지 효과는 별도 검증에 남았다. [물소 보호자의 유전 체격과 새끼 방어](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#물소-보호자의-유전-체격과-새끼-방어)

`-CheckpointRoundTrip`은 사냥 직후를 저장하고 새 전용 서버에서 복원한다. 살아 있는 개체의 계보·유전값, 사망 상태, 대표 재고, 새 Client의 표현, 복원 후 사체 수지를 확인했다. 복원된 사체의 실제 섭식 지급은 이 사례의 검증 범위 밖이다. [전용 서버 사냥 직후 체크포인트 복원](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#전용-서버-사냥-직후-체크포인트-복원)

규칙형 운영 복구는 초지 멧돼지의 조건부 사냥 시험에서 두 부모 없는 0세대 개체의 실제 등록, 재실행 거절과 복원, 첫 식생 지급을 확인했다. 생존 개체 또는 들어오는 동종이 있는 지역에서는 운영 방사를 거절하며, 장기 정착과 자연 재유입은 별도 근거를 모은다. [사냥 이후 초지 멧돼지 운영 복구](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#사냥-이후-초지-멧돼지-운영-복구)

`check_island_trait_cohorts.py --overview`는 한 실행에서 16종의 실제 실행기, 사망 원인, 지급 영양, 출생·성숙·생존 세대와 장부 일치를 함께 보여 준다. `--compare`로 시작 개체·유전값과 먹이 입력 일치를 확인한다. 공통 규칙 후보는 저장 섬의 같은 자원으로 우선 비교하고, 효과가 갈리는 종과 생애 단계에 별도의 짧은 진단을 쓴다. 장시간 독립 시드와 대표 저장·멀티 검증은 공유 경로 후보가 정해진 뒤 같은 빌드에 묶는다.

**서버 에이전트는 선택지다.** 독립적으로 진행 가능한 코드 검토·로그 집계, 또는 동일 SHA·UE 버전·모델·맵 설정을 고정한 별도 환경의 대표 멀티플레이 시험에 쓸 수 있다. 실제 빌드와 로그·맵·시드를 함께 남기고, 공유 엔진·체크아웃에 UBT를 중복 실행하지 않는다.

## 5. 증거와 종료 판정

최신 종별 출생·성숙·먹이와 서버 검증은 [실행 증거](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md)에 누적한다. 저장 섬과 먹이·시작 밀도를 조정한 별도 실행을 합쳐 16종에서 두 부모가 확인된 출생을 관찰했다. 일반 섬의 포식자 유지와 전 종의 여러 세대 변화는 이 증거에 포함되지 않는다.

**유전색 검증 범위.** 소유 섬 16종의 유전값과 머티리얼 표시를 연결했다. 눈밭의 늑대–사슴 대조에서 밝은 털의 최초 시각 검사 통과율이 낮았고, 두 시드 모두 위장으로 밝은 창시 사슴의 출생 기여가 늘지는 않았다. 한 시드에서 4세대 출생을 관찰했으며 밝은 색의 세대별 증가와 장기적인 생존 이점은 확인되지 않았다. 완료 판정에서는 최초 시각 감지, 실제 생존·번식, 여러 세대의 분포를 각각 확인한다. [16종 유전색 검증](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#16종-유전색-검증) · [눈밭 40게임분 대조](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#눈밭-사슴의-감지생존번식-대조)

장기 검증의 분류는 PPO 팩 보유 여부와 별도로 해당 세션의 실제 실행기를 따른다. 현재 30게임분 표본은 사슴 PPO R7e, 늑대 Native 위협 FSM, 규칙형 14종이다. 시작과 종료 개체 수, 최고 출생 세대, 16종의 클라이언트 스케일은 [같은 증거표](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#현재-실행기별-30게임분-개체군)에서 확인한다. 같은 종의 후보 모델을 비교할 때는 섬 배치와 초기 자원·압력·실제 활성 모델을 기록하고, 사망 원인과 먹이 도달·지급을 같이 확인한다.

이어서 기존 일곱 패치의 재생률만 3배로 바꾼 장기 대조에서는 물소와 산토끼 창시 세대가 두 시드에서 생존했다. 두 종은 1세대 출생을 확인했으며 종료 표본에서 1세대 생존과 2세대 출생은 없었다. 말 생존 방향이 시드별로 달랐고 두 시드에서 까마귀가 사라져 여러 종의 개체 수지와 후손 생존을 묶어 검토한다. 이 비교는 PIE 입력 변경으로만 적용했다. [실제 패치 지급과 재생률 대조](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#물소산토끼의-실제-패치-섭식과-재생량)

노출 식생에서 동시에 도달한 개체의 섭식 순환을 별도 옵션으로 추가했다. 한 장기 대조에서 산토끼 1세대가 성숙 후 종료까지 생존했으며 물소는 종료 생존 2→0으로 줄었다. 같은 먹이점에서 후손으로 지급 순서가 바뀐 영수증과 세대별 실제 지급을 확인했다. 다종 장기 결과와 2세대 출생의 근거가 더 필요해 저장 섬 기본 적용은 보류했다. [육상 섭식 순환과 후손 영양](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#육상-식생의-동시-지급과-후손-영양)

두 시드의 30게임분 기록에서 성숙 후손과 혈연 제한을 통과한 짝의 지역·거리·동시 에너지를 대조했다. 말과 물소는 가까운 짝이 있어도 에너지가 부족했고, 산토끼는 시드에 따라 성숙 후손의 짝이 다른 지역에만 존재하거나 가까운 짝의 에너지가 부족했다. 같은 실행의 멧돼지 2세대 한 마리에서 부모·실제 섭식·종료 성숙·체격 표현을 연결했다. 생산 배치를 바꾸기 전에는 종별 근거리 먹이 접근과 도달할 수 있는 이주 통로를 별도 조건으로 비교한다. [성숙한 후손의 짝과 에너지 표본](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#성숙한-후손의-짝과-에너지-표본)

기존 초지 두 패치의 재고를 그대로 두고 건조한 접근점만 늘린 대조에서는 물소 1세대 두 마리가 각 시드의 30게임분 종료까지 살아남았다. 두 시드에서 말의 섭식과 생존이 줄었고 물소·말의 2세대는 없었다. 접근점끼리 재고를 공유하는 지급을 실동작에서 확인했다. 공존 기준을 충족하지 않은 이 배치는 PIE 조건으로 유지한다. [같은 재고에 연결한 초지 섭식 접근점](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#같은-재고에-연결한-초지-섭식-접근점)

말이 실제로 먹던 WestMeadow 쪽으로 접근점을 분산한 두 시드에서는 이전 공용 배치보다 말의 섭취와 전체 생존이 늘었다. 접근점 추가가 없던 대조군보다 말 생존이 낮았고, 두 시드의 분산 배치에서 종료에 남은 말 1세대와 물소·말의 2세대 출생은 없었다. 말과 물소가 같은 시각에 다른 접근점에서 동일 재고를 나누어 쓴 영수증을 확인했다. 접근점만 바꾸는 시험으로 두 종의 장기간 공존이 확보되지 않아 기본 적용은 보류했다. [물소와 말의 섭식 접근점을 나눈 대조](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#물소와-말의-섭식-접근점을-나눈-대조)

권위 섭식의 첫 부족을 먹이 방문이 닫히기 전에 다음 후보 점수에 반영한다. 실제 지급·재고·후보 점수를 같은 섬 실행에서 연결했고 기존 식생·개체 수지와 집중 자동화를 통과했다. 30게임분 대조에서 물소와 말의 2세대 출생은 관찰되지 않았다. [첫 섭식 부족을 다음 선택에 반영](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#첫-섭식-부족을-다음-선택에-반영)

같은 섬·시드·먹이 배치에서 규칙형 번식 순서만 바꾼 후속 시험에서도 물소·말·산토끼 1세대는 부모로서 번식을 예약하지 않았다. 물소는 성숙 후 가까운 짝이 있었고 말과 산토끼도 같은 지역의 짝과 근접한 표본이 있었다. 세 종 모두 가까운 두 개체가 동시에 에너지 70%를 넘은 표본은 없었다. 다음 대조는 짝과 동시에 실제로 확보한 영양과 지역 이주 유입을 기록하며, 번식 순서 비교 결과는 섬의 기본값에 적용하지 않았다. [같은 초지에서 실제 번식 예약과 부모 순서 비교](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#같은-초지에서-실제-번식-예약과-부모-순서-비교)

플레이어 압력은 두 세계 시드의 30게임분에서 Grassland 지정 성체 사슴 한 마리만 같은 피해량으로 제거하고 후손의 형질 분포·번식 기여를 확인했다. Grassland 창시 사슴 12마리의 유전값이 다른 후속 집단에서 최대 체격 유전값과 무작위 표적을 각각 제거했다. 두 표적의 표현 체격은 같았다. 플레이어가 볼 수 있는 체격 구간별 포획·부모 기여와 여러 집단에서의 반복 결과가 남아 있다. [사냥 피해와 세대 대조](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#별도-창시-집단과-체격을-읽지-않는-표적-선정)

후속 표시 체격 시험은 두 창시 집단에서 각각 큰 쪽과 작은 쪽을 사냥했다. 첫 발에서 선택한 체격과 실제 메시 표현이 일치했고, 표적별 피해 100과 사망 한 건을 검증했다. 두 집단의 작은 쪽 사냥에서 3세대 출생을 관찰했으나 후손 평균 체격의 변화 방향은 일관되지 않았다. 네 표적 사체는 섭식 없이 만료됐다. 반복 사냥과 사체의 실제 먹이망 효과는 별도로 검증한다. [표시 체격과 권위 세대 대조](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#표시-체격의-양끝을-고른-사냥-대조)

사냥 시점의 후속 대조에서 같은 사슴의 영양 100을 늑대·까마귀·멧돼지가 실제로 소비하는 경우를 확인했다. 다른 시드에서는 멧돼지가 사냥 사체를 선택했다가 위협으로 이탈해 지급이 없었다. 개체의 허기·도달과 다른 먹이 선택을 실제 지급 근거에 연결했으며, 여러 번의 사냥에 대한 지역 먹이망·개체군 반응은 남아 있다. [사냥 시점별 실제 지급](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#사냥-시점에-따른-사체의-실제-지급)

같은 지역의 두 차례 사냥을 단발과 대조했다. 30게임분 시드에서는 추가 사냥으로 사라진 부모의 기여와 다른 부모의 후속 출생을 확인했다. 별도 10게임분 시드에서는 두 번째 사체 지급, 사망 전에 태어난 후손, 피해를 받지 않은 사슴 두 마리의 공포 표본을 확인했다. 장기간 반복 압력과 지역 회복, 여러 접속자의 권위 결과는 별도로 검증한다. [단발과 두 차례 사냥](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#같은-지역의-단발-사냥과-두-차례-사냥)

규칙형 멧돼지에 같은 빈도 검사를 적용했다. 30게임분의 한 시드에서 동일한 1세대 개체가 부모의 추가 피격을 목격했고, 도주 중 이동과 형질을 기록했다. 추가 사체는 까마귀 두 마리에게 영양을 지급했다. 단발과 반복의 후손 섭취·사망·종료 개체 수가 달랐고, 이 실행에서 멧돼지 2세대 출생은 관찰되지 않았다. [같은 초지의 멧돼지 단발과 반복 사냥](MMORPG_ECOSYSTEM_TRAIT_EVIDENCE_20261122.md#같은-초지의-멧돼지-단발과-반복-사냥)

1. **종별 상태표를 갱신한다.** 구현, 실제 실행 증거, 검증한 조건, 남은 조건을 종별 한 줄로 관리한다. 조우나 지급이 발생하지 않은 실행, 미지원·실패 결과를 분리한다.
2. **비교 조건과 자원을 보존한다.** 같은 초기 시드·형질 분포·모델·맵·날씨·플레이어 동선·배속으로 비교한다. 개체·먹이·사체의 시작·종료 장부와 이주·운영 투입·만료를 대조한다. 세대 효과는 독립 시드, 실제 번식과 후손에서 확인한다.
3. **원인과 한계를 사용자에게 보여 준다.** 플레이어 압력 뒤 후손의 어느 특성이 어떻게 달라졌는지, 가시적 단서, 멀티·복원 검증 조건을 기록한다. 출생만 관찰하고 성숙·다음 번식이 없으면 그 범위까지 보고한다.
4. **최종 완료는 16행을 채웠을 때다.** 2종·6종 중간 결과를 보존하고, 16종의 최소 한 가지 형질·성능·표현, 16종이 함께 있는 공통 수지, 대표 동시 접속·저장 복원을 묶어 판정한다. 장기 평형, 16종 PPO 전부 학습, 배포 패키지의 검증은 각각 따로 기록한다.

| 남길 증거 | 최소 기록과 판정 |
| --- | --- |
| 출생에서 능력까지 | 개체·종·부모 안정 ID, 출처, 세대, 유전 축 값, 성숙도·신체 상태와 파생 성능을 잇는다. 같은 성숙도·상태의 대조에서 능력 차이가 실제 이동·접촉·소모로 관찰돼야 한다. |
