## 권위와 선택

- 스폰·이동·섭취·피해·죽음·출생은 기존 규칙 종 권위 실행기와 M4 거래를 사용한다. 표현은 안정 ID, 현재 이동·활동, 실제 성장률을 받아 그린다. 기존 R7e 관측·출력·학습과 원준 담당 플레이어 전투를 바꾸지 않는다.
- 성장·유전은 기존 `EcoLifeV3` 개체 값을 재사용한다. 신규 규칙 종에서 체급과 나이는 충돌 크기와 포획 자격, 유전 속도·부상·피로는 이동, Caution은 위협 유지 시간과 위험 비용, Sociability는 보호자 추종 간격에 반영한다. 색과 예술적 표현은 실제 소비 코드가 생길 때만 행동과 연동됐다고 기록한다.
- 감지된 후보, 실행 가능한 후보, 선택과 실제 지급을 구분한다. 먹이 관계는 체급·나이·방어·매체를 확인하는 데이터다. 살아 있는 먹이, 제한된 패치와 사체는 같은 관측 시점에서 비교하고 접촉에서 다시 검증한다. 신규 종 모델은 나중에 선택 요청만 공급하며, 학습은 팀 담당 범위다.
- 수중 이동은 opt-in 수역의 수면·실제 바닥·유속을 읽는다. 현행 도하는 같은 수면을 사용한다. 수중 먹이와 지상 식생 재고를 분리하고, 어류를 지상 식생 소비자로 집계하지 않는다. 수위는 권위 시계의 작성된 상승·유지·하강으로 계산하며 Client 표현에는 같은 시계가 쓰인다. 잉어 산란장의 수온 17–23 °C와 느린 유속은 초기 조건이다. 메기류 산란의 정확한 수온 범위는 자료 부족으로 적용하지 않았다.

## 적용과 검증 순서

1. `import_jyu_expanded_fauna.py`에서 원본을 Saved에 스테이징하고 UE로 임포트한다. `audit_jyu_expanded_fauna_assets.py`의 뼈 좌표와 프레임 표본으로 클립 범위와 배율을 잡는다. `setup_jyu_expanded_fauna.py`에서 외부 텍스처, Blend Space, AnimBP, 소유 맵을 생성한다. 스크립트는 프로젝트 소유 태그를 가진 산출물을 재사용한다.
2. 종별 스폰·이동·접촉·섭취·사망·출생을 짧은 장면에서 확인한다. 말·큰뿔양·산토끼는 평지·경사·제동·급회전, 밍크는 제방에서의 입수·복귀, 물고기는 깊이·유속·연결 상태, 맹금류는 이륙·선회·하강·착지와 포획 접촉을 비교한다. 원본에 없는 동작의 대체 자세는 임시로 표시한다.
3. 선택 근거와 결과는 같은 ID로 연결한다. 실패는 감지·자격·경로·공격 접촉·사체 접근·실제 지급·다음 식사 간격으로 나눈다. 수위·은폐·재고는 하나씩 변경하고, 개체의 나이·크기·상태는 고정한 환경에서도 비교한다.
4. 기존 여덟 종의 기준군과 신규 추가 조건을 소유 맵에서 동일 시드·배속으로 비교한다. 초기 시드는 20000·20017이다. 환경 상태를 고정한 뒤 종별 선택기만 바꾸는 비교를 별도로 설계한다. 장시간 공존은 결과로 판단한다.
5. 서버 권위·복제와 이동·출생·사체 저장 상태가 바뀐 경로는 전용 서버 두 Client 및 저장 복원에서 확인한다. UE 5.8 직접 UBT 완료와 자동화, 화면에서 본 발 미끄러짐·루프 튐·관통 검사는 각각 기록한다.

같은 소유 맵에서 [검증 실행 스크립트](../../Tools/Editor/run_jyu_expanded_fauna_validation.ps1)의 `Crest`, `Animation`, `Persistence`, `Population`을 각각 실행한다. 결과는 `Saved/ExpandedFaunaImport`, 렌더는 `Saved/FaunaAudit`에 남는다. 수영·잠수의 이동과 수중 사체는 `EcoFaunaWaterMovement.cpp`가 계산하며, 권위 프레임과 지상 이동 호출 순서는 기존 조정자가 소유한다.

## 첫 30·60분 개체군 비교

시드 20000, 같은 `LV_JYU_ExpandedFauna`와 고정 30fps에서 실행했다. 기준군은 테스트 시작 전에 새 7개 규칙 종과 관련 먹이 후보를 제거했다. 지형과 작성된 수위는 두 실행에서 같았다. 수치에는 살아 있는 개체만 포함한다. 뒤이어 추가한 사체 부유·침강과 사냥 비행 보정은 이 실행의 조건에 포함되지 않았다.

추가군에서 메기류 8건, 잉어 6건, 산토끼 10건의 자연 출생을 기록했다. 유생과 어린 개체로 넘어가는 시간을 압축한 수치다. 큰뿔양·말·밍크·검독수리의 사망은 모두 기아였다. 샘플의 두 수역 사이 실제 이동은 확인되지 않았다. 수위로 인한 물리적 통과 허용과 자발적 통과를 별도로 검사한다. 근거는 `Saved/ExpandedFaunaImport/{BaselineSeed20000,ExpandedSeed20000}.jsonl`과 같은 이름의 로그에 있다.

저장 복원 첫 시도는 기본 R7e의 첫 결정 경계 전이라 두뇌 ID 검증에서 거절됐다. 같은 빌드에서 결정 경계를 지난 뒤 새 프로세스로 다시 로드해 104개 생존 StableAgentId의 일치를 확인했다. 이 기록은 해당 이전 포맷에 대한 검사다. 수중 사체를 추가한 포맷은 별도로 검증한다.

## 수로, 섭취와 저장 재검증

- 16개 초기 배치의 8종을 등록했다. 로우폴리 물고기는 가상 담수형으로 섭취와 `ExpandedWaterLittoralNursery` 부화가 실제로 일어났다. 같은 실행에서 잉어는 `MacrophyteEdge`, 메기류는 `RootMargin`에서 부화했다. 검독수리 ID 91은 쥐 107과 산토끼 100을 실제 포획했다. `Saved/Logs/ExpandedFauna_ExpandedSaveV9.log`.
- 수로 턱의 실제 충돌 높이는 111 cm였다. 6 cm 여유를 적용한 물리 샘플은 낮은 수위에서 실패했고 상승 구간에 열렸다가 하강 때 다시 닫혔다. 같은 초기 위치와 반대편 먹이 패치의 통제 시험에서 메기 ID 93은 수위가 변할 때 턱을 넘어 23번, 총 31.649 에너지를 먹었다. 수위를 110 cm에 고정하면 통과와 그 패치의 메기 섭취가 없었다. 비교의 입력은 먹이 경쟁을 고정하기 위해 서쪽의 메기 대상 패치만 제외했다. `Saved/Logs/ExpandedFauna_Crest{Dynamic,Closed}Final.log`.

## 경사 발 접촉 보정

공용 발 IK에서 몸통 하강과 관절 길이 제한을 적용한 뒤 최종 발 마커를 지면과 다시 대조한다. 경사면 안에서 관절이 수평으로 당겨지는 경우도 반영한다. 지면을 통과하는 발만 리그별 보정 한도 안에서 들어 올리고, 스윙과 발의 원래 회전은 유지한다. 이 변경은 표시 뼈 자세에 적용한다.

고정 평지와 12° 경사가 이어진 동일 장면을 60fps로 비교했다. 각 종마다 경사 진입·보행·선회·급반전·제동·달리기에서 발 마커 2,160개를 측정했다. 말 최저는 −4.82→+0.13 cm, 산토끼는 −5.68→+0.10 cm였다. 큰뿔양은 수정 뒤 최저 +7.48 cm였다. 큰뿔양 측정점은 발목이므로 이 값은 발굽 밑면과 지면 사이의 높이를 직접 나타내지 않는다. 별도의 응력 시험에서 테스트 판 전체를 한 프레임에 기울인 순간에는 말의 앞발 마커 두 개가 각각 −5.72, −4.81 cm였고 다음 프레임부터 지면 위였다. 일반 이동의 고정 경사 시험에는 해당 프레임이 없다. 신규·기존 8종의 렌더 검증도 통과했다. `Saved/FaunaAudit/ExpandedFaunaSlope{Before,After}Metrics.json`, `ExpandedFaunaPhysicalSlopeMetrics.json`, `ExistingFaunaIKRegressionMetrics.json`.

## 수변에서 가림과 허기가 먹이 선택에 미치는 영향

밍크의 입수 지점은 실제 지면·수심·유속으로 검사한다. 입수 지점에 연결된 먹이 패치와 주변 생먹이를 각각 검증한다. 물속 가림막이 패치와 소형어류 한 마리를 가리면 시야가 열린 다른 먹이는 여전히 평가한다.

시드 20000에서 밍크 ID 89는 두 조건 모두 17.4초, 에너지 약 86.95에서 입수를 시작했다. 시야가 열려 있을 때 처음 향한 먹이는 ID 96이었다. 가림막을 넣자 96은 `HuntOccluded`로 탈락했고 입수 목표가 97로 바뀌었다. 가림막 조건에서도 이후 관측이 바뀌자 96을 먼저 포획했고, 97도 나중에 포획해 사체에서 섭취했다. [검증 스크립트](../../Tools/Editor/run_jyu_expanded_fauna_validation.ps1)의 `WaterCover`가 목표 변경과 실제 섭취를 함께 확인한다.

가림막 없이 대사 소비율만 0.75에서 0.04로 낮춘 통제에서 같은 ID의 17.4초 에너지는 약 99.30이었다. 115초 시점 에너지는 약 95.37이었고 입수·수중 포획은 관측되지 않았다. 이 값은 허기 영향을 분리한 시험용이며 종 프로필 기본값을 조정한 결과와 구분한다. `Saved/ExpandedFaunaImport/Mink{ClearFinal,ScreenFinal,LowDemand}20000_status.json`.

검독수리 피로 통제는 같은 시드와 맵에서 비행에 적용되는 피로 소비율만 0.10→0.65로 바꿨다. 215초 동안 ID 91·92를 약 1초 간격으로 읽었다. 에너지 80% 미만의 순항 표본 중 급강하에 필요한 스태미나 0.35 미만은 기본 0/29, 높은 소모 20/26이었다. 급강하 상태 표본은 26→15였고 실제 포획은 두 조건 모두 2건이었다. 이는 상태 표본 수이며 급강하 횟수와 구분한다. `Saved/ExpandedFaunaImport/Eagle{Normal,Rapid}Fatigue20000.jsonl`.

발 IK와 수변 먹이 선택 변경 뒤 UE 5.8 직접 UBT와 전체 자동화 314건을 통과했다. 일반 성공 312건, 경고 동반 성공 2건, 실패·미실행 0건이며 기본 R7e와 플레이어 전투 회귀를 포함한다. `Saved/ExpandedFaunaIKCoverAutomation/AutomationFinal/index.json`.

## 지역 경계를 잇는 수로

- 두 지역이 인접하고 작성자가 규칙 종 통과·서식지 보고·수중 통로를 지정한 경로를 사용한다. 필수 수영 종의 체격별 수심, 실제 바닥과 수면, 역류, 목적지 수용량과 접근 가능한 먹이를 조사한다. 접근은 기존 수중 이동에서 수행한다. 경계에서는 짧은 이동의 수심과 충돌을 재검증하고 기존 도착 거래로 위치와 소속 지역을 함께 갱신한다. 지상 무리·밍크의 상륙은 각자의 기존 경로를 사용한다.
- 시드 20000에서 메기 ID 93은 수면 142 cm에서 서쪽을 떠나 동쪽에 도착해 먹이 패치를 소비했다. 서쪽 유출 1과 동쪽 유입 1이 일치했다. 수면 110 cm에 고정하면 이동·도착·지역 수지 변화가 없었다. 출발 직후 수면을 낮춘 통제에서는 같은 ID가 이동 예약을 해제했다. 수로를 다시 열자 재출발해 한 번만 도착했다.
- 개방 통제의 이동 중에 저장하고 별도 프로세스에서 복원했다. 생존 ID 149개와 신규 규칙 개체 15개의 권위 상태가 같았고 메기 ID 93의 동쪽 도착과 섭취가 이어졌다. [검증 스크립트](../../Tools/Editor/run_jyu_expanded_fauna_validation.ps1)의 `RegionalWater`를 실행하면 고정 개방·폐쇄, 이동 중 저장 복원, 폐쇄 후 재개방을 검사한다. `Saved/ExpandedFaunaImport/RegionalWater{Open,Restore,Closed,Closing}20000_status.json`.
- `LV_JYU_ExpandedWaterPassage`는 강우로 수위가 변하는 별도 소유 맵이다. 전용 서버와 로컬 IP 클라이언트 두 개를 띄웠다. 두 클라이언트 모두 메기 ID 93의 서쪽→동쪽 이동, 서쪽 유출 1·동쪽 유입 1, 표시 수면 110–142 cm를 받았다. 클라이언트의 권위 ID와 Native Step은 모두 0이었다. `Saved/ExpandedFaunaImport/RegionalWaterClient{A,B}_client.json`.
- 수로 구현 이후 UE 5.8 직접 UBT와 자동화 314건을 통과했다. 자동화에는 기존 지상 통로, R7e, 플레이어 전투 회귀가 포함된다. `Saved/ExpandedFaunaRegionalWaterAutomation/AutomationFinal/index.json`.

## 검독수리 둥지·급이·이소

검독수리는 절벽이나 큰 나무에서 번식한다. 관찰된 부화까지의 기간은 약 41–45일, 부화 후 이소까지는 약 6.5–12주이며 이소 뒤에도 수 주 동안 부모의 보살핌을 받는다. [USFWS 번식·이소 관찰](https://www.fws.gov/species/golden-eagle-aquila-chrysaetos) [USGS 절벽 둥지의 먹이·생산성 관찰](https://www.usgs.gov/publications/using-motion-activated-cameras-study-diet-and-productivity-cliff-nesting-golden-eagles)

- 복사 맵의 3.6 m 서쪽 플랫폼을 번식 자리로 작성했다. 4.4 m 플랫폼은 휴식 횃대로 쓴다. 부모의 실제 섭취·건강·거리, 지형 충돌·빈 공간을 검증한 뒤 기존 개체군 예약과 출생 경로를 사용한다. 둥지의 새끼는 부모가 들고 있는 에너지를 가까운 착지 상태에서 받아 먹으며, 설정된 기간 뒤 이륙·착지 실행기를 쓴다. 기본 맵의 포란 30초, 둥지 체류 90초는 압축된 게임 시간이다. 새끼는 성장 배율을 적용한 동일 리그를 사용한다. 알은 부화 예약으로 표현한다.
- 시드 20000 통제에서 높이 360 cm의 번식 자리만 지정했을 때 새끼 ID 99가 태어났다. 부모 급이, 둥지에 머무르는 구간, 동일 ID의 이륙·순항·하강·지면 착지를 확인했다. 같은 플랫폼과 먹이에서 번식 자리 ID만 빼면 새끼가 없었다. 시험은 시작 부모 위치와 유한한 먹이를 통제했고, 일반 맵의 자연 번식 빈도는 별도 측정 대상이다. `Saved/ExpandedFaunaImport/Nest{Save,Load,NoSite}20000_status.json`.
- 부모 한 마리를 지상에서 시작시킨 통제에서는 ID 92가 지상에서 이륙해 높이 360 cm의 번식 플랫폼에 실제로 착지했다. `Saved/ExpandedFaunaImport/NestParentReturn20000_status.json`.
- 포맷 10은 부화 전 예약에 둥지 ID를 저장한다. 부화 전 별도 프로세스 저장·복원에서 기존 개체 ID 98개와 신규 규칙 개체 상태 16건이 같았으며, 이어진 부화와 급이·이소도 재현됐다. 실행은 [검증 스크립트](../../Tools/Editor/run_jyu_expanded_fauna_validation.ps1)의 `Nest`를 사용한다.
- 최신 직접 UBT와 자동화 314건을 통과했다. 일반 성공 312건, 경고 동반 성공 2건, 실패·미실행 0건이다. R7e와 플레이어 전투 회귀를 포함한다. `Saved/ExpandedFaunaNestAutomation/AutomationFinal/index.json`.
- 저장한 복사 맵을 일반 조건으로 다시 열어 권위 개체 98개와 신규 8종 각각 2마리의 초기 배치를 확인했다. 155초 일반 실행에서 검독수리 부화는 관찰되지 않았다. `Saved/ExpandedFaunaImport/NestAuthoredSmoke20000.jsonl`.

### 회전·제동 표현

기존 60fps 시험에서 방향 입력이 약 180° 바뀌자 첫 프레임부터 몸이 12° 회전했다. 부드러운 회전을 사용하는 표현은 이제 지상·비행·수중의 회전 속도와 각가속도를 제한한다. 제동 시 Blend Space의 회전 가중치는 서서히 줄고, 고개는 방향 입력의 부호가 뒤집히는 구간에서 실제 몸의 회전을 따라간다. 수영 전용 개체의 꼬리 운동 속도는 지상 급회전 감속 규칙과 분리했다. 이동 좌표·권위 속도·학습 출력은 기존 실행 경로에서 공급한다. 순간이동과 표현 재사용 시에는 이전 개체의 회전 상태를 초기화한다.

`audit_jyu_fauna_motion.py`는 급반전의 첫 프레임 각도·최대 각속도·최종 방향 오차를 기록한다. 제동 장면은 방향을 돌리면서 감속한 뒤 정지하는 입력을 사용한다. [Unreal Engine Blend Space](https://dev.epicgames.com/documentation/en-us/unreal-engine/blend-spaces-in-unreal-engine)

60fps에서 신규 8종의 급반전 첫 프레임은 0.58–0.68°, 최대 프레임 회전은 6–9°였다. 30fps에서도 모든 종이 방향 입력에 수렴했다. 말의 60fps 제동에서 정지 임계값을 지날 때 회전 가중치는 0.4597 → 0.4023 → 0.3521로 줄었다. 검독수리의 비행 기울기와 급강하, 밍크의 입·출수, 전용 돼지의 제동·회전·사망 자세도 재검증했다. 돼지의 경사 사망 중 발 마커 −9.36cm는 그대로 재현됐다. `Saved/FaunaAudit/FaunaSmooth{Expanded60,Expanded30,Pig60}Metrics.json`.

까마귀 표현에는 이륙·착지 피치와 선회 뱅크를 추가했다. 60fps 선회 장면에서 약 4.72° 기울었고 이륙·착지는 설정 범위 ±22° 안에서 전환됐다. 기존 8종의 회전하며 제동하는 경로는 통과했다. 동일한 고정 경사에서 직선 제동 후 다시 달리는 경로는 기존 돼지의 발 마커가 한 샘플에서 −0.58cm로 내려가 허용치 −0.50cm를 초과했다. 두 경로를 모두 검증 도구에 남겼다. `Saved/FaunaAudit/FaunaCrowExisting{60,Straight60}Metrics.json`.

#### 급반전 방향과 정지 자세 연속성

±180° 부근에서 입력이 흔들려도 표시 몸체는 선택한 반전 방향을 유지한다. 속도에 출발과 정지 기준을 각각 두어 미세한 움직임이 몸 방향과 휴식 자세를 반복해서 바꾸는 문제를 줄였다. 정지할 때 몸의 선회 속도를 서서히 낮추고 비행·유영 피치와 비행 뱅크에 각가속도 제한을 적용했다. 좌·우 클립의 의미가 다른 Blend Space 회전 축은 기존처럼 선형으로 보간하고 각도 경계는 몸 방향에서 처리한다. 변경은 표현 Actor와 AnimInstance에서 처리한다. [Epic의 Blend Space 축과 Wrap Input 안내](https://dev.epicgames.com/documentation/en-us/unreal-engine/blend-spaces-in-unreal-engine)

120fps에서 180° 주변을 오가는 속도 방향을 넣었을 때 처음 0.2초의 몸 회전은 돼지·큰뿔양·산토끼·말·밍크·검독수리에서 8.55° → 43.20°, 물고기 세 종에서 1.80° → 28.80°였다. 저속 방향 흔들림은 4–6° → 0°, 정지 문턱을 오가는 입력에서 이동·휴식 자세 교체는 9회 → 0회였다. 비행·유영 피치 반전의 연속 프레임 회전량 차이는 최대 1.33° → 0.27–0.29°였다. 이 수치는 속도 입력에 대한 표현 스트레스 시험이며 실제 이동 경로는 별도 경사 회귀로 확인한다. `Saved/FaunaAudit/FaunaContinuity{BeforePig,BeforeExpanded,FinalPig120,FinalExpanded120}Metrics.json`.

30·60fps에서도 같은 입력을 반복했으며 반전 도중 역회전 프레임과 정지 자세 교체가 각각 0회였다. 기존 8종과 신규 8종의 평지→고정 경사 보행·급반전·제동·재가속을 30·60fps에서 통과했다. 까마귀·검독수리의 비행 뱅크·착지, 검독수리의 급강하, 밍크의 입수·유영·상륙도 각각 확인했다. 전용 돼지의 12° 오르막 휴식·기상·사망·안착에서 발 마커 최저값은 +0.25cm였고, 안착 이후 몸통 마커는 움직이지 않았다. `Saved/FaunaAudit/FaunaTurnSlope{Existing,Expanded}{30,60}Metrics.json`, `Saved/FaunaAudit/FaunaTurnPigUphillMetrics.json`.

### 이주 후 먹이 접근과 수로 확인

규칙 종의 이주 판단에서 사체는 통과 지점의 감지 범위, 도착 후 남은 수명, 지상 시야·후각 또는 수중 연결을 확인한다. 살아 있는 먹이는 실제 수영 상태, 체급, 감지 거리, 지상 시야 또는 수중 접근을 확인한다. 지역 안에 있더라도 너무 멀거나 도착 전에 사라지는 먹이는 목적지의 이득으로 계산하지 않는다. 육상 회귀에서는 먼 사체, 예상 도달 전에 사라지는 사체, 가림막 뒤의 사체가 출발을 만들지 않고 가림막을 걷으면 같은 개체가 통로를 통과하는 것을 확인했다.

### 수위에 따른 먹이와 다음 수변 조건

현재 수역은 작성된 수면·바닥 충돌·수심·수평 유속·고정 수온을 읽는다. 기존 산란 검사는 수심·수온·유속을 산란 예약과 부화 시점에 확인하고, 수로는 시야·연결·충돌과 지역 수용량을 확인한다. 이번 변경은 노출된 수중 먹이 재고가 강우만으로 계속 회복되던 부분을 보완했다. 소유 복사 맵 `/Game/JYU/Maps/LV_JYU_SeasonalWaterFood`에서 기존 먹이와 계절성 얕은 구간을 함께 볼 수 있다.

- 계절성 패치는 처음 노출되어 있으면 재고 0에서 시작한다. 잠긴 깊이에 따라 회복 속도가 커지고, 드러나면 재고가 줄어든다. 입수·유영은 기존 체급별 최소 수심을 사용한다. 수위 아래에 먹이 지점이 있는지 섭취와 이주 예상량에서도 확인한다. 상시 수중 패치와 육상 패치는 기존 회복 계약을 유지한다. 수면 확인에 필요한 작성 입력을 읽을 수 없으면 계절성 재고 갱신을 보류한다.
- 얕은 구간의 게임 초기값은 기준 높이 125cm, 최대 회복까지 추가 침수 12cm, 최대 회복 0.30재고/초, 노출 손실 0.24재고/초, 최대 재고 12다. 이 값은 압축된 맵의 조정값이다. 잉어의 온대 범람원 이용은 실제 관찰의 근거이며, 온천 개체군의 예외 사례도 보고됐다. 연구의 수심·계절 값을 모든 어종에 일괄 적용하지 않는다. [USGS 범람원 연결·치어 서식지 연구](https://pubs.usgs.gov/of/2022/1037/ofr20221037.pdf) · [잉어의 온천 산란 현장 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC11576824/)

시드 20000의 140초 통제에서 수위 순환은 재고 0 → 12 → 6.69, 낮은 수위 고정은 0이었다. 침수 중 저장한 재고 4.880896과 권위 개체 ID 106개가 별도 프로세스에서 복원됐고 이후 퇴수에 따른 감소가 이어졌다. 먹이 접근 통제에서는 잉어 ID 95가 침수된 같은 패치에서 22번, 로그 반올림 합계 15.17에너지를 실제 섭취했다. 통제용 허기와 시작 위치는 맵에 저장하지 않았다. 재현 모드는 `SeasonalWaterFood`, `SeasonalWaterPersistence`이며, 직접 UE 5.8 빌드와 자동화 316건을 통과했다. 자동화는 일반 성공 314건, 경고 동반 성공 2건, 실패·미실행 0건이다. `Saved/ExpandedFaunaImport/SeasonalWaterFood{Cycle,Dry}20000_status.json`, `Saved/ExpandedFaunaImport/SeasonalWater{Save,Restore}20000_status.json`, `Saved/Logs/SeasonalWaterFeedingFinal20000.log`, `Saved/Automation/SeasonalWater/index.json`.

### 물가 식생·바닥 구조와 물속 은폐

소유 맵 `/Game/JYU/Maps/LV_JYU_RiparianHabitat`에 물가 식생과 나무, 돌, 충돌이 있는 진흙 경사, 반투명 수면을 추가했다. 기존 풀 메시 일부는 수초 외형으로 사용했다. 수초 만의 실제 유속을 약 1.23cm/s, 열린 물길은 5cm/s로 작성했다. 낙엽층·수초 만·돌 가장자리는 각자 다른 소비자와 재고를 가진 유한 먹이 패치다. 수초 만의 유속과 수온은 작성값이며, 메시가 흐름을 계산하는 유체 모형은 없다. 계절성 얕은 먹이 자리, 기존 산란장, 밍크의 상륙 지점도 복사 맵에 함께 남아 있다. [USDA 하천 복원 현장 안내](https://www.nrcs.usda.gov/sites/default/files/2024-10/Stream%20Restoration%20Field%20Guide_july%202012.pdf) · [USGS 유목 설치 현장 실험](https://pubs.usgs.gov/publication/70269959)

수중 은폐는 수심·수초 높이·밀도를 사용한다. 수초 상단에 가까워지면 감지 거리 감소가 점차 줄며, 상단이나 수면 밖에서는 수초의 수중 은폐가 적용되지 않는다. 식생의 효과는 시각 후보를 찾는 단계에 적용하고 포획 접촉은 기존 거리·체급·물리적 가림 검사를 사용한다. 수초의 구조에 따라 포식자별 효과가 달라질 수 있다는 실험을 참고했다. [수초 구조와 포획 실험](https://pubmed.ncbi.nlm.nih.gov/15300485/) · [수초 구조·부착생물·무척추동물 현장 실험](https://pubmed.ncbi.nlm.nih.gov/16932971/)

같은 시드와 시작 상태의 두 실행에서 밍크 ID 89는 개방 상태에서 물고기 ID 96을, 밀생 식생 상태에서 ID 97을 선택했다. 로그에 ID 96의 식생 시야 차단과 ID 97의 포획·실제 섭취가 남았다. 복사 맵의 별도 실행에서는 밍크가 물가 낙엽층의 재고를 소비했다. 식생 개체의 성장·계절 변화, 포식자를 감지한 물고기가 은신처를 찾아 들어가는 행동, 유목 주변의 유속·퇴적 변화는 후속 범위다.

최종 맵에서 수변 메시 48개, 세 패치의 재고 9·9·7과 유속 두 구역을 확인했다. 통제용 위치와 허기를 부여한 별도 실행에서는 잉어 ID 94가 수초 만에서, 아리아케 메기류 ID 93이 돌 가장자리에서 실제로 먹었다. 조정한 시작값은 맵에 저장하지 않았다. 반투명 수면 너머 수초·바닥·물고기가 보이는 렌더를 확인했다. 바닥과 물가의 기초 지형은 여전히 테스트용으로 단순하다. UE 5.8 직접 UBT 성공과 전체 자동화 317건(일반 성공 315, 경고 동반 성공 2, 실패 0)을 확인했다. 재현 모드는 `RiparianHabitat`과 `WaterVegetation`이며, 최종 캡처는 `Saved/ExpandedFaunaImport/RiparianHabitatFinal.png`다.

### 식생 재생·건조·섭취 표현

검증된 언덕 사면·관목 가장자리·초지·범람원·물가 좌표를 사용해 정적 외형을 `/Game/JYU/Forage/BP_JYU_ForagePatchVisual` 15개로 교체했다. 군락별로 패치 ID와 식물 인스턴스를 편집하고 `Rebuild Forage Preview`로 확인할 수 있다. 풀·초본은 뿌리 위치를 유지하며 식생 유형별 잔존 높이까지 낮아진다. 관목은 먹을 수 있는 잎만 단계적으로 줄어들며 별도 메시 레이어의 가지와 줄기는 유지된다. 뜯긴 뒤 남은 잎과 저장 자원이 재생에 영향을 주고, 건조 스트레스와 물가 식생의 회복 여건이 다르다는 자료를 반영했다. [USDA NRCS 목초 재생](https://www.nrcs.usda.gov/plantmaterials/idpmspu10096.pdf) · [USDA NRCS 방목지 수문과 물가](https://www.nrcs.usda.gov/sites/default/files/2022-09/Chapter%207%20-%20Grazing%20Lands%20Hydrology.pdf)

기온·강우는 기존 회복 곡선을 쓰고 강우와 상대습도를 합친 지표가 생장을 늦추거나 남은 생체량을 줄인다. 습윤 초지 풀·초본은 건조에 더 민감하고 관목은 비교적 느리게 반응하도록 조정했다. 이 맵에는 기존 환경 어댑터로 160초의 테스트 강우 주기를 적용했다. 수치와 시간은 게임값이다. 서버의 기존 먹이 장부에서 기후 갱신과 섭취를 완료한 뒤 시각 액터에 1바이트 재고 비율을 보낸다. 체크포인트의 재고를 복원할 때도 표현을 다시 발행한다. 건조 지표는 구역 단위이며 토양 수분·지하수·답압·침수에 따른 식생 천이는 별도 과정이다. 기존 수중 경관용 수초·개구리밥은 각각 수중 구조·수면 높이 표현을 맡으며 잉어·메기의 무척추동물 섭취를 잎 손실로 처리하지 않는다.

시드 20000의 건조·강우 비교에서 테스트 군락에 실제 섭취가 없음을 확인했다. 건조 약 36초에 물가 습윤 풀 재고가 13→6.75, 물가 초본이 9→3.80, 언덕 관목이 10→7.13으로 감소했다. 강우 전환 뒤 90초에 세 재고가 모두 초기치로 돌아왔다. 외형 높이 또는 평균 잎 스케일은 각각 66%, 49%, 71%까지 감소한 뒤 회복했다. 테스트 강우 주기를 켠 일반 140초 실행에서는 큰뿔양 24회, 산토끼 32회, 말 18회, 물소 50회의 군락 섭취를 기록했다. 같은 시간대의 군락 재고와 인스턴스 스케일을 15개 전체에서 대조했으며 관목의 가지 스케일은 일정했다. 재현은 `-Mode ForageWeather`와 `-Mode HerbivoreForage`다. UE 5.8 직접 UBT와 전체 자동화 318건을 다시 통과했다. 관목의 가림 재질에 인스턴스 메시 사용 플래그를 저장하고 D3D11 캡처 `Saved/ExpandedFaunaImport/ForageGrowthVisualFinal.png`에서 잎·줄기와 배치 상태를 확인했다.

`-Mode ForagePersistence`에서 먹이가 줄어든 상태를 저장하고 새 PIE 세션에서 복원했다. 복원 직후 15개 군락의 재고와 시각 비율이 저장값과 일치했다.

`-Mode ForageNetwork`의 실시간 전용 서버 PIE와 클라이언트 한 개에서 건조·강우 전환을 확인했다. 건조 25.7초에 세 군락의 클라이언트 재고 비율은 각각 0.63, 0.55, 0.79였고, 56.1초에 모두 1.0으로 돌아왔다. 클라이언트가 받은 비율로 인스턴스 외형이 갱신됐고 클라이언트 권위 개체 수는 0이었다. 고정 프레임 벤치마크에서는 클라이언트 식생 비율이 초기값에 머물렀으며 실시간 PIE에서 검증을 마쳤다.

### 휴식·사망의 지면 지지와 보행 IK 회귀

돼지 휴식 전환의 발 마커는 수정 전 평지에서 −10.40cm, 12° 오르막에서 −24.41cm, 12° 가로 경사에서 −11.47cm까지 내려갔다. 지상에서 눕거나 죽는 동안 표시 메시를 실제 정적 지면에 기울이고, 최종 평가된 발 마커가 그 지지면을 통과할 때만 높이를 보정한다. 기상 애니메이션이 섞이는 동안 지면 기울기를 유지한 뒤 보행 자세로 복귀한다. 공중·유영에서 지지면을 적용하지 않으며 수중 사체 위치는 기존 이동과 부유 규칙을 사용한다. 표시 메시 보정은 권위 위치, 사체 장부, 피격 범위와 보행 IK 노드의 계산에 별도 쓰기를 추가하지 않는다. [표시 액터 구현](../../Source/AdaptiveEcosystem/Creature/Representation/EcoCreatureRepresentationActor.cpp) · [Epic 스켈레탈 컨트롤](https://dev.epicgames.com/documentation/en-us/unreal-engine/skeletal-controls)

| 돼지 시험 | 휴식 최소 발 마커 | 기상 최소 | 사망·안착 최소 | 안착 후 몸통 마커 높이 변화 |
| --- | ---: | ---: | ---: | ---: |
| 평지 | +0.25cm | +0.25cm | +0.25cm | 0.00cm |
| 12° 오르막 | +0.85cm | +0.25cm | +0.25cm | 0.00cm |
| 12° 가로 경사 | +0.10cm | +0.25cm | +0.25cm | 0.00cm |

오르막에서 클립 시작 0.6초 뒤에 사체 안착 상태를 보내도 보이던 사망 클립이 1.75초 더 재생된 뒤 마지막 자세로 고정됐다. 안착한 몸통 마커의 높이는 평지 18.50cm, 오르막 18.91cm였고 렌더에서 몸체가 경사에 놓인 상태를 확인했다. 몸통 마커 높이는 뼈 기준이며 메시 표면과 지면의 물리 간격으로 해석하지 않는다. `Saved/FaunaAudit/PigSupport{Before,Final}{Flat,Uphill,CrossSlope}Metrics.json`.

가로 경사의 별도 회귀에서 기존 8종과 신규 지상 자세 5종의 사체가 안착 뒤 움직이지 않았다. 발 마커가 있는 11종의 휴식·기상·사망·안착 전체 최저값은 +0.10cm였다. 기존 및 신규 8종의 경사 보행·선회·급반전·제동·질주 구간은 각각 108프레임씩 이전과 비교했고, 기록한 자세·방향·발 마커 값이 모두 일치했다. 표범 급반전에서 −1.07cm의 기존 발 마커 관통도 같은 프레임에 재현됐다. `Saved/FaunaAudit/FaunaSupport{Existing,Expanded}{Grounded,Walk}Metrics.json`.

재현은 [모션 검증 스크립트](../../Tools/Editor/audit_jyu_fauna_motion.py)의 `-FaunaRestSupport=Flat`, `Uphill`, `CrossSlope`를 사용한다. 돼지 전용은 `-FaunaMotionPig -FaunaSupportVerify`, 조기 안착 입력은 돼지 오르막 조건에 `-FaunaSupportEarlySettle`을 추가한다. 보행 회귀는 기존과 신규 소유 맵에서 `-FaunaMotionPhysicalSlope`로 별도 실행한다. 발 마커가 없는 밍크·검독수리는 지상 자세의 몸통 기준과 사체 유지로 확인하고, 물고기 세 종은 기존 수영·사망 표현 시험에 포함한다.

### 재질·발소리·생태 재점검

- 기본 표현 17개, 재질 슬롯 28개에 텍스처 참조가 있다. 기존·신규 D3D11 검증 로그에서 재질 컴파일 또는 기본 재질 대체 오류가 없었다. 팀 통합 레벨의 전체 조명과 성장별 교체 메시까지 대조한 실행은 아니다. `Saved/FaunaAudit/BoundMaterials.json`.
- 기존 8종과 큰뿔양·산토끼·말의 발 소켓 Notify를 실제로 재생했다. 신규 보행종은 잔디와 돌에서 각각 맞는 재질 소리가 났다. 밍크·검독수리 지상 음향과 플레이어는 거리 기준이다. 검독수리·까마귀 비행 중 발소리는 없었고 플레이어는 실제 재생 로그에서 일곱 표면과 젖은 잔디를 확인했다. `Saved/FaunaFootsteps/GroundSupportFootsteps{Existing,Expanded}/PlaybackAudit.json`.
- 시드 20000, 180초 단일 지역 실행에서 16종·초기 98개체, 종료 108개체를 기록했다. 첫 집계 이후 11종에서 출생이 추가됐으며 신규 8종 모두에서 개체별 체급 차이를 확인했다. 다른 세션의 통제 부화 결과와 합쳐 16종 출생·부화 경로를 확인한 이전 기록은 그대로 유효하다. 다지역 통제에서 잉어 95가 서쪽에서 동쪽으로 한 번 도착했고 같은 개체가 수초 먹이 패치에서 섭취했다. `Saved/ExpandedFaunaImport/GroundSupport{Ecology180,CarpRoute}_status.json`.
- 지상·수중 통과는 지역 경로를 작성한 맵에서 확인했다. 늑대, 비행 지역 이주, 밍크 수륙 혼합 이주의 범위는 위 생명주기 표를 따른다. 사슴만 학습 모델 R7e를 쓰고 다른 종은 규칙으로 실행했다. 기아의 두뇌 효과를 분리할 동일 종·환경의 정책 대조 시험은 이번 점검에 포함하지 않았다.

### 이주 후 정착지에서의 자연 출생

규칙 종은 현재 지역의 실제 번식 가능한 거주 개체를 종별로 모은다. 초기 스폰 목록이 비어 있어도 도착을 마친 두 개체가 기존 나이·건강·영양·혈연·거리 검사를 통과하고 종별 산란장이나 둥지 조건을 만족하면 번식할 수 있다. 실제 출생은 기존 개체군 상한, 먹이 예산, 지면·수심 검사를 사용한다. 처음부터 배치한 종의 처리 순서를 유지하고 새로 정착한 종은 그 뒤에 종 ID 순으로 처리한다. [번식 후보 수집과 권위 출생](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFauna.cpp)

두 지역의 지상 경로를 실제로 건넌 쥐 2·3이 쥐 초기 배치가 없는 목적지에 도착했다. 도착 후 번식 자격을 갖춘 조건에서 자연 출생한 4의 부모·세대와 목적지 권위 개체수 3, 출발지 개체수 1을 확인했다. 이 시험은 부모의 영양 상태를 통제했다. 장기 자연 정착이나 다른 이동 방식의 새 지원을 확인하는 시험은 아니다. `Saved/Logs/FaunaSettlersTarget.log`.

UE 5.8 직접 빌드와 자동화 320건을 완료했다. 성공 318건, 경고 동반 성공 2건, 실패 0건이다. `LV_JYU_ExpandedFauna`에서 시드 20000의 16종을 180초 실행했다. 30·60fps 모두 초기 98개체, 자연 출생 19건(11종)이었고 종료 개체수는 각각 108·106이었다. 두 실행의 모든 발행 개체군 행에서 `개체수 = 누적 스폰·출생 - 사망 + 전입 - 전출`이 성립했다. 30fps의 종별 개체군 표본 36개는 수정 전 `GroundSupportEcology180`과 전부 일치했다. 30·60fps 사이에는 사슴·쥐·산토끼의 출생 또는 사망이 달랐다. `Saved/Automation/FaunaSettlers/index.json`, `Saved/ExpandedFaunaImport/FaunaSettlersEcology{30,60}.jsonl`.

두 지역의 잉어 수로 통제는 시드 20000에서 각각 145초 실행했다. 수로 개방 시 잉어 95가 한 번 건너고 도착지의 수초 먹이 패치를 실제로 이용했다. 출발지 전출과 도착지 전입은 각각 1건이었다. 차단 시 도착·전입·전출이 모두 0건이었다. `Saved/ExpandedFaunaImport/FaunaSettlersCarp{Open,Closed}_status.json`과 대응하는 권위 로그.

UE 5.8 직접 UBT와 자동화 319건을 통과했다. 일반 성공 317건, 경고 동반 성공 2건, 실패·미실행 0건이다. `Saved/Automation/FaunaGroundSupport/index.json`. 경계가 끊긴 지형과 움직이는 플랫폼은 이번에 렌더한 연속 경사와 다른 조건이다.
