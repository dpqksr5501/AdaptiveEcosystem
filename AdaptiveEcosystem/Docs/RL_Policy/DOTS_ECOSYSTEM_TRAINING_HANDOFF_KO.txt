AdaptiveEcosystem 환경 개발 및 Dots 학습 인계
2026-11-14 갱신

이 문서는 Dots에 전달하는 실행 전 참고 자료다. 현재 요청은 준비 검토다.
설치, 스모크, 본 학습, 결과 업로드는 별도의 실행 지시에서 범위를 정한다.

1. 목표와 역할

최종 목표는 언리얼 섬의 16종이 먹이, 지형, 물길, 기후, 다른 개체의 행동에
따라 상황에 맞게 움직이는 생태계다. 환경이 바뀌면 행동 기회가 달라지고,
섭취·포식·이동·출생·사망 결과가 다시 자원과 개체군에 영향을 준다.

로컬 팀은 언리얼의 환경과 권위 실행기를 개발하고, RL 담당과 함께 Python
대응 세계와 관측·행동 계약을 검증한다. Dots는 지정된 Git 커밋에서 Python
학습을 실행하고 모델 팩과 결과를 반환한다. 반환 모델은 로컬에서 같은 장면의
규칙 실행 및 기존 모델과 대조한 뒤 언리얼 적용 범위를 결정한다.

2. 지금 준비할 수 있는 범위

현재 R9는 사슴·늑대·멧돼지·물소·표범·여우 6종을 이어 학습한다.
출발 팩은 herbivore_rl/results/v3/r9/packs/fauna_r2다. 설정 후보는
herbivore_rl/configs/v3_r9_fauna_motion.yaml이다. 현재 정책 계약은
115개 관측과 지상 행동 19개다. 기존 팩은 6종의 학습 기준선으로 쓴다.
실행 커밋, 설정, 팩, 줄 이름, 학습 한도, 중단 기준, 보관 위치는 인계 시 확정한다.

현재 확인한 읽기 기준은 로컬 origin/Branch_Sinhyeok의
062de0b741d6ae27ede2b454be18eb72ad6226d6이다. 이 커밋의 herbivore_rl
트리는 로컬 작업 커밋과 같았다. fauna_r2의 manifest.json SHA-256은
016c748a6b221c78d0ea1f4012c107b88d64d3ee8d5ff857ec96009ef1fc27d6이다.
매니페스트가 지목한 22개 파일과 6종의 재개 ZIP·상대 정책 NPZ를 확인했다.
6종 NPZ는 공통 I/O 해시 0x0fa76480fe9465e0이며 각 종의 원래 몸 해시는
매니페스트와 일치했다. 이 값은 해당 커밋과 출발 팩의 확인용이다.

M1 설정에서는 동일 종의 ZIP을 PPO 재개에 사용하고, 다른 몸 해시를
가진 상대 정책 NPZ는 기존 chain_r9.py가 출처를 기록하며 rebody한다.
이때 R9 입출력 순서를 변경하거나 몸 해시 검사를 끄지 않는다.
Dots에서는 지정된 커밋을 고정한 뒤 실제 설치·check·스모크 단계에서
종별 몸 해시, ZIP 로드, 종별 결정 처리량과 출력 팩을 다시 확인한다.
로컬 파일 점검은 이번 Dots에서 학습이 실행됐다는 증거가 아니다.

11월 14일 로컬에서 위 커밋과 현재 작업 기준의 herbivore_rl 트리
3f744ed605ad0cea455dd9214426203e53181939가 일치함을 다시 확인했다.
공식 pack_r9.py verify로 매니페스트와 여섯 종의 팩 계약을 통과했다.
Fauna Motion 설정과 비교한 same_body는 6종 모두 false다. 출발 팩은
Fauna 설정에서 작성됐으므로 M1은 위에 적은 기존 rebody 경로를 사용한다.
Fauna Motion 설정 파일의 SHA-256은
30dd58240aa565c6112ee7688dd9266db7e700040259a9a744aecbd1698cc7d5다.

최종 섬 검증 후 Windows Python 3.12.13에서 chain_r9.py check가 통과했다.
--shards 1의 dry-run은 6종 각각 자신의 원본 ZIP을 --init에 전달했다.
같은 M1 R9VecEnv를 종별로 하나씩 만들고 원본 ZIP을 PPO.load로 열어
reset한 뒤 115개 관측에서 Discrete(19) 정책 행동을 출력했다. 이 확인은
학습 없이 수행했다. 클라우드의 속도·메모리·장애 복구는 Dots에서 측정한다.
공식 사전 테스트 세 파일은 42건을 통과했고, 별도 데모 시작 모델을
요구하는 시험 1건은 건너뛰었다. Windows 격리 셸에서는 named pipe
연결이 시간 초과됐고 일반 실행 환경에서 같은 다중 프로세스 시험과
전체 사전 테스트를 다시 통과했다.

추가 대상은 쥐·큰뿔양·산토끼 계열·말, 까마귀·검독수리, 밍크,
아리아케 메기류·잉어·가상 담수 소형어류다. 각각 지상, 비행, 수륙 전환,
유영의 실행 조건을 Python과 언리얼에서 확인한 뒤 별도 인계한다.
종 동정이 불확실한 에셋은 비교에 사용한 생태 유형과 가정을 기록한다.

신규 10종은 필요한 이동·섭식 조건을 공유하는 순서로 준비한다.
각 종에서 표의 입력→요청→실행 결과를 같은 사건 순서로 비교한다.

종 | 먼저 확인할 장면 | Python 환경에 연결할 계약
쥐 | 위협을 피해 한 입구로 진입하고 다른 입구로 이탈 | 몸 폭·가림·위협 기억과 양방향 지면 이동
큰뿔양 | 경사와 수심을 달리한 같은 먹이터 접근 | 체폭·단차·도섭에 따른 유효 지상 경로
산토끼 | 중간 먹이터 고갈 후 경유와 전환 | 실제 도착 에너지와 피난·먹이 접근의 경로 비용
말 | 마른 둑과 침수된 뿌리의 공유 재고 | 왕복 이동과 도섭, 같은 재고의 원자적 차감
아리아케 메기류 | 낮밤과 가림에 따른 군락·사체 전환 | 수류·수심을 반영한 유영 감각, 정지 섭취와 지급
잉어 | 퇴수 중 치어가 잠긴 선반에서 섭취 | 몸 크기별 수심, 산란 예약과 부화, 실제 접근·지급
가상 담수 소형어류 | 공유 재고의 한 점이 드러난 뒤 재개방 | 유영 접근 및 대체 경로, 같은 군락의 한 재고
밍크 | 수위 상승 후 실제 입수·대체 출구·상륙 | 지상·유영 전환 상태와 거리·수류·체력 비용
까마귀 | 지상 동물과 같은 사체에 도착해 경쟁 | 이륙·비행·착지 상태와 권위 사체 섭취
검독수리 | 가림과 도주로 달라지는 급강하·포획 | 3D 감지·급강하·접촉·포기·착지 계약

호환 검사는 종·몸/세계 버전과 단위, 관측 순서·정규화·가용 마스크,
행동 요청 코드, 실제 실행·지급, 초기화와 종료 사유를 포함한다.
부분 장면이 재생된 종도 정책에서 쓸 관측과 행동, 재시작 가능한 학습
세계가 연결되고 Unreal 대응 결과를 비교한 뒤 본 학습 대상으로 지정한다.

3. 로컬 환경과 시스템의 개선 우선순위

- 먹이와 접근성. Native 식생 격자, 육상 군락, 수중 먹이, 사체의 재고와
  소비 경로를 확인한다. 같은 장소의 재고가 서로 다른 자원인지 작성할 때
  명시한다. 총재고와 종·성장 단계별 도달 가능 재고를 함께 측정한다.
  먹이량을 고정하고 배치나 통로 하나를 바꿔 첫 섭취 시간, 접근 실패,
  지역 고갈, 남은 재고를 비교한다.
  설원 대응 장면에서는 지역에 충분한 재고가 있어도 현재 셀은 비고,
  남은 먹이가 감지 범위 밖이거나 직선 지면이 막힐 수 있다. 현재 셀 재고,
  감각을 통과한 후보, 실제 도달, 식생 차감, 순 에너지 변화, 섭식 표시를
  각각 대조한다. 같은 재고에서 위치를 옮긴 결과는 시드별로 달랐다.
  기존 R7e와 다른 R9 지상 관측에 전체 지도 재고나 경로 정답을 추가하지
  않는다. 사례와 수치는 FAUNA_HABITAT_CAPACITY_20261113.md의 과섭식 절에 있다.
  Examples/island_native_food_boundary_actual_20261114.json은 네 지역에서
  이동 경계와 겹치지 않는 셀의 초기 식생, 설원 경계 확장 전후의 통과,
  창시 개체가 실제로 경계를 넘고 먹은 결과를 기록한 비교 자료다.
  현재 R9 M1의 평면 월드 외곽 제한과 독립적인 섬의 지역 경계를 구분한다.
  그 발췌는 설원 확장 전의 기준과 일시 확장 실험이다. 이후 소유 섬에는
  설원만 120×120m로 저장했다. 기존 초기 Native 식생 총량은 같고
  설원 사슴·늑대의 시작 위치가 달라지므로 새 모델 비교에는 확장본의
  새 시작 상태를 기준으로 고정한다. 후속 저장본에는 초지의 남쪽
  경계를 유지한 120×102m 확장도 포함된다. 초지 사슴·늑대의 시작점이
  달라졌으므로 정책 간 비교는 설원과 초지를 모두 반영한 동일 맵에서 한다.
- 식생과 먹이 품질. 새순·성숙한 줄기, 계절성 열매·씨앗, 수변 곤충과
  저서 먹이부터 비교한다. 먹을 수 있는 양·얻는 영양·섭취 시간·은폐·그늘은
  별도 값으로 다룬다. 렌더링의 식생 밀도와 실제 먹이 공급을 대조한다.
- 섭식 피드백. 화면에서 먹는 시간, 섭식 간격, 재고 차감량, 실제 에너지와
  저에너지 체류를 종·성장 단계별로 기록한다. 격자 식생의 차감 상한을
  Python에 연결할 때는 RL 담당과 같은 초기 재고·영양 배율·에너지 여유를
  사용해 섭취 후 재고와 지급값을 대조한다. 기존 팩의 기준 실행은 유지한다.
- 기후와 수문. 현재 날씨의 감각 효과와 토양 수분·식생·수위의 지연 효과를
  함께 기록한다. 같은 누적 강수의 잦은 비와 집중호우, 같은 최고 수위의
  빠른 퇴수와 느린 퇴수를 비교한다. 저수위 피난처, 산란장 침수 연속성,
  치어 고립, 밍크의 대체 상륙점을 확인한다.
  Examples/island_forage_soil_actual_20261114.json에 토양 입력만 켜고 끈
  초지의 두 시드·두 강우 패턴을 담았다. 비가 그친 뒤 군락 중심 셀의 수분,
  실제 먹이 재고와 권위 로그의 지급량을 따로 읽는다. 이 부분 표본은 학습
  입력이나 재생 가능한 세계가 아니다. Python에서는 위치별 토양 입력,
  갱신 시점과 지급·잔량을 작은 대응 장면에서 먼저 확인한다.
  Examples/island_forage_stock_authority_20261114.json에는 두 시드의
  실제 권위 거래를 순서대로 담았다. Examples/README.md의 재생 명령으로
  비가 그친 뒤 고갈·미지급·회복 지급을 Python 표준 라이브러리로 검증한다.
  R9의 개체가 같은 먹이터를 선택하는지 여부는 별도 대조 대상이다.
  Examples/island_ground_food_choices_20261114.json으로 말의 기존 후보와
  유효한 요청이 실제 선택에 미친 영향을 대조한다. 육상 지급은 별도
  권위 표본에서 재생하며 거리·시야·재고 중 실제로 기록된 사유를 사용한다.
  Examples/island_forage_guild_comparison_20261114.json은 먹이 예산을
  고정하고 풀·관목 분류만 바꾼 두 시드의 지상 대조다. 처음 고른 먹이터와
  실제로 도착해 지급받은 먹이터를 따로 확인한다.
  Examples/island_forage_meal_cap_20261114.json은 한 번 지급 한도만 낮춘
  사례다. 같은 에너지를 여러 번 나누어 받은 경우가 있으므로 섭식 빈도와
  총 지급량을 함께 비교한다.
  Examples/island_flooded_ground_forage_20261114.json은 현재 수위에서
  뿌리 좌표 도달과 실제 먹이 지급이 갈리는 경우를 대조한다. 두 접근점은
  한 군락 재고를 공유하고, 종별 도하 한도와 지면 접근을 검증한다.
  Examples/island_water_access_geometry_20261114.json과 Examples/README.md의
  명령으로 잉어 치어의 수직 통과 여유와 범람 시 밍크 상륙점 높이를 확인한다.
  두 시드의 실제 섭취와 상륙 사건을 함께 담았다. 연속 경로·충돌·수류를
  계산하는 Python 세계와 신규 종의 감각 입력은 후속 대응 항목이다.
  Examples/island_water_food_connectivity_20261114.json은 같은 재생기로
  메기·잉어·소형어류의 두 체급을 저수위·고수위·퇴수 격자에서 대조한다.
  연결된 수심, 낮·밤 명목 탐색 거리, 실제 도달·섭취를 별개로 기록한다.
  Python에서 Drift→SlowShelf 실측 격자를 목적지 지정으로 이동했다.
  두 시드와 세 수위에서 각각 71칸을 통과했고, 시작 지점에서 낮·밤
  감지와 시험 먹이 지급은 없었다. 시험 먹이는 도착 후에만 지급했다.
  물길 이동의 시험 명령은 목적지를 알고 있으며 학습 관측에 넘기지 않는다.
  별도의 제어 탐색기는 인접 수심과 자기 방문 기억으로 이동한다. 먹이는
  감지될 때 위치의 상대 방향만 받는다. 두 시드의 각 수위에서 낮 159번째,
  밤 160번째 이동에서 처음 감지했고 161번째 이동 뒤 시험 먹이를 지급했다.
  이 격자 탐색은 신규 종의 전체 학습 정책이나 연속 유영 검증과 별개다.
  Python 먹이 감지에는 반경 안의 연결된 수주만 사용한다. 먼 우회로를
  여는 대조에서는 관측이 같았고, 감지 범위 안의 수로를 열자 방향이
  나타났다. Unreal의 연속 시야와 수중 감지는 추가 대응이 필요하다.

  추정하므로 장거리 우회나 전체 수중 길찾기는 별도 계약이 필요하다.
- 경쟁과 개체차. 늑대와 표범의 드문 충돌, 사체를 둘러싼 접근과 이탈을
  기존 모델에서 기록한다. 체급·나이·부상·새끼 보호·주변 동족·지형이
  행동의 비용과 결과에 어떻게 영향을 주는지 비교한다. 공격 장면만으로
  허기나 경쟁을 확정할 수 없으며 공격 빈도를 보상 목표로 삼지 않는다.
  기존 평지 학습 두뇌의 R1 자연 장면은 기본·물소 중심 조건에서
  늑대→표범 물림 사망이 각각 1건이었다. R2 학습 두뇌의 두 조건은
  0건이었다. 같은 R2 보고서의 규칙 두뇌는 각각 2·6건이었다.
  각 조건은 10세계×1,350결정이며, 개별 사건의 당시 허기·부상·추격
  경로는 출발 팩의 요약 보고서에 없다. S2(1대1)와 자연 장면을 따로
  평가한다. 최신 JYU
  섬의 Native 늑대와 규칙 표범은 해당 R9 정책으로 구동되지 않는다.
  섬의 위치·소리 표본은 현지 환경 근거로 사용하고, 새 계약은 두 종의
  감지·요청·허용·접촉·피해·사체 접근과 이탈을 대조할 수 있게 한다.
  로컬 표범의 육상 시험에서는 건강한 성체 쥐의 기대 섭취 1.82가
  기본 위험 비용 2보다 작아 후보에 들어와도 추적을 시작하지 않았다.
  두 시드의 후보 95건을 Examples/island_leopard_hunt_value_20261114.json
  에 남겼다. 같은 샘플의 점수 계산에서 표범 에너지를 절반으로 줄여도
  방어 저항 0인 쥐의 위험은 그대로였다. 쥐 체력 50%에서는 스태미나가
  충분할 때만 양의 점수가 나왔다. Unreal의 별도 평지 자동화에서는
  표범 상태와 95cm 거리를 고정했다. 쥐 체력 100%에서는 선택하지
  않았고 50%에서는 실제 선택·공격 준비·접촉·포식 사망을 확인했다.
  섬의 자연 발생 조우 빈도와 사체 지급은 별도 검증으로 다룬다.
  저장 섬 60분에서는 까마귀·멧돼지·늑대가 같은 물소 사체에서
  먹은 사례가 두 시드에 있다. island_guard_population_regression_20261114.json의
  세 종 지급 순서와 남은 재고를 비교한다. Native 늑대의 시각이 없는
  지급은 순서만 사용하고 동시 접촉이나 직접 경쟁의 근거로 쓰지 않는다.
- 공간과 시간. 스폰·출생 위치가 먹이와 피난처 선택을 미리 결정하는지,
  특정 통로에만 몰리는지, 지역별 고갈과 회복이 동시에 일어나는지 본다.
  무개입, 플레이어 통과, 사냥을 비교해 교란과 사체 공급 효과를 구분한다.
  Examples/island_player_passage_20261114.json은 정지·은밀 이동·달리기
  두 시드의 발소리, 산토끼 회피, 경유점, 도착, 첫 지급을 담고 있다.
  달리기의 첫 경유점은 5·9초 늦었지만 첫 지급은 +5·-5초였다.
  check_player_passage.py로 사건 순서를 검사한다. 단계별 결과를 비교하고
  발소리가 첫 섭취를 항상 늦추는 규칙은 추가하지 않는다.
  같은 자료의 jackrabbit_hearing_profile은 저장 섬의 실제 에셋에서 읽었다.
  Python --ground 대조는 17m 범위, 감지 문턱 0.12, 가림 배율 0.44를
  사용한다. 7m는 제어 거리이며 실제 경로의 음원–개체 위치 대응은 별도다.
  지상 통로의 대응 시험은 먹이 없는 경유 구역과 먹이 있는 도착 구역을
  분리한다. 기존 먹이 예산으로 출발·입장·최종 도착·섭취와 예약 해제를
  기록한다. Unreal의 임시 두 구간 시험은 진단 근거다. Python 구현과 정책
  관측 반영은 RL 담당이 별도 계약으로 검증한다.
  이어 저장 섬의 일반 서식지에서 같은 초본 9를 강변과 중간 먹이터에
  4.5씩 배치했다. 기본 배치의 산토끼가 두 시드에서 중간 먹이터에
  도착해 섭취했다. Examples/island_transition_habitat_actual_20261113.json
  에 두 시드의 도착·식사·재고·날씨 표본이 있다. Unreal 도착은 경계
  통과 이력, 섭식은 실제 지급 에너지로 비교한다. 현재 R9의 격자
  풀·뿌리·사체와 제자리 EAT에 이 결과를 바로 대입하지 않는다.
  check_island_ground_passage.py는 두 시드의 실측 출발·경계·먹이터를
  연결하고 경계를 닫으면 지급 0, 열면 도착 뒤 첫 지급 2.8을 확인한다.
  이동은 미리 주어진 경로의 일정 보행이다. Unreal의 출발 판단·충돌과
  식생 회복을 함께 검증하려면 이동 및 재고 처리부터 대조한다.
  같은 명령의 --patch-inputs는 저장 섬의 초본 회복 계수를 사용한다.
  같은 초기 재고·거리·강우에서 군락 수분만 0.10에서 0.55로 바꾸면,
  도착 시각은 같고 첫 지급은 0에서 2.8로 변했다. 토양 수분은 이 시험의
  고정 입력이므로 토양 입력의 시간적 변화는 별도로 대조한다.
  원시 좌표나 전역 재고는 진단에 쓰고 정책 입력은 기존 계약을 따른다.

4. Dots에 인계할 데이터와 평가

- 저장소 커밋, 설정과 출발 팩 해시, 종 및 몸 해시, 관측·행동·실행 계약
  버전, 개발·검증 장면, 학습 규모와 종료 기준을 기록한다.
- 정책에는 직접 감지한 정보, 유효한 기억과 수신 신호 등 계약된 값을 준다.
  숨은 실제 위치, 전체 재고와 사망 원인 같은 권위 정보는 진단에 쓴다.
- 환경만 바꾼 대조와 두뇌만 바꾼 대조를 준비한다. 감지 → 선택 → 허용 →
  실행 → 섭취·피해·이동 → 장부 반영이 어디에서 달라졌는지 기록한다.
- 학습에서 보지 않은 먹이 분포·통로·날씨 조합에서 비교한다. 개체 성과는
  만남당 접근·공격·이탈, 실제 섭취와 에너지로 보고, 생태 결과는 재스폰
  없는 평가에서 출생·사망·이주·먹이 회복을 함께 본다.
  학습 두뇌가 없는 종은 초기 환경 검증에서 감지·접근·섭취·회피를 확인한다.
  장기 기아는 실행기와 환경을 같은 조건에서 비교할 때 원인을 추적한다.
- 실행 지시 후 공식 안내의 check, 대상 pytest, 스모크를 거쳐 본 학습을
  시작한다. 종료된 결과는 pack과 verify로 검사한다. 검증한 팩은 새 줄의
  출발점이다. 동일 줄을 새 VM에서 재개하려면 해당 줄의 체크포인트 디렉터리와
  고정 입력을 복구한다. 반환 경로는 r9-train/<줄>이다.

5. 저장소 안내와 자료

Dots에 붙여 넣을 실행 전 점검 요청

AdaptiveEcosystem에서 사슴·늑대·멧돼지·물소·표범·여우의 기존 R9 PPO
이어 학습을 준비해 줘. 기준 커밋은
062de0b741d6ae27ede2b454be18eb72ad6226d6이고 출발 팩은
herbivore_rl/results/v3/r9/packs/fauna_r2, 설정은
herbivore_rl/configs/v3_r9_fauna_motion.yaml이야. 이 문서 2절의
매니페스트와 설정 SHA-256을 먼저 맞춰 줘.

1. 저장소 루트 AGENTS.md와 R9_CLOUD_TRAINING.md를 읽고 승인된
   커밋에서 학습용 경로만 받도록 sparse checkout을 사용해 줘. 여섯 종의
   기존 운동 계약과 출발 팩을 사용해. Unreal LFS 에셋은 필요 없어.
2. JYU_Dots_Review_20261114.zip을 받았으면 별도 폴더에 풀고
   `sha256sum -c SHA256SUMS`와 `bash run_island_reference_checks.sh`를
   실행할 수 있어. 이 보조 자료는 위 학습 커밋과 별도로 전달되는 섬 비교
   장면이야. 실행 지시가 준비 검토라면 해시와 절차까지만 확인해 줘.
3. 설치·스모크 승인 뒤에는 R9_CLOUD_TRAINING.md 4절의 check와 pytest,
   별도 출력 경로의 6종 스모크를 실행해 줘. CPU·메모리·디스크, 종별
   ZIP 로드와 출력 팩 검증, 종별 실측 결정/초를 정리해 줘. 리소스가
   약 9 vCPU라면 `--shards 1`을 초기 비교값으로 사용할 수 있어.
   스모크의 출발점·설정은 본 학습과 같고, 출력은 기본
   `ckpt/r9_cloud_smoke/<줄>/`에 남겨 줘.
4. 종별 500만 결정의 본 학습 첫 바퀴는 `max(5000000 / 종별 실측
   결정/초)`에 저장과 평가 시간을 더해 추정해 줘. 스모크가 짧아서
   속도가 흔들리면 실측 구간과 오차 범위를 함께 알려 줘. 본 학습 규모,
   줄 이름, 종료 시각, 저장 위치와 반환 경로는 실행 지시의 값을 사용해.
5. 신규 10종은 2절 표의 종별 비교 장면과 실행 계약을 점검해 줘.
   표본을 정책 관측이나 완전한 학습 세계로 취급하지 말고, 계약이 준비된
   종별로 첫 개발 스모크의 조건과 필요한 구현을 알려 줘.

승인된 학습 결과는 새 줄의 팩으로 verify하고, 클라우드 재시작을 대비해
완료 바퀴마다 팩과 해당 줄의 체크포인트 보존 여부를 확인해 줘.

아리아케 메기의 낮밤 대조에서 Native 문맥 없는 같은 수주의 50ms 이동은
권위 낮 1.198635cm, 밤 1.943486cm였다. 수심·유속·목표를 고정했다.
별도 먹이 대조는 동일 수주에서 220cm 거리, 시작 에너지 50%, 재고 10을
고정했다. 낮에는 시작 시 선택하지 않았고 7초간 지급 0이었다. 밤에는
시작부터 선택해 6초 뒤 2를 먹어 재고가 8이 됐다. Python의
check_water_day_night.py에서도 시작 선택, 밤 유영 거리와 첫 지급을
대조한다. 공통 속도는 Unreal 낮 이동량에서 맞췄고 지급은 정지 후에만
가능하다. 고요한 한 축 수주 시험으로 지형·수류는 추가 대응 범위다.

이미 받은 학습용 sparse checkout에서 섬 대조도 실행하려면
git sparse-checkout add AdaptiveEcosystem/Tools/EcoVegetationEval
을 사용한다. Examples/README.md의 「엔진 없이 실행하는 섬 대조」 명령은
Unreal 에셋과 학습 라이브러리를 요구하지 않는다. 자료가 들어 있는 동일
Git 커밋을 사용한다.

강변의 작은 Python 세계에서는 같은 먹이 재고로 뿌리 접근점만 있을 때와
마른 둑도 접근점일 때를 비교한다. 두 시드에서 범람한 뿌리 쪽은 물소의
도섭 한계 안이었고 말·큰뿔양·산토끼의 한계를 넘었다. 말은 마른 둑에
도착한 뒤 Unreal의 첫 지급처럼 2.8을 가져갔다. 별도 Python 퇴수
대조에서는 같은 재고를 뿌리 쪽에서도 이용하고, 포만 뒤에는 더 먹지 않았다.
지점 간 연결은 시험 입력이고 연속 충돌·가림·이동 시간·재생은 후속 범위다.

부모 보호 대조에서는 보호자의 후보 자격, 접근 목표, 공격 실행 순간의
공격 경로 차단을 따로 기록한다. 멧돼지처럼 두 번째 부모가 허용된 설정은
주 보호자가 경로 밖에 있어도 두 번째 부모가 막을 수 있다. 제어 자동화의
조건과 체력 결과는 로컬 설계 문서의 「공용 사체의 포획·섭취·이탈」에 있다.

Examples/island_eagle_contact_reference_20261114.json에는 고원의 검독수리
사냥 후보, 급강하, 접촉 예약과 최종 거리 거절·포획·사체 지급이 들어 있다.
Examples/README.md의 Python 명령으로 사건 순서를 대조한다. 포획 빈도와
공중 궤적은 향후 비행 세계에서 별도로 검증한다.
실행형 급강하 대조도 같은 README에서 실행한다. 실측 쥐 위치에서 접촉
예약 후 정지한 경우와 0.10초 동안 22cm 움직인 경우를 비교했다. 준비
시점에 거리가 가까워도 실제 실행 때 멀어지면 실패하고 사체를 만들지
않는다. 체급과 시야, 이동 중 몸의 충돌을 바꾼 장면도 포함한다.
장애물·독수리 시작 위치·움직임은 시험 입력이다. 실제 고원 비행 궤적,
후보 탐색, 착지와 사체 접근은 별도 검증 범위다.
island_highland_eagle_actual_20261114.json의 saved_geometry는 고원 두
지점의 시야 선과 비행체 반경을 각각 기록한다. 두 시드의 Unreal 조회
16건과 Python 계산이 일치했다. 시야만 가리면 시작 전에 취소하고,
시야가 열려도 몸이 걸리면 급강하 중에 멈추는 사례를 Python에서 실행한다.

검독수리 포획 5건에서 사체 생성·착지·첫 지급 순서를 대조하고, 두 건의
수직 착지 구간과 15건의 실제 지급을 Python으로 확인했다. 까마귀와
같은 사체를 쓰는 통제 시험에는 사냥 개체 우선권, 한 자리 경쟁과
