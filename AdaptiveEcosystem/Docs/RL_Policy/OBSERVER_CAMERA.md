# 관찰 카메라 — 늑대·사슴·탑·쿼터뷰 단축키 (2026-10-27)

사용자 요구(10-27): "카메라가 느려 행동 관찰이 어렵다." 늑대 시점·사슴 시점·탑뷰·쿼터뷰로 행동을 바로 따라가는 단축키를 만든다. 단축키 목록은 **화면 오른쪽 위에 글자로 늘 보이고**, `H` 로 숨기거나 다시 보인다.

- 코드: `Source/AdaptiveEcosystem/AI/Policy/EcoV3ObserverCamera.h/.cpp` (`UEcoV3ObserverCameraSubsystem`, 도우미 `EcoV3Observe`)
- 시험: `Source/AdaptiveEcosystem/AI/Policy/Tests/EcoV3ObserverCameraTest.cpp` (`AdaptiveEcosystem.Policy.V3.ObserverCamera.*`)
- 같이 고친 것: 촬영 감독 `EcoV3FilmDirector` 의 wolf·deer 장면 대상 찾기 (아래 7절)
- 상태: 코드·시험·문서를 쓴 뒤 10-27 오전에 확인했다 — UBT 두 판(적응 unity·`-DisableAdaptiveUnity`) 성공, 자동화 `AdaptiveEcosystem` 전체 실패 0, 창 모드(1280×720) 게임에서 `eco.Cam.*` 예약 명령으로 모드마다 화면을 찍어 대상이 가운데에 오고 화면 글(한글)이 맞는 것을 봤다. 그 확인에서 숲 지역 나뭇잎 가림·움직임 흐림·자동 추적 줌의 짝 놓침을 보고 4절의 가리는 나무 숨기기·가림 피하기·흐림 끄기·짝 맞춤 거리를 더했다. PIE 에서 사람이 키를 직접 눌러 본 것은 아니다 (예약 콘솔 명령은 키와 같은 동작 함수를 부른다).
- 10-27 사용자 결정 뒤 더함 — 관찰 중(1~5 모드) 플레이어 이동 입력 막기 (1절 끝·11절). 안 보이는 폰이 `W` `A` `S` `D` 로 걸어 발소리(`Player.Footstep`)를 사슴이 듣던 문제를 막는다. 시험 `MoveInputBlock` 을 더했다. 10-27 오후 확인: UBT 두 판(적응 unity·`-DisableAdaptiveUnity`) 성공, 자동화 `AdaptiveEcosystem` 255 개 실패 0 (`MoveInputBlock` 포함), 창 없는 헤드리스 게임에서 Enhanced Input 강제 키(`Input.+key W`·`S`)로 막힘·풀림을 봤다 (1절 끝 표). 사용자 지시(창이 포커스를 빼앗지 않게)로 창 모드·실제 Windows 키 메시지 확인은 하지 않았다.
- 10-27 적대적 검토 (커밋 `b7fcbc0` 뒤, 코드는 그대로): 창 모드 게임 창에 실제 Windows 키 메시지(`WM_KEYDOWN`·`WM_KEYUP`·`WM_MOUSEWHEEL`)를 보내 2절의 키가 모두 먹는 것을 봤다 — `1`·다시 `1`(다음 늑대)·`2`·`.`·`,`·`3`·`4`·`G`·`5`·`0`·숫자패드 `1`·`2`·`0` 은 기록 `[EcoCam]` 줄로, `-`(30 → 36 m)·`=` 두 번(→ 30 → 25 m)·휠 아래 두 번(→ 30 → 36 m)·휠 위(→ 30 m)·숫자패드 `+`(14 → 12 m)·`-` 두 번(→ 14 → 17 m)·`H`(목록 숨김·다시 보임)는 화면 글로. 엔진 입력 길(뷰포트 → 플레이어 컨트롤러 키 상태 `WasInputKeyJustPressed`)을 그대로 탄다. 편집기 PIE 에서 사람이 누른 것은 아니다. 같은 시드 카메라 켬·끔 비교는 1절 끝.

## 1. 보기만 바꾼다

관찰 카메라는 화면에 보이는 카메라만 옮긴다. 사슴·늑대·먹이·난수·Mass 조각·플레이어 폰에 쓰지 않는다 (관찰 중에는 플레이어 컨트롤러의 이동 입력만 막는다 — 이 절 끝). Mass 를 읽을 때도 엔티티 관리자의 지연 명령 버퍼를 비우지 않는다 (`SetFlushDeferredCommands(false)`). 통합 v3 Native 세계는 보는 자리를 읽지 않으므로 카메라를 켜고 꺼도 그 세계의 결과(포획·굶음·숨음 비율 등)는 같다. 대상을 가리는 나무는 **이 화면에서만** 숨긴다 (4절 — 플레이어 컨트롤러의 숨김 목록. 액터·충돌·사슴 눈길 가림은 그대로이고 원래 카메라로 돌아가면 되돌린다).

다만 카메라가 플레이어 컨트롤러의 보는 자리(view point)를 옮기므로, 그 자리를 읽는 코드는 플레이어가 직접 카메라를 옮길 때처럼 따라 바뀐다.

- 팀 종 AI(`EcoSpeciesAIInputProcessor`)는 보는 자리와의 거리로 결정 간격 단계(가까움·중간·멂)를 정한다. 그래서 팀 생태 레벨에서는 카메라 자리에 따라 개체별 결정 간격이 달라질 수 있다.
- 팀 표현 액터 예산(보는 자리 200 m 안 64 마리)과 복제 관련도도 보는 자리를 따른다.
- World Partition 스트리밍 원천도 보는 대상(카메라 액터) 자리다. 아래 11절을 본다.

- 로컬 플레이어 화면마다 따로 돈다 (단독·리슨 서버·클라이언트). 데디케이티드 서버에는 만들지 않는다.
- 게임·PIE 월드에만 만든다 (에디터·미리보기 월드 없음).
- 촬영 감독(`-EcoV3Film=`)이 도는 실행에는 만들지 않는다. 촬영 카메라와 보기 대상을 다투지 않고, 촬영 프레임(`-EcoV3FilmUI` 포함)이 전과 같다.
- 시간은 실시간으로 잰다. 느린 재생(slomo)·멈춤 중에도 카메라는 제 속도로 움직인다 (멈춘 동안에도 키가 먹는다).

관찰 중 플레이어 이동 입력 막기 (10-27 사용자 결정):

- 관찰 중(1~5 모드)에는 로컬 플레이어 컨트롤러의 **이동 입력만** 막는다. 카메라가 폰에서 떨어져 있어 폰이 걷는 것이 보이지 않는데, 통합 v3 세계는 폰의 발소리(`Player.Footstep`)를 사슴이 듣는 위협으로 읽기 때문이다.
- 방법: 엔진의 이동 무시 수(`AController::SetIgnoreMoveInput` — 여러 곳이 걸면 쌓인다)를 하나 더한다. 그러면 프로젝트 캐릭터의 `Move`(`AddMovementInput`)가 폰에 들어가지 않는다. 폰 자체(자리·속도·부품)에는 쓰지 않는다.
- 푸는 때: `0`(원래 카메라)·`eco.Cam.Enable 0`·`eco.Cam.BlockMove 0`·월드 닫기. 우리가 더한 하나만 뺀다 — 팀·엔진이 따로 건 막기(영화 모드 등)는 남는다.
  - `G`(지역 바꾸기)·`,` `.`·다른 관찰 모드(1~5 사이)는 관찰을 이어 가므로 막기도 그대로다 (풀리지 않는 것이 맞다 — `0` 을 누르면 풀린다).
  - Play 를 끝내면(월드 닫기) 플레이어 컨트롤러가 월드와 함께 지워져 이동 무시 수도 같이 사라진다. 이때는 컨트롤러가 이미 지워져 `풀림 — 월드 닫기` 기록 줄이
    남지 않는다. 그 줄은 끊김 없는 이동(seamless travel)처럼 컨트롤러가 다음 월드로 넘어갈 때만 나온다. 다음 Play 는 새 컨트롤러라 막힘이 남지 않는다.
  - 10-27 적대적 확인 (창 없는 리슨 호스트, 통합 맵, 예약 명령): `eco.Cam.Wolf`(막음) → `eco.Cam.Region Highland`·`Barren`(지역 바뀜, 막음 그대로) →
    `eco.Cam.Player`(풀림 — 원래 카메라) → `eco.Cam.Auto`(막음) → 끝 시간으로 종료(풀림 줄 없이 닫힘, 위와 같음).
- 엔진이 수를 지우면(폰 다시 시작 때 `APlayerController::ClientRestart` 의 `ResetIgnoreInputFlags`) 다음 프레임에 다시 건다. 로컬 플레이어 컨트롤러가 바뀌면 전 것을 풀고 새 것을 막는다.
- 막지 않는 것: 시야(마우스 — 관찰 카메라는 쓰지 않는다. 컨트롤러 방향은 돌므로 `0` 으로 돌아오면 폰 카메라 방향이 바뀌어 있을 수 있다)·점프(`Space` — 제자리 점프는 가로 속도가 없어 발소리가 나지 않는다)·`Shift`·`Ctrl`(걸음새만 바뀐다)·`F`(플레이어 치기 — 11절).
- 이동 키를 누르던 중에 관찰을 켜면 폰은 제 제동으로 멈춘다 (그 사이 발소리가 한 번쯤 날 수 있다 — 아래 확인에서는 0.5 초 안에 섰고 발소리는 없었다).
- 오른쪽 위 글에 `플레이어   이동 키 막음 (0 으로 풀림)` 줄이 보이고, 기록에 `[EcoCam] 플레이어 이동 입력 막음`·`풀림 — <까닭>` 줄이 남는다.

## 2. 단축키 (화면 오른쪽 위에 늘 보인다)

| 키 | 하는 일 |
|---|---|
| `1` | 늑대 시점 — 늑대 뒤에서 따라간다. 다시 누르면 같은 지역의 다음 늑대 (id 차례) |
| `2` | 사슴 시점 — 사슴 뒤에서 따라간다. 다시 누르면 다음 사슴 |
| `3` | 탑뷰 — 대상 바로 위. 대상이 없으면 지역 무대 전체 |
| `4` | 쿼터뷰 — 대상 기준 45° 사선 |
| `5` | 자동 추적 — 쫓기는 사슴·사냥 중인 늑대를 따라가고, 사건이 끝나면 다음 사건으로 |
| `,` `.` | 이전·다음 대상 (자동 추적이면 다음 사건) |
| `-` `=` · 마우스 휠 | 줌 (멀리·가까이, 한 번에 1.2 배, 기본 거리의 0.15~8 배) |
| `G` | 지역 바꾸기 (이름 차례로 다음 지역) |
| `0` | 원래 카메라 (폰) 로 돌아가기 |
| `H` | 단축키 목록 숨기기/보이기 |

숫자패드 `0`~`5`, `+`·`-` 도 같은 일을 한다. `,` `.`·`-` `=`·휠·`G` 는 관찰 중(1~5 모드)일 때만 먹고, 원래 카메라일 때는 아무 일도 하지 않는다 (`H` 는 늘 먹는다). 관찰 중에는 플레이어 이동(`W` `A` `S` `D`)이 먹지 않고, `0` 으로 돌아오면 다시 먹는다 (1절 끝). 콘솔에 글을 치는 동안에는 키가 먹지 않는다. 프로젝트 Enhanced Input 매핑은 바꾸지 않았다 (플레이어 컨트롤러 키 상태 `WasInputKeyJustPressed` 만 읽는다).

- 늑대 시점에서 `2` 를 누르면 보던 늑대에게 가장 가까운 사슴으로, 사슴 시점에서 `1` 을 누르면 그 사슴 곁의 사냥 중인 늑대(없으면 가까운 늑대)로 넘어간다.
- 처음 `1` 은 보는 자리의 지역에서 사냥 중인 늑대를 먼저 고른다.
- 늑대·사슴 시점에서 대상이 죽으면 3 초 머문 뒤 가까운 같은 종으로 넘어간다. 대상이 사라지면(조정자가 지움) 바로 넘어간다 (탑뷰·쿼터뷰는 무대 전체로).

## 3. 화면 글

오른쪽 위에 어두운 반투명 바탕·흰 글자 묶음 하나를 그린다.

- 맨 윗줄: `관찰 카메라   H 단축키 숨기기` (숨기면 `H 단축키 보이기`). 이 줄은 늘 남는다.
- 그 밑: 단축키 목록 (`H` 로 숨기기/보이기).
- 가는 줄 밑: 모드·거리, 대상(종·id·지역), 상태(색), 사슴이면 가장 가까운 늑대 거리·상태, 늑대면 가장 가까운 사슴 거리·상태, 자동 추적이면 사건/짝, 이동을 막고 있으면 `플레이어   이동 키 막음 (0 으로 풀림)`. 원래 카메라일 때는 `원래 카메라 (1~5 로 관찰)` 와 모든 지역의 산 사슴·늑대 수.

상태 이름은 사슴 `먹기·경계·거리 두기(쉬는 늑대)·도망·도망(트인 쪽)·도망(은신처)·숨으러 감·웅크림·얼기·잠·이동`, 늑대 `배회·사냥·먹기·쉼`, 그리고 `죽음` 이다. `거리 두기(쉬는 늑대)` 는 10-27 세계 규칙 고침(쉬는 늑대 시야 밖으로 걸어 물러나기, 덮기 `EcoWorldV3::kKeepRest`, `eco.IntegratedV3.RestKeep`)을 화면에서 따로 보이게 한 것이다 (경계처럼 두뇌가 먹기를 고른 동안만). 서버·단독 통합 v3 는 지역 세계의 행동·도주 덮기·두 길 두뇌의 길·늑대 상태(배부름 포함)를 읽고 (`EcoV3Integrated::DeerLabel`·`WolfLabel` 과 같은 판정), 클라이언트·v1 은 팀 표현 활동 값(`EEcoSpeciesActivity`)을 읽는다.

자리:

- 왼쪽 위는 두뇌 교체 알림·상태 줄(화면 메시지)과 팀 `ECO INSPECTOR` 판(x 15~655 px)의 자리다. 묶음 왼쪽 끝은 x 663 px 보다 오른쪽에 둔다.
- 팀 `HERD MIGRATION` 판(오른쪽 위, `M` 으로 켬)이 보이면 그 밑에 두고, 밑에 안 들어가면 그 왼쪽 옆에 둔다.
- 1280×720 에서도 잘리지 않게 배율을 줄인다 (0.55 배까지). 기본 배율은 화면 높이 ÷ 720 × 1.15 (1~2.4) 이고 `eco.Cam.HudScale` 로 더 키우거나 줄인다.
- HUD 를 숨기면(`showhud`) 같이 숨는다. `UDebugDrawService` 의 `Game` 표시로 HUD 위 디버그 캔버스에 그린다.
- 통합 개체가 하나도 없는 레벨에는 그리지 않는다 (볼 것이 없다). 원래 카메라일 때도 1 초마다 다시 보고, 개체가 생기면 1 초 안에 나타난다.

## 4. 카메라 움직임

| 모드 | 거리 | 숙임 | 방위 |
|---|---|---|---|
| 늑대 시점 | 14 m | −20° | 대상이 가는 쪽 뒤 (0.8 m/s 보다 느리면 몸 방향) |
| 사슴 시점 | 11 m | −18° | 같음 |
| 탑뷰 | 45 m (대상 없으면 무대 한 변 1.1 배가 화면 세로에 드는 높이) | −89° | 들어설 때 방위 그대로 |
| 쿼터뷰 | 30 m | −45° | 45° 고정 |
| 자동 추적 | 24 m (줌 곱함), 짝이 있으면 짝까지 한 화면에 드는 거리(짝 거리 × 1.25 + 8 m)보다 가까이 가지 않음, 120 m 까지 | −35° | 짝 선과 직각, 지금 방위에 가까운 쪽 |
| 대상 없음 (탑뷰 밖) | 무대 한 변 0.95 배 | −40° | 45° 고정 (지역 무대 전체) |

- 부드러운 따라가기: 초점·방위·숙임·거리를 임계 감쇠(`EcoV3Observe::SmoothDamp`, 넘침 없음)로 옮긴다. 초점 시간 상수는 0.18 초이고, 초점에 대상 속도 × 0.18 초(최대 6 m)를 앞으로 더해 9 m/s 로 뛰는 늑대도 뒤처지지 않는다 (앞보기가 없으면 약 1.6 m 뒤처진다 — 시험이 본다).
- 150 m 넘게 건너뛰면(지역 바꾸기 등) 끊어 옮긴다.
- 카메라는 땅(아래로 쏜 선이 맞은 WorldStatic 가운데 가장 낮은 것) 2 m 위 밑으로 내려가지 않는다. 내려가야 하면 높이를 올리고 초점을 다시 본다.
- 가림 피하기 (10-27 창 모드 확인 뒤 더함): 숲 지역에서 자동 추적(24 m, −35°)·늑대 시점 카메라가 나무 잎 속에 들어가 대상이 가려졌다. 그래서 초점→카메라 사이를 반지름 25 cm 공으로 쓸어 처음 닿는 **보이는 WorldStatic 물체**(지형·바위·나무 — 땅 찾기와 같은 물체 종류) 40 cm 앞으로 바로 당긴다(2.5 m 보다 가까이는 당기지 않는다). 이 레벨의 나무는 카메라 채널(`ECC_Camera`, 스프링 팔 채널)을 막지 않아 채널 쓸기로는 잎을 못 찾았다. 막는 부피(`AVolume`)·숨긴 액터·안 보이는 부품은 건너뛴다 (무대 밖 보이지 않는 벽에 끌려 들어가지 않게). 트이면 시간 상수 0.6 초로 넘치지 않게 다시 편다 (`EcoV3Observe::ArmStep`, 시험 `SmoothFollow` 7번). 카메라·플레이어 폰·대상·짝 표현 액터는 건너뛴다. 화면 글의 `거리` 는 당기기 전 거리이고, 1 m 넘게 당기면 `(가림 피해 N m)` 를 덧붙인다.
- 가리는 나무 숨기기 (10-27 창 모드 확인 뒤 더함): 이 레벨 너도밤나무(`Beech_Tree`)는 잎에 충돌이 없어 위 쓸기로는 못 찾는다. 그래서 그리기 상자(Bounds)가 높이 4 m 이상·가로 반폭 1~30 m 인 보이는 정적 메시(인스턴스 묶음 말고 — 한 그루만 숨길 수 없다)를 5 초마다 후보로 모으고, 초점→카메라 선분(자동 추적이면 짝→카메라 선분도)이 상자를 지나면 그 메시를 이 플레이어 화면에서만 숨긴다 (`APlayerController::HiddenPrimitiveComponents`, `EcoV3Observe::IsOccluderBox`·`SegmentHitsBox`, 시험 `SmoothFollow` 8번). 그림자는 남는다. 후보 수는 기록 `[EcoCam] 가리는 나무 후보 N` 으로 남긴다. 원래 카메라(`0`)·`eco.Cam.Enable 0`·월드 닫기에서 되돌린다.
- 자동 추적 줌: 줌은 기본 거리(24 m)에만 곱한다. 짝 맞춤 거리까지 곱하던 처음 판은 당겼을 때(줌 < 1) 가운데만 보여 사슴·늑대가 둘 다 화면 밖이었다 (10-27 창 모드 확인).
- 움직임 흐림(motion blur)은 관찰 카메라에서만 끈다 (빠르게 따라갈 때 대상이 뭉개졌다). 다른 후처리는 그대로다.
- 시야각 70°.

## 5. 자동 추적 (키 5)

고르는 차례 (지역을 `G`·`eco.Cam.Region` 으로 골랐으면 그 지역 안만, 아니면 지금 지역을 먼저 보고 모든 지역):

1. 쫓기는 사슴 — 도망 중이고 사냥 중인 늑대가 40 m 안에 있는 사슴 가운데 그 늑대가 가장 가까운 것 (짝 = 그 늑대)
2. 사냥 중인 늑대 — 가장 가까운 사슴이 가까운 것 (짝 = 40 m 안의 가장 가까운 사슴)
3. 도망 중인 사슴 — 아무 늑대가 가까운 것

대상의 사건(사슴 도망·숨으러 감, 늑대 사냥)이 끝나면 2.5 초 머문 뒤 다음 사건으로 넘어간다. 방금 끝난 대상은 다른 후보가 없을 때만 다시 고른다. 짝이 60 m 안이면 둘 다 한 화면에 넣는다. 40 m 는 야생 도주 안전 거리 기본값과 같다.

## 6. 대상 찾기 — 논리 Mass 개체에서

대상은 통합 개체 꼬리표(`FEcoIntegratedCreatureTag`)가 붙은 **논리 Mass 개체**에서 고른다 (`EcoV3Observe::Gather`). 팀 표현 액터(`BP_EcoDeer/Wolf`, `BP_JYU_Deer/Wolf` — 모두 `AEcoCreatureRepresentationActor` 하위)는 보는 자리 200 m 안의 가까운 64 마리에게만 생기므로 (`AEcoCreatureIntegrationSpawner::HostVisualDistance`, `ConnectionBudget.MaxActorRepresentations`), 표현 액터로만 찾으면 멀리 있는 대상을 못 고른다.

- 자리는 표현 액터가 붙어 있으면 그 액터 자리(화면에 보이는 것과 같다), 없으면 논리 자리다. 카메라가 대상 곁으로 가면 팀 표현이 그 곁 개체에게 액터를 붙인다.
- 클라이언트에서는 받은 표본 자리(`FEcoClientPresentationFragment`)를 쓰고, 아직 표본이 없는 개체는 뺀다 (팀 표현과 같다).
- Mass 처리 중에는 읽지 않고 지난 목록을 쓴다. 읽기만 한다.

## 7. 촬영 감독 wolf·deer 장면 고침

촬영 감독(`-EcoV3Film=` … `wolf`·`deer` 장면)이 대상을 못 찾던 원인은 두 가지가 겹친 것이다.

1. 대상을 팀 표현 액터에서 골랐다 — 표현 액터는 보는 자리 200 m 안 가까운 64 마리에게만 생긴다.
2. 촬영 카메라가 월드 원점에서 시작한다 — 무대에서 300 m 넘게 떨어져 있어 첫 프레임에 무대에 표현 액터가 없었다.

고침: wolf·deer 장면의 대상 고르기와 따라가기, 정찰 기록(`scout.csv`)을 6절과 같은 논리 개체 찾기(`EcoV3Observe::Gather`)로 바꿨다. 늑대 번호는 그 지역 산 늑대의 StableAgentId 차례 그대로이고, 정찰 기록의 `widx` 도 같은 차례라 장면 `대상` 번호와 맞는다. 표현 액터가 있으면 자리는 그 액터 자리라 전과 같다.

달라지는 점: 정찰 기록이 이제 보는 자리 둘레 일부가 아니라 지역의 모든 산 늑대·사슴을 센다 (`nd`·`run20`·`edge25`·`covin` 이 커질 수 있다). 표현 액터가 없는 개체의 `motion` 은 액터 기본 문턱(서기 5 cm/s, 뛰기 400 cm/s)으로 셈한다 — 블루프린트가 문턱을 바꿨으면 액터가 있는 개체와 조금 다를 수 있다.

## 9. 팀 키를 피한 이유

이미 쓰이는 키와 겹치면 한 번 누름에 두 가지 일이 함께 일어난다. 그래서 아래 키는 쓰지 않았다 (`EcoV3Observe::TeamReservedKeys`, 시험이 겹침을 본다).

| 키 | 이미 하는 일 | 어디 |
|---|---|---|
| `Tab` | 검사할 개체 돌리기 | 팀 `AEcoCreatureInspectorHUD` (JYU 검사 HUD) |
| 마우스 가운데 | 검사할 개체 집기 | 같음 |
| `R` | 검사 기록 | 같음 |
| `M` | 무리 이주 판 켜기/끄기 | 같음 (`EcoHerdMigrationDebug::Toggle`) |
| `[` `]` | 이주 계획 돌리기 | 같음 |
| `F` | 플레이어 행동 | `UEcoPlayerEcologyComponent` |
| 왼 `Shift` · 왼 `Ctrl` | 뛰기 · 살금살금 | 같음 |
| `W` `A` `S` `D` · `Space` · 방향키 | 이동 · 점프 (관찰 중에는 이동만 막는다 — 1절 끝) | 프로젝트 기본 입력 (`IMC_Default`) |

숫자 `0`~`5`, `,` `.`, `-` `=`, `G`, `H` 는 이 저장소의 C++ 에서 다른 곳이 읽지 않는다. 에셋은 `/Script/InputCore`·`K2Node_InputKey` 를 참조하는 `Content/**/*.uasset` 의 이름표(name map)에서 이 키 이름(`One`~`Five`·`Zero`·`G`·`H`·`Comma`·`Period`·`Hyphen`·`Equals`·`MouseScroll*`·`NumPad*`)을 찾아봤고, 입력 매핑(`IMC_Default`·`IMC_MouseLook` 등)과 블루프린트 키 이벤트에서는 나오지 않았다 (`UI_Thumbstick` 의 `Subtract` 는 키가 아닌 수식 노드 이름이다). 이름표 검사는 에셋을 열어 본 것이 아니다 — PIE 에서 숫자 키가 다른 일을 같이 하면 알려 주기 바란다.

| `MoveInputBlock` | 시험이 만든 플레이어 컨트롤러·폰으로: 원래 카메라는 안 막음(폰에 `W` 가 들어감), 관찰 중은 막음(폰 이동 입력 0), 매 프레임·모드 바꿈에도 한 번만 더함, 엔진이 지우면(`ResetIgnoreInputFlags`) 다시 막음, `eco.Cam.BlockMove` 0·1, `0` 이면 풀림, 팀이 건 막기는 남김, 컨트롤러가 바뀌거나 없어지면 전 것을 풂 (로컬 플레이어가 없어 Tick 대신 막기 맞추기를 직접 부른다) |

## 11. 남은 것

- 사람이 편집기 PIE 에서 키를 직접 눌러 본 확인은 아직이다. 10-27 은 창 모드 게임에 예약 콘솔 명령으로 같은 동작을 걸어 화면을 찍었고, 적대적 검토에서 같은 창 모드 게임에 실제 Windows 키 메시지를 보내 모든 키가 먹는 것을 봤다 (머리의 상태 줄).
- 관찰 중 플레이어 이동(`W` `A` `S` `D`·방향키·게임패드 이동)은 이제 막힌다 (10-27 사용자 결정, 1절 끝). 전에는 관찰 중에도 폰이 걸었고, 카메라가 폰에서 떨어져 있어 그것이 보이지 않은 채 발소리(`Player.Footstep`)를 그 둘레 사슴이 들었다. 남은 것:
  - `F`(플레이어 치기)는 그대로 먹는다. 팀 `UEcoPlayerEcologyComponent` 가 키를 직접 읽어(`IsInputKeyDown(EKeys::F)`) 이동 무시 수와 상관없고, 이 변경은 그 파일을 건드리지 않았다. 관찰 중 `F` 를 누르면 안 보이는 폰 곁의 개체를 칠 수 있으니 누르지 않는다.
  - 폰 자리 자체는 그대로 위협이다 — 레벨 설정이 플레이어 폰을 위협 원천으로 쓰면, 서 있는 폰 곁 사슴은 관찰 중에도 반응한다 (폰을 옮기지 않으므로 전과 같다).
  - 이동 키를 누르던 중에 관찰을 켜면 폰이 제 제동으로 멈추는 동안 발소리가 한 번쯤 날 수 있다 (10-27 확인 실행에서는 0 번).
  - 키 입력은 창 없는 게임에서 Enhanced Input 강제 키(`Input.+key`)로 확인했다 (1절 끝 표 — 프로젝트 매핑·캐릭터 `Move` 를 탄다). 사람이 편집기 PIE 에서 `W` 를 직접 눌러 본 확인은 아직이다.
  - 통합 맵 `/Game/Map/LV_Ecosystem_IntegrationTest` 의 플레이어 폰은 엔진 `DefaultPawn` 이다. 막기는 같은 이동 입력 길에 걸리지만, 이 맵에서 폰이 강제 키로 움직이는지·발소리를 내는지는 보지 않았다 (확인은 `BP_JYU_Player` 가 있는 조연우 복사 맵에서 했다).
- 화면 글 글꼴은 엔진 작은 글꼴(`GEngine->GetSmallFont()`, 화면 메시지와 같다)이다. 10-27 창 모드 화면에서 한글이 깨지지 않고 보였다. 엔진 경고(예: `[VSM] Non-Nanite Marking Job Queue overflow`) 같은 화면 메시지 한 줄이 묶음 위를 가로질러 겹칠 수 있다 (화면 메시지는 화면 너비를 다 쓴다).
- 숲 지역 팀 화면 이름표(`Wolf #1`)가 카메라 반대쪽에서 보면 거울 글씨로 보인다 (팀 표현 액터의 글 부품 — 관찰 카메라 밖).
- World Partition 스트리밍: 플레이어 컨트롤러의 스트리밍 원천은 보는 대상(관찰 카메라 액터)의 자리다 (`APlayerController::GetStreamingSourceLocationAndRotation`). 스트리밍을 켠 레벨에서 카메라를 플레이어 폰에서 멀리(다른 지역 등) 옮기면 폰 둘레 칸이 내려가 폰이 떨어질 수 있고, 지역을 건너뛸 때 불러오기로 멈칫할 수 있다. 폰에는 손대지 않았으므로 PIE 에서 확인해야 한다.
- 탑뷰·쿼터뷰의 대상 없는 무대 전체 보기는 통합 v3 서버·단독에서는 무대(정사각형) 크기, 그 밖(클라이언트·v1)에서는 그 지역 개체 둘레 상자로 잰다.
