# Dots 16종 학습 · 실험 인계

이 문서는 Dots에서 종별 실험을 비교할 때 쓰는 참고표다. 현행 계약과 실행기는 [R9 클라우드 안내](R9_CLOUD_TRAINING.md), 로컬 환경의 상세 근거는 [기존 인계](DOTS_ECOSYSTEM_TRAINING_HANDOFF_KO.txt)와 [Python 대응 예제](Examples/README.md)를 따른다.

## 기준을 고정하는 방법

- 기존 R9 실행은 당시 전체 SHA, 팩, YAML, 몸·입출력 해시, 종별 출발 ZIP과 상대 정책을 함께 기록한다. 기존 R9는 115개 관측과 지상 행동 19개를 쓴다. M1에서 상대 정책 NPZ의 몸 정보 이전과 학습 대상 PPO ZIP 로드는 각각 확인한다.
- Unreal 구현 기준은 `2b0110d6`의 `LV_JYU_IslandEcosystemRefreshed`다. 당시 섬은 사슴 R7e, 늑대 Native 규칙, 나머지 14종의 규칙 실행으로 돌았다. 16종 118마리와 작성 먹이 용량 215·명목 재생 2.82/게임초는 해당 비교의 시작 조건이다. 생존 수는 재현용 기준선으로 기록한다. [로컬 최신 검증](../Team/JYU_ISLAND_ECOSYSTEM_HANDOFF_20261105.md)
- `fe551ddb`의 호수·해안 확장·새 수로는 레벨 설계안이다. 종별 끼니 기준의 전면 적용, 퇴수 피난, 수온·용존산소·탁도 역시 후속 범위다. 신규 10종의 클라우드 실험은 기존 R9 계약 및 현재 Unreal의 실행 범위와 각각 비교한다.
- 실측 JSON에는 진단용 정답이 들어갈 수 있다. 관측에 연결하기 전에는 게임의 개체가 해당 값을 직접 감지할 수 있는지 확인한다. 공동 학습에서 훈련 전용 비평가에 추가 정보를 주는 경우에도 실행 정책의 입력은 게임 계약을 따른다.

## 종별로 먼저 재현할 장면

| 종 | 첫 장면 | 비교할 결과 |
| --- | --- | --- |
| 사슴 | 가까운 먹이의 고갈과 가림 | 실제 섭취, 위협 후 복귀와 에너지 |
| 늑대 | 경쟁자가 있거나 없는 사체 | 사냥·섭취·이탈, 기아와 다른 종 영향 |
| 멧돼지 | 식물 먹이와 가까운 사체 | 기존 M1 대비 실제 섭취와 공격·기아 사망 |
| 물소 | 같은 재고의 두 접근점 | 접근·도착·실제 섭취와 고갈 시 전환 |
| 표범 | 시야와 퇴로가 다른 포획 장면 | 시도→접촉→포획→섭취 중 끊기는 곳 |
| 여우 | 살아 있는 먹이와 사체의 거리 대조 | 실제 섭취, 기아, 전환과 포기 사유 |
| 쥐 | 먹을 수 있는 곳과 위협 아래 양방향 대피 | 실제 섭취, 가림과 대피, 행동 편중 |
| 큰뿔양 | 가까운 먹이와 이동·경사를 요구하는 먹이 | 이동·실제 섭취·저에너지 체류 |
| 산토끼 계열 | 먹이터 고갈과 다른 먹이터·피난처 | 정지·먹기 반복, 이동과 실제 지급 |
| 말 | 마른 둑에서 먹고 돌아오는 장면 | 요청→도착→실제 섭취→복귀, 이동 비용 |
| 까마귀 | 다른 종도 쓰는 사체 | 접근·착지·섭취·재이륙과 경쟁 |
| 검독수리 | 접근·착지 또는 급강하·포획 | 각 단계의 성공과 실제 지급, 다른 종 영향 |
| 밍크 | 입수해서 먹은 뒤 다른 곳으로 상륙 | 육지↔물 전환, 소모와 마른 땅 복귀 |
| 메기류 | 수중 군락과 사체가 있는 장면 | 수심·거리별 감지, 유영 접근과 실제 지급 |
| 잉어 | 정상·퇴수의 선반과 부화 뒤 첫 식사 | 치어·성체별 도달, 부화 후 첫 지급 |
| 가상 담수 소형어류 | 공유 재고의 한 지점 노출·재개방 | 접근점 전환, 재침수 후 섭취와 단일 재고 차감 |

예제 중 일부는 기록을 재생하거나 2D로 단순화한 장면이다. 각 실험에 Unreal 실측, Python 독립 실행, 아직 빠진 조건을 명시한다. 원본과 후보의 정책 비교에서는 다른 종의 정책을 고정한다.

## 실험 한 건에 남길 내용

- **가설과 대조군.** 실패가 발생한 사건을 고정하고 바꿀 변수 하나, 예상되는 개선과 악화 허용 범위, 판정 시점을 사전에 적는다. 최초 단계는 먹이 존재→개체의 감지→실행 가능성→정책 요청→실행·거절→섭취·에너지→보상이다.
- **실행 정보.** 전체 SHA, 환경 및 설정 해시, 출발 체크포인트, 상대 정책, Python·라이브러리 버전, 시드 역할, 실제 결정·전이·독립 세계 수, 시간과 메모리를 기록한다. 종료 사유와 목표 대비 완료량을 별도로 남긴다.
- **평가 정보.** 같은 세계의 개체들을 독립 시드처럼 집계하지 않는다. 원본과 후보를 같은 시드·초기 개체·환경·상대 정책에서 비교하고, 새 지도와 조건을 따로 보고한다. 실제 게임에 쓸 행동 선택 방식에서 우선 확인한다. 팀 판정 시드 `44800~44999`는 팀에 남긴다.
- **복구 정보.** 검증된 외부 저장 위치, 체크포인트와 최적화 상태, 정규화·카운터·시드 상태, 복원 검사 결과를 남긴다. 엔진 환경 상태까지 정확히 복원할 수 없으면 어느 시점부터 재시작하는지 적는다. 원본 팩과 실패한 실험 기록도 보존한다.

## 참고 자료와 바로 연결할 질문

- 유효하지 않은 행동의 선택과 배포 시 같은 판정이 가능한지 대조한다. [PPO](https://arxiv.org/abs/1707.06347) · [행동 마스크](https://arxiv.org/abs/2006.14171)
- 시범이 실제로 성공하고, 학생이 방문하는 상태에서도 재현되는지 비교한다. [DAgger](https://proceedings.mlr.press/v15/ross11a.html)
- 한 상대 정책에 맞춰진 행동이 검증된 과거 정책이나 새 환경에서도 유지되는지 확인한다. [Aquarium](https://arxiv.org/abs/2401.07056) · [과거 정책을 섞는 다중 에이전트 연구](https://proceedings.neurips.cc/paper/2021/hash/797134c3e42371bb4979a462eb2f042a-Abstract.html)
- 독립 시드의 결과 분포와 실제 CPU 병렬 효율을 보고한다. [Procgen](https://proceedings.mlr.press/v119/cobbe20a.html) · [강화학습 평가](https://arxiv.org/abs/2108.13264) · [SB3 병렬 환경](https://stable-baselines3.readthedocs.io/en/master/guide/vec_envs.html)
