# Native v3 사슴의 Static Mesh 접촉 회피 교체 명세

2026-11-18 설계안. 기준은 `jwj-1115`의 `69519972`와 현재 작업 트리다. 첫 적용 장면은 `1102_Integration_JWJ`의 `Forest_A`다. 아래 명령과 지표는 다음 구현의 요구사항이다.

A/B 실행과 현재 구현 범위는 [사용자 검증 안내](15_STATIC_MESH_CONTACT_AVOIDANCE_TEST_GUIDE.md)를 따른다.

## 목표와 적용 조건

사슴은 줄기와 돌 사이로 몸이 들어가면 직진한다. 예정 이동 구간에서 실제 몸체가 레벨의 충돌 표면에 닿을 때만 방향을 보정한다. 대상은 지형 이동 훅을 사용하는 Server/Standalone 통합 Native v3 사슴의 일반 이동·도주·이주다. 지형 훅이 없는 기준 세계나 가져온 원판으로 재생하는 실험은 기존의 기하 계약을 따른다.

모든 일반 Static Mesh와 ISM/HISM·Foliage 인스턴스에 동일한 판정 경로를 쓴다. 기준은 배치된 컴포넌트의 쿼리 활성 여부, 기존 이동 채널에 대한 Block 응답, 인스턴스 변환과 실제 이동 쿼리가 보는 충돌 형상이다. 나무 이름·메시 경계 상자·Archetype으로 통행을 판정하지 않는다. 지면으로 쓰는 메시에는 기존 보행 가능 경사와 단차 규칙을 적용한다. `SM_pine02_ForestA`는 줄기 캡슐을 가진 예시다. 공유 Foliage Type 교체는 별도 레벨 작업이다. 5cm는 기존 스캐너의 수집 기준이며 실제로 Block하는 작은 물체를 통과하는 값으로 쓰지 않는다.

## 접촉 판정과 최종 위치

1. 기존 정책·Social·이주·개체 간 조향에서 이번 스텝의 원하는 변위를 받는다. 정지 개체는 이동 쿼리를 만들지 않는다. 실제 몸 반경은 현재 개체 크기와 기존 이동 규칙에서 얻는다. 사전 여유 반경이나 전방·좌우 탐색을 추가하지 않는다.
2. 월드 어댑터가 실제 몸체로 이동 구간을 쓸어 본다. 첫 구현은 현재의 30cm 분할과 각 구간의 지면 높이를 사용한다. 통과하면 기존 직진 결과를 채택한다. 지면 없음·경사·금지 구역·개체 간 접촉을 Static Mesh 측면 충돌로 기록하지 않는다.
3. 첫 Blocking Hit에서 검증된 부분까지 접근한다. 중심의 안전한 도착점은 스윕의 `Hit.Time` 또는 `Hit.Location`에서 구하고, `ImpactPoint`는 표면 접점 표시용으로 사용한다. 이미 사용한 거리와 남은 거리를 구분한다. 시작부터 겹친 경우는 별도 사유로 기록하고 마지막 안전 위치 또는 기존 복구 경로를 사용한다. 반복해서 같은 위치를 밀어내지 않는다.
4. 접촉면을 향하는 성분을 남은 수평 변위에서 제거하고 접선 후보 하나를 만든다. 정면 충돌로 접선 길이가 거의 0이면 직전 성공 방향, 동률이면 StableAgentId 기반의 일관된 좌우 선택을 쓴다. 남은 거리 위에서만 시도하고 두 번째 장애물 또는 예산 소진 시 검증한 범위에서 멈춘다. 모양이 파묻혀 보이는 사례가 확인될 때만 접촉 후 정지 간격을 조정한다.
5. 어댑터 결과에는 허용 종점(XY와 지면 Z), 거절 원인, 실제 접촉 여부와 법선을 담는다. 원래 경로와 꺾인 경로 모두 해당 구간의 지면·단차·수심·지역 경계·개체 간 접촉 조건을 만족해야 한다. 후보를 조회하는 동안 위치, GroundZ, 여정 도착, 섭식·포획 상태를 변경하지 않는다. Native가 선택된 결과를 한 번 반영하고 후속 로직이 실제 위치를 읽는다.

권위 처리에서 실제 위치를 쓰는 주체는 기존 Native Step이다. 사슴별 Actor·충돌 Component·OnComponentHit delegate·충돌 RPC를 추가하지 않는다. 같은 스텝에서만 필요한 hit는 지역 변수로 소비한다. 다음 스텝 또는 진단이 읽는 최소 상태만 기존 개체 Fragment에 둔다. 예를 들어 `LastStaticHitStep`과 수평 법선을 저장하면 전체 개체의 bool을 매번 초기화할 필요가 없다. 스텝 번호는 지역 이동·복원 시의 유효성을 정의하고, 오래된 접촉과 성공 방향은 만료시킨다. 접촉마다 Tag/Fragment를 추가·삭제하지 않는다. 필드가 기존 저장 형식에 들어가는지 확인하고 일시 상태는 생성·복원·지역 인계 때 초기화한다.

## 거리 LOD와 서버 프레임 예산

| 상황 | 추가 회피 처리 |
| --- | --- |
| 근거리 또는 곧 가시 범위에 들어올 개체 | 접촉한 이동에서 접선 후보 최대 하나를 허용한다. |
| 중거리 | 접촉 후 재시도를 여러 스텝에 분산하고, 최근 성공 방향을 우선한다. |
| 모든 관찰자에게 먼 개체 | 통상 접선 탐색을 생략한다. 이동 의도가 지속되지만 전진하지 못한 개체에는 대기 순서를 고려해 제한적으로 재시도 기회를 준다. |

기존 서버 관찰자·복제 관련성 입력에서 가장 중요한 연결을 기준으로 정한다. 관전 카메라, 관찰자 없는 전용 서버, 경계 왕복을 포함한다. 승격은 보이기 전에 수행하고 강등에는 거리 완충과 지연을 둔다. 사냥·이주 등 중요한 상호작용의 장기 정체도 측정한다. 거리와 재시도 주기는 실제 맵 비교로 정한다. 클라이언트는 기존 위치·방향 복제와 보간을 사용한다.

선택적 접선 검사의 예산은 **서버 월드의 한 프레임**이 공유한다. 지역별 또는 같은 프레임에 따라잡는 Native Step별로 예산을 새로 주지 않는다. 후보 수와 실제 하위 Sweep 수를 모두 계측하고, 긴 후보 하나가 30cm 분할로 상한을 소진할 수 있음을 반영해 실제 쿼리 단위로 제한한다. 반복해서 탈락한 개체에 우선권을 주고 동률은 StableAgentId로 결정한다. 기본 충돌·지면 검사가 필요한데 이를 생략한 채 이동을 승인하지 않는다.

## 선택적 최적화: 빈 구간의 몸체 Sweep 생략

기본 판정이 병목일 때만 추가한다. 이동 어댑터 안에서만 “이 구간에 장애물이 있을 수 있는가”를 조회한다. 이미 있는 공간 자료가 실제 차단 물체 전체를 포괄하고 무효화까지 보장하는지 먼저 확인한다. 기존 5cm·높이 필터, 원판 수 상한, 몸 중심의 지역 포함 여부로 축약한 스캔 결과만으로 빈 공간을 증명할 수 없다.

- 실제 몸 반경·높이와 고저차를 포함하는 구간 전체를 조회한다. 인접 셀에서 넘어온 형상, 회전·스케일된 인스턴스, 바닥과 측면을 함께 가진 메시까지 포함한다. 후보가 있을 가능성만으로 이동을 막지 않는다.
- **비어 있음이 확인된 구간**만 정적 장애물 Sweep을 생략한다. 같은 쿼리로 잡던 다른 차단체까지 누락된다면 검사 대상 채널을 분리하거나 기존 Sweep을 사용한다. 지면·수심·금지 볼륨의 유효성 검사는 별도로 수행한다.
- 셀 로딩·언로드, 컴포넌트 등록·제거·이동, 충돌 응답 변경, Foliage 인스턴스 변경에 대해 사용 전 무효화를 보장한다. 인덱스 세대가 오래됐거나 갱신 여부가 불명확하면 실제 월드 쿼리로 돌아간다. 서버 월드의 해당 충돌 데이터 자체가 준비되지 않은 구간은 진입을 보류한다.
- 비교 예시로 같은 구성의 사슴 30마리 중 15마리가 확인된 빈 구간, 15마리가 후보 구간에 있고 10마리가 실제 접촉한다고 하자. 각 경로와 접선 후보가 1개 하위 구간이고 접촉한 10마리가 모두 재시도하면 몸체 Sweep은 40회에서 25회로 준다. 충돌에 따른 Archetype 이동은 0회다. 37.5%는 이 가정의 쿼리 횟수 감소이며 CPU 예측값이 아니다.

## 적용·측정·삭제 순서

1. **A — 기존 방식 기록.** 같은 브랜치·빌드 설정, 맵, Foliage 참조·인스턴스 수, 시드, 사슴 수와 체격, 서버 틱률, 시야 조건을 기록한다. 원판 사전 검사와 실제 Sweep·지면 조회·금지 볼륨 순회 시간을 분리한다. 과거 원본 소나무의 갈색 원 접촉률은 새 메시의 물리 충돌 기준선으로 사용하지 않는다.
2. **B — 접촉 회피로 교체.** 실제 월드 이동의 단일 선택 지점에서 기존 사슴 원판 판정과 새 판정 중 하나만 실행한다. 일반·도주·이주와 디버그를 같은 결과에 연결한다. A 보고서 또는 비교용 빌드를 확보한 후 생산 사슴 경로의 구 호출, 전용 상태·통계와 중복 재시도를 제거한다. 공통 Native 기준 세계에는 해당 세계가 소비하는 원판 경로를 남긴다. 두 방식이 같은 변위를 순차 보정하는 단계는 두지 않는다.
3. **C — 빈 구간 생략 비교.** B의 실제 쿼리 비용이 유의할 때만 같은 입력에서 공간 선별을 추가한다. B보다 서버 p99가 반복 편차를 넘어 개선되고 안전·진행·네트워크 지표가 유지될 때 채택한다. 그 외에는 B를 최종 경로로 쓰고 C 전용 인덱스·갱신 훅을 제외한다. B 자체가 통행 또는 성능 기준에 실패하면 전환을 보류하고 마지막 검증 빌드로 돌아간다.

### 사용자 실행과 완료 판정

기존 [MoveTest 실행 흐름](09_AVOIDANCE_INTEGRATION_SPEC_20261112.md)에 `eco.MoveTest Run StaticMeshAvoidance`를 추가하는 안이다. 기존 2개체 [회피 실험](13_MOVE_TEST_APPLIED_AVOIDANCE_GUIDE.md)과 구분해 실제 권위 월드에서 결과를 수집한다. A/B/C, 맵·빌드·개체 수·프레임별 실행 스텝 수, 테스트 조건과 미관측 항목을 보고서에 남긴다. 임의의 실시간 화면 출력은 기본 OFF다. `eco.V3Debug.Obstacles`를 켰을 때 선택한 개체의 예정 구간, 실제 접점·법선, 허용 종점과 막은 컴포넌트/인스턴스를 확인할 수 있게 한다. 인스턴스 번호는 해당 시점의 진단에만 사용한다.
