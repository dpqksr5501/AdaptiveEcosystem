# 지역 생태계 조향·회피 통합 계획

2026-11-16에 `jwj-1115`의 `69519972`를 기준으로 작성한 구현 계획이다. 이후 작업 트리에 1~4단계 코드가 이어졌다. [4단계 실행 설정](13_MOVE_TEST_APPLIED_AVOIDANCE_GUIDE.md)에 현재 명령, 실험 범위와 자동화 클릭 순서를 기록한다.

## 사용자가 콘솔에서 검증하는 흐름

첫 구현에 디버그 진입점을 포함한다. 이후 기능은 구현과 함께 해당 단계의 콘솔 재현 장면, 수집 항목, 통과 기준, 예상 출력 예시를 제공한다. **실행은 사용자가 시작한다.** Codex는 코드 변경 후 저장소 규칙의 직접 UBT 빌드를 수행하고, 사용자가 생성한 보고서를 읽어 다음 변경을 결정한다. 에이전트가 별도로 Unreal Automation Test나 PIE 런타임 검증을 실행하는 절차는 사용자 콘솔 실행으로 대체한다.

1. 사용자가 Play를 시작하고 콘솔에서 예를 들어 `eco.MoveTest Run HeadOn`을 입력한다. 단계별 시나리오 이름만 알면 실행할 수 있도록 시드·측정 구간·비교 모드 기본값을 제공한다.
2. 명령이 맵·backend·권위·시나리오 전제 조건을 검사한다. 실제 개체를 관찰하는 명령은 현재 v3 세션을 이용한다. 배치나 이동 규칙을 바꾸는 재현은 전용 v3 테스트 맵에서 실행한다. 기본 `/Game/JWJ/Integration_JwJ`의 Legacy 세션에서 v3 시나리오를 요청하면 필요한 테스트 맵을 콘솔에 안내한다.
3. 재현 명령은 같은 초기 배치·시드로 각 구간을 시작하고, 정해진 Native 스텝 수 동안 데이터를 수집한다. 해당 비교를 한 세션에서 초기화할 수 없는 경우에는 깨끗한 다음 세션에 입력할 명령과 비교 Run ID를 출력한다. 과거 상태를 부분 복사해 같은 초기 조건이라고 판정하지 않는다.
4. 화면에는 현재 단계, 대상, 경과 스텝과 완료 여부를 표시한다. 종료 시 Output Log에 결과 한 줄과 저장 경로를 출력한다. 사용자는 출력 한 줄 또는 Run ID를 전달하고, Codex는 저장소의 로컬 보고서를 찾아 후속 변경 근거로 사용한다.

| 명령 예시 | 동작 |
|---|---|
| `eco.MoveTest Help` | 현재 빌드에서 지원하는 시나리오, 테스트 맵, 필요 접속 수 표시 |
| `eco.MoveTest Observe` | Inspector 선택 사슴을 읽기 전용으로 기록. 선택이 없으면 ID 지정 방법 표시. `Observe <StableAgentId>` 지원 |
| `eco.MoveTest Run HeadOn` | 전용 맵에서 사슴 정면 교차 재현 및 준비된 비교 구간 실행 |
| `eco.MoveTest Status` | Run ID, 모드, 완료 스텝, 보고서 위치, 멀티 접속 준비 상태 표시 |
| `eco.MoveTest Stop` | 현재 실행 종료, 임시 모드 해제, 수집분을 중단 결과로 저장 |

개발용 빌드에서 기존 Inspector·계측 및 Native 실행을 재사용한다. World별로 실행 하나를 관리하고 동일 명령 중복 입력, PIE 다중 World, 월드 종료, 대상 사망을 처리한다. 명령이 여는 실험은 완료·중단 시 임시 설정을 복구한다. 재현이 배치를 변경한 전용 세션은 다음 비교 전에 초기화한다. 클라이언트는 수신값을 기록하며 권위 이동 실험은 서버 콘솔에서 시작한다. `NetBoundary`는 사용자가 준비한 Dedicated + Client 2 세션을 사용하며 부족한 접속은 콘솔에서 안내한다.

## 단계별 구현과 사용자 재현

| 순서 | 구현 | 사용자 명령 예시와 결과 |
|---|---|---|
| 1. 흔들림 기준선 | 기존 Inspector에 관찰 명령 연결. 행동·목표·기본 조향·최종 제어·실제 변위·표현 yaw와 도주 시점을 기록 | `Observe`로 사용자가 본 장면을 기록. 같은 목표 안의 반전, 목표 교체, 지형 차단, 표현 회전을 구분 |
| 2. 정확 탐색과 이동 경계 | 기존 동족 관측의 후보와 누산 순서를 보존하며 후보 조회를 비교. 모든 사슴의 제어 계산 완료 후, 실제 이동 전의 불변 입력을 정리 | `Run Baseline`에서 같은 시드의 원본/변경 경로 비교. 관측·mask·요청·위치·RNG·장부 차이 0 |
| 3. 예측 회피 비교 | 현재 이동을 실행하면서 상대 위치·속도·몸 크기로 회피 후보를 별도 계산. 초과 후보, 위험 상대, 기존 분리와 새 보정을 기록 | `Run ShadowHeadOn` 및 `Run Crossing`에서 기존/제안 방향·예측 최소 간격·비용 비교. 기존 실행 결과 일치 |
| 4. 사슴 회피 적용 | 전용 세션에서 기존 목표 조향 뒤 회피 보정을 적용. 지형 detour 이후 후보, 정지 상태, 긴급 도주 제약 확인 | `Run HeadOn`, `Run Graze`, `Run Flight`에서 동일 조건의 Off/Enabled 비교. 반전·겹침·도착·섭식·긴급 지연을 기록 |
| 5. 늑대와 포획 | 늑대 동료 회피와 포획 가능한 현재 표적에 대한 접근을 구분. 기존 포획 시점 유지 | `Run Hunt`에서 동료 교차, 표적 추격과 은신처 경계의 포획 허용·금지 결과 확인 |
| 6. 통로 양보 | 폭·입구·출구가 지정된 테스트 통로에 통행 순서와 대기·해제 적용 | `Run Corridor`에서 양방향 진행, 장기 대기와 취소·사망 이후 점유 해제 확인 |
| 7. 복제·표현 | 지역과 실제 거리·상호작용 중요도를 기존 Bubble과 표현 선정에 반영 | `Run NetBoundary`에서 경계 반대편의 가까운 개체, 재진입·late join, 전송 bytes·샘플 지연·표현 수 확인 |

새 회피는 같은 시점의 이동 입력을 읽어 보정 속도만 제안한다. Native가 실제 지면·접촉 제약을 확인하고 최종 위치를 한 번 갱신한다. 초기 사슴 비교는 기존 분리력을 포함해 기록하고, 중복으로 밀어내는 현상이 관찰되면 별도 비교 모드에서 조정한다. 좁은 통로와 늑대 접촉은 독립 시나리오로 평가한다. 이동 경로가 달라지면 다음 관측과 생태 결과도 달라질 수 있으므로 고정 입력에서 정책 선택 일치와 자유 실행에서의 생태 결과를 각각 확인한다.

## 보고서와 후속 개발

저장 위치는 `AdaptiveEcosystem/Saved/Profiling/EcoMovement/<RunId>/`로 제안한다. `Summary.json`은 시나리오·모드·버전·맵·월드·시드·모델·개체 수·실제 스텝 수·지표·판정·누락 이유를 담는다. `Samples.csv`는 원인 분석에 필요한 개체별 시계열을 담는다. 서로 다른 환경에서 얻은 두 보고서는 비교 조건 불일치를 표시한다. 포획 미발생, 대상 부족, 사용자 중단은 `Incomplete`로 표기한다. 관찰 전용 실행은 `Recorded`로 표시하고 기능 통과의 증거로 집계하지 않는다.

초기 제안 목표는 원인 구간의 방향 반전 지표 30% 감소, 도달 가능 장면의 도착률 하락 1%p 이내, 도착 시간 p95 증가 10% 이내, Native Step p95 증가 5% 이내, 새 평상시 보정으로 인한 긴급 도주 지연 0스텝이다. 비교 전에 기준선·구간·문턱을 확정한다. 짧은 사용자 실행은 문제 재현과 기능 확인에 쓰고, 성능을 판정할 때는 같은 명령의 측정 프로필로 비교 구간을 늘린다. CPU/전송 측정에는 화면 진단과 상세 CSV 비용을 분리한다.

사용자 실행 결과가 도착하면 Codex는 보고서에서 통과·실패·미측정 항목과 영향을 받은 단계부터 확인한다. 예를 들어 행동과 목표가 같은데 실제 이동만 반전되면 회피·지형 보정을 먼저 조정하고, 화면 yaw에서만 반전되면 표현을 수정한다. 다음 변경과 함께 다시 입력할 명령 한 줄을 전달한다. 콘솔 실행 증거가 필요한 단계는 보고서가 오기 전까지 검증 대기로 기록한다.

4단계의 `Run HeadOn`, `Run Graze`, `Run Flight`는 같은 시드에서 시작하는 독립 Native fixture 두 개를 사용한다. 3단계의 정면 비교는 `Run ShadowHeadOn`으로 열 수 있다. 4단계 결과 판정에는 사용자가 실행한 보고서가 필요하다.

기술 근거는 [Epic Mass Avoidance](https://dev.epicgames.com/documentation/unreal-engine/mass-avoidance-overview-in-unreal-engine), [Epic MassGameplay](https://dev.epicgames.com/documentation/unreal-engine/overview-of-mass-gameplay-in-unreal-engine), [Reynolds의 조향 계층 GDC 원문](https://www.red3d.com/cwr/steer/gdc99/), [Planet Coaster 군중 개발 사례](https://www.gamedeveloper.com/audio/game-design-deep-dive-creating-believable-crowds-in-i-planet-coaster-i-)를 따른다. 콘솔 실행 절차와 프로젝트별 판정값은 이번 개발 계획의 제안이다.
