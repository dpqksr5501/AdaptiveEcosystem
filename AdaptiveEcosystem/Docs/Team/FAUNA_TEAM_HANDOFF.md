## 종별 학습 정책 연결 경계

사슴의 Native v3 R7e는 서버·단독 월드에서 사슴의 개체별 관측으로 행동을 요청한다. 늑대는 Native 위협 규칙을, 여섯 규칙 종은 각 종 프로필과 개체 상태를 사용한다. 사슴의 학습 입력·행동 순서·마스크·가중치는 기존 계약을 따른다. `eco.V3Brain.Load`는 사슴 전용이다. 기존 사슴 파일은 그대로 읽고, 파일에 선택 메타데이터 `species_id`가 명시되어 있으면 `Herbivore`만 허용한다. [사슴 모델 로더](../../Source/AdaptiveEcosystem/AI/Policy/EcoV3Brain.cpp) · [정책 계약과 실시간 적용](../RL_Policy/LIVE_ADAPT_SPEC.md)

- 다른 종 모델을 연결할 때는 종 ID, 관측과 행동 계약, 모델 ID를 함께 검증하고 결정 스텝 경계에서 활성화한다. 규칙 종의 행동 후보를 고르는 기존 경로에서 모델 요청을 소비할 수 있다. 모델이 없거나 로드·출력 검증이 실패하면 해당 종의 규칙을 사용하고 실패 원인을 기록한다.
- 종 프로필의 먹이·체급, 감각 증거, 위험, 행동 가능 조건과 접촉·지형·권위 검증은 실행 계층에서 확인한다. 정책 출력으로 Transform·HP·자원·출생·사체 장부를 직접 쓰지 않는다. Client는 권위 결과의 표현을 소비한다.
- 개체 템플릿에서 규칙 종, Native 사슴/늑대, Legacy/StateTree 실행기를 섞으면 거부한다. 통합 템플릿은 샌드박스 v3 태그도 거절하며 샌드박스 Step·Visual은 통합 개체를 쿼리에서 제외한다. Native 결정과 위치 반영은 종 ID 및 배타적인 조각 구성을 확인한다. 같은 월드에서 서로 다른 종의 실행기가 공존할 수 있다. [템플릿 검증](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoCreatureTemplateValidation.cpp) · [규칙 종 템플릿](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFauna.cpp) · [Native 실행기](../../Source/AdaptiveEcosystem/AI/Policy/EcoPolicyV3IntegratedProcessors.cpp) · [혼합 태그 회귀](../../Source/AdaptiveEcosystem/AI/Policy/Tests/EcoPolicyV3MassTest.cpp)
- 사슴은 Native 긴급 도주와 실제 Social 은신처 예약을 이미 적용한 스텝에 일반 생활 규칙이 이동을 덮지 않도록 한다. 유효한 Social 예약 또는 공유 도주를 쓰는 동안 플레이어 경험은 관측·감쇠를 이어간다. 일반 은신처는 현재 플레이어 회피·경계가 적용된 스텝의 방향을 덮지 않는다. 이주 중에는 이전 스텝의 Social 적용 기록으로 도착을 보고하지 않는다.
- 새 모델을 받으면 같은 시드에서 해당 종만 정책 ON/OFF를 비교하고, 요청·허용/거절 이유·실행·실제 섭취/접촉과 다른 종의 개체군을 함께 기록한다. 모델 누락·다른 종 파일·잘못된 관측 계약·도주 중 요청·사망 직전·저장 복원·Client 합류도 확인한다. 저장은 권위에서 사용한 모델과 그 종의 fallback 상태를 식별할 수 있어야 한다.

### 다른 종 모델의 접점과 인수 기준

현재 다종 개체군 시험은 사슴 R7e와 나머지 종의 현재 규칙을 함께 평가한다. 다른 종의 실제 모델은 아직 연결되지 않았다. 기존 사슴 로더의 저장소는 프로세스 전역이고 체크포인트도 활성 사슴 모델 ID 하나를 확인한다. 다른 종 모델을 받을 때는 별도의 월드별·종별 등록과 체크포인트 호환 검사가 필요하다. 새 종 파일에는 종 ID를 필수로 넣고, 사슴 파일의 기존 호환 규칙은 보존한다. [사슴 레지스트리](../../Source/AdaptiveEcosystem/AI/Policy/EcoV3Brain.h) · [현재 체크포인트](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoEcosystemCheckpoint.cpp)

| 단계 | 모델 적용 시 사용할 경계 |
| --- | --- |
| 후보 생성 | 현재 지각과 유효기간이 남은 기억에서 지상/비행, 접근 가능한 먹이, 은신, 도주, 이주 등 가능한 후보와 안정 ID를 만든다. 서버에만 있는 숨은 먹이 위치나 성공 여부를 입력으로 넘기지 않는다. 안전·물리 제약으로 불가능한 행동과 규칙이 낮게 평가한 행동을 구분한다. |
| 후보 선택 | 기존 규칙 점수와 모델 선택은 같은 후보 집합에서 결정의 출처를 선택하는 두 경로다. 한 결정 스텝에 모델 ID 또는 규칙 fallback 중 하나를 적용한다. 규칙의 기호·확률·체류 선호를 강제 마스크로 옮기면 학습이 기존 행동을 바꾸지 못한다. 마스크와 fallback에는 각각의 이유를 기록한다. |
| 실행·결과 | 기존 단일 이동·전투·섭취 실행기가 요청을 처리한다. 접촉 시점에 거리·시야·생존·체급·권위를 재검사하고, 실제 섭취와 실패를 각각 기록한다. 갈 수 없는 경로와 이미 사라진 대상에 대한 선택은 새 관측 또는 실패 결과로 돌려준다. |
| 교체·복원 | 종별 모델 ID·해시, 관측/행동/마스크 판, 활성화 시점, fallback 상태를 저장한다. 결정 경계에서 검증된 모델을 활성화하며, 진행 중인 사냥·섭취·이주는 기존 실행기가 마무리하거나 취소한다. 복원 시 후보 ID와 모델이 현재 월드와 맞는지 확인한 뒤 실행을 재개한다. |

한 종의 모델을 연결할 때 같은 시작 상태에서 규칙 기준과 모델 실행을 비교한다. 별도로 관측은 같지만 모델 요청을 실행하지 않는 비교를 두면 후보 누락, 선택의 차이와 실행 실패를 구분할 수 있다. 한 시드나 한 지도에서 개체가 오래 살아남는 결과는 다른 환경의 일반화를 입증하지 않는다. 검증에서 기온·시간대, 서식지와 먹이 배치, 포식자 수, 이동 경로 차단과 플레이어 압력을 바꾸고, 학습에서 제외한 시드·맵도 포함한다. 생존 외에 식사 성공률·실섭취량·추격 비용·실제 이주 도착과 비대상 종의 출생·사망을 본다. 기존 개체군에서 선택한 유지비나 먹이 수치를 고정된 보상 목표로 바로 쓰지 않는다.

2026-11-12 인수 경계는 현재 사슴 R7e와 규칙 종의 선택을 유지하는 것이다. 현지 자원이나 통로에 같은 정책을 노출해 결과가 바뀌는지 먼저 확인한다. 후보를 감지했는데도 행동 선택만 달라서 생긴 차이는 종별 모델 적용 후 비교한다. 규칙 포식자의 먹이 관계는 현재 규칙 종 목록에 있는 ID만 허용하며 살아 있는 Native 사슴은 후보가 될 수 없다. 이 범위를 넓힐 때는 실제 감각으로 위협을 전달하는 관측, Native 몸의 생존 상태와 사망 거래, 다른 포식자와 공유하는 사체 재고를 함께 검증한다. [먹이 관계 검증](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFauna.cpp) · [후보 검사](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFaunaMovement.cpp)

단계별 서식지 비교의 기준 커밋은 `cde24fa5`다. 현재 재개 기준은 이 문서 상단에 있다. [통합 PR #16](https://github.com/dpqksr5501/AdaptiveEcosystem/pull/16) · [생활 규칙 검증](../Architecture/FAUNA_POPULATION_BALANCE.md#허기위험에-따른-생활-행동)

## 첫 실행과 공통 기준

1. [프로젝트 공통 맥락](../PROJECT_CONTEXT.md)에서 UE 5.8, 권위 서버, 빌드 규칙을 확인한다. 위 표에서 검증 목적에 맞는 맵을 고른다. 팀 통합 맵을 대상으로 검증할 때는 맵과 결과를 별도로 기록한다.
2. 공개 체크아웃에는 코드와 작성 도구가 있다. 라이선스가 확인된 원본 모델·음원을 준비한 뒤 소유 테스트 맵을 생성한다. [로컬 에셋 준비와 맵 생성](../조연우/JYU_FAUNA_INTEGRATION_20261108.md#공개-pr과-로컬-재현)
3. 비교할 때 SHA, 맵, 활성 두뇌, 시드, 시간 배율, 서식지 단계와 대사·생활 규칙 설정을 기록한다. 0단계는 기준 설정, 1단계는 쥐 서식지, 2단계는 공유 대체 먹이, 3단계는 표범 배치·접근을 누적 적용한다. 생활 규칙은 기본 OFF이며 복사 맵에서 `-EcoAdaptiveRoutineMask`로 하나씩 시험할 수 있다. [규칙별 재현과 포획 진단](../Architecture/FAUNA_POPULATION_BALANCE.md#생활-규칙-분리와-포획-검증)
4. 장기 개체군은 `-EcoFaunaPersistence=0/1`로 비교한다. 60분 이상 종별 생존·출생·피식·기아와 처음 생존 0이 된 시점을 기록한다. 실제 이주 검증에서는 출발 개체의 ID와 도착을 함께 기록한다. [장기 유지 설정과 결과](../Architecture/FAUNA_POPULATION_BALANCE.md#장기-유지와-자원-변화에-대한-반응)
5. 면적이나 먹이 총량을 조정하기 전에 [개체군 붕괴 원인 보고서](../Architecture/FAUNA_PERSISTENCE_CAUSE_REPORT.md)에서 사냥 접촉, 실제 섭취, 인구 예산, 식생 교란과 검증 시간 조건을 확인한다.
6. 독립 감사에는 [전체 고려사항과 복사용 감사 프롬프트](ECOSYSTEM_INDEPENDENT_AUDIT_PROMPT.md)를 사용한다.
7. 사슴의 포만 상태 섭취 재현, 여덟 종과 시스템 전반의 제약, 수정 우선순위는 [2026-11-12 행동·구조 점검](../Architecture/ECOSYSTEM_BEHAVIOR_AUDIT_20261112.md)에 있다.

## 신규 동물 에셋 연결 순서

1. 스켈레탈 메시, Blend Space, AnimBP의 스켈레톤을 맞춘다. 지상 종은 `EEcoPresentationPose` 순서대로 기본 9칸, 비행 종은 이륙·비행·착지를 더한 12칸을 설정한다. 이동 칸은 Blend Space가 담당한다. 사망 클립의 마지막 자세와 애니메이션 루트 위치를 먼저 확인한다. [자세 슬롯 순서](../../Source/AdaptiveEcosystem/Creature/Representation/EcoCreatureAnimationProfile.h) · [애니메이션 프로필 검증](../../Source/AdaptiveEcosystem/Creature/Representation/EcoCreatureAnimationProfile.cpp)
2. 발 IK를 켠다면 몸통 기준 뼈, 다리 끝 뼈, 그 바로 아래 발 접촉 마커와 접촉 높이를 등록한다. 소유 복사본 PIE에서 평지·경사 걷기, 달리기→정지, 방향 전환과 사망 안착을 확인한다. 비행 종은 이륙·착지와 공중에서 발 IK가 꺼지는 시점도 본다. [애니메이션 회귀 도구](../../Tools/Editor/audit_jyu_fauna_motion.py)
3. 표현 클래스와 `FaunaSpecies`, 지역 배치에 같은 `SpeciesId`를 사용한다. 몸체·눈높이·단차·수심, 이동 속도, 성숙·출생, 먹이 관계를 프로필에 넣는다. Native v3 life가 활성화된 소유 복사본의 유효 지면에 한 마리를 배치해 표현을 확인한 뒤, 섭취·출생은 각각 실제 먹이와 두 부모가 있는 조건으로 확인한다. 발소리가 필요한 종은 같은 ID의 음향 프로필로 표면 재생과 주변 동물의 감지를 확인한다. [종 프로필 검증](../../Source/AdaptiveEcosystem/Creature/Runtime/EcoFauna.cpp) · [발소리 회귀 도구](../../Tools/Editor/audit_jyu_fauna_footsteps.py)
4. 두뇌를 받기 전에는 규칙 실행기로 월드 연결을 검증한다. 새 모델을 받을 때는 위 인수 기준에 따라 종별 선택을 연결하며 이동·피해·사체·개체군 결과는 공통 권위 경로에서 확정한다.

사냥은 `PreyRules`로 설정한다. `CarrionEnergyPerMeal=0`이면 다른 개체의 사체는 먹지 않으며, 직접 포획한 먹이는 기존 기본 한 입 분량으로 먹는다.

| 애니메이션·아트 | 팀 레벨에서 급반전, 경사 보행·정지, 작은 쥐와 어린 개체의 발 접촉, 까마귀의 착지·공중 사망을 본다. 종별 Blend Space·AnimBP와 Notify, 사망 마지막 포즈, 수신 메시와 히트 프록시 정렬을 확인한다. | 동일 조건의 프레임 기록과 사용 클립·스켈레톤을 남긴다. 사체 안착 및 섭식 가능 시각은 서버 담당과 함께 대조한다. |

대사 변경 비교를 먼저 고정하면 이후 먹이 배치나 모델 변경의 효과를 따로 읽을 수 있다. 에셋 준비, 권위·복제 회귀와 팀 레벨 지면 검증은 이와 병행할 수 있다.

## 이전 검증과 권위 경계

- 초기 소유 다종 맵의 별도 단계별 비교에서 UE 5.8.4 빌드, 자동화 299개, 단계별 30분 비교 10회와 60분 확장을 수행했다. 3단계는 여우가 세 시드 모두 생존했고 표범은 세 시드 모두 30분 전에 기아로 사라졌다. 쥐는 시드별 결과가 달랐고 60분에서는 쥐 2마리, 늑대 1마리였다. [당시 개체군 비교](../Architecture/FAUNA_POPULATION_BALANCE.md#최종-30분-비교)
- 이전 다종 전용 서버 접속·복제와 Standalone 프로세스 복원은 별도 실행이다. 최신 Standalone 결과는 [장기 유지 설정과 결과](../Architecture/FAUNA_POPULATION_BALANCE.md#장기-유지와-자원-변화에-대한-반응)에 기록한다. 포맷 7의 복수 Client, 팀 레벨, 패키지, 장기 플레이어 반복 사냥은 후속 검증 범위다.
- 생명주기와 피해·먹이 거래는 권위 서버에서 확정한다. Native 사슴·늑대와 규칙 종은 각자의 단일 이동 경로를 사용하고 Client는 Bubble 표현과 요약을 소비한다. 지역 식생, 서식지 먹이, 사체 재고는 각 지급 경계에서 차감한다.
