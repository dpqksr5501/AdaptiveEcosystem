## 송해찬 님 · 레벨 디자인

> 소유 복사 맵에 초지·숲 가장자리·경사지·물가를 여러 생활권으로 배치하고 실제 지상·수중 통로를 작성해 주세요. 첫 비교에서는 기준 맵의 군락 총 용량과 회복률을 유지해 배치와 접근성 차이를 확인하고 싶습니다. 물길은 낮은 수위와 높은 수위 각각에서 통과점과 피난 수역을 표시해 주세요. 팀 맵에 적용할 후보 위치와 추가 충돌·스트리밍 작업도 함께 알려주세요.

- **인계물** — 기준·변경 맵 패키지, 지역 ID, 지면·통로 경유점과 실패 위치, 패치 ID·용량·군락 유형, 입수·상륙점, 수위·수심·유속, 횃대·둥지와 비행 접근, 지형별 Physical Material을 담은 작성표. 첫 후보는 초지·습윤 물가·숲 가장자리 먹이의 초기 총량과 재생을 유지하고 배치만 바꾼다. 낮은 수위 우회로, 생활권 확장은 각각 후속 변형으로 인계한다.
- **첫 완료 확인** — 말 또는 물소가 지상 출발점에서 먹이까지 실제 도착하고, 밍크가 강변의 입수·상륙 지점을 사용하며, 한 어종이 높은 수위에 통과해 도착 뒤 먹는다. 낮은 수위에서는 통과 제한과 대체 피난처를 확인한다. 종별 추가 표본은 같은 맵에서 확장한다.
- **팀 맵 렌더·스트리밍** — 정적 장식의 인스턴싱·LOD·HLOD를 동일 카메라에서 비교한다. 셀 경계를 통과해 원본과 프록시가 중복되거나 사라지는지 기록한다. 동적 군락 BP는 저·고수위와 셀 언로드·재진입에서 서버 재고, 차폐, 외형이 각각 이어지는지 확인한다. 맵 담당은 같은 경로의 건조·젖은 Physical Material과 차폐 지점을 플레이어 담당에게 전달한다. ## 장원준 님 · 플레이어 입력·사냥·발소리

> 팀에서 쓰는 플레이어 입력과 무기 경로로 새 지형에서 걷기·은밀 이동·달리기, 지상과 물가 경계 통과, 실제 사냥을 재현해 주세요. 플레이어 발소리는 현재 거리 기반 타이밍이므로 접지 Notify를 쓸 수 있는 리그와 적용 범위도 확인해 주세요. 로컬에서 들린 소리, 서버가 기록한 청각 증거, 동물의 실제 반응을 한 타임라인에서 비교하고 싶습니다.

- **인계물** — 입력·무기·캐릭터·표면 설정, 재현 맵과 경로, 시각/서버 타임스탬프, 표면·보행 상태·발 ID를 담은 로그. 사냥은 명중한 StableAgentId, 서버의 피해 승인·거절 사유, 사망 원인 및 사체 생성까지 이어지는 기록을 공유한다.
- **첫 완료 확인** — 전용 서버와 조작·관찰 클라이언트에서 단단한 지면→마른 흙→젖은 강변→얕은 물을 걷고, 같은 경로를 은밀 이동과 달리기로 반복한다. 정지·비접지 때 재생 여부, 접촉당 중복, 시야가 가려진 구간의 권위 청각을 각각 확인한다. 한 번의 치명 피해가 한 건의 권위 사망과 사체로 이어지고, 사체 소비와 늦게 접속한 클라이언트 표현도 같은 개체 ID로 추적되는지 확인한다.
- **함께 확인할 경계** — 플레이어 입력과 전투·오디오는 장원준 님의 기존 경로를 사용한다. 클라이언트의 접지·오디오 표현과 서버 청각 증거는 각 경로의 입력을 검증하고, 동물 쪽 반응은 기존 감지·위협 실행기에서 확인한다. Physical Material과 차폐 지점은 송해찬 님의 작성표를 쓴다. [발소리·청각 계약](../Architecture/FAUNA_FOOTSTEPS_AND_HEARING.md) · [사냥 권위와 재현](../Architecture/PLAYER_HUNTING_IMPLEMENTATION_AND_TEST_20261106.md)

## 권신혁 님 · 학습과 종별 정책

> 현재 학습 중인 종과 내보낼 모델의 계약, Unreal에서 처음 비교할 후보 종을 알려주세요. 기존 사슴 R7e를 기준으로 고정한 상태에서 동일 맵·시드의 해당 종 규칙 실행과 모델 실행을 비교하고 싶습니다. 먹이가 가까이 없었던 경우, 감지했지만 고르지 않은 경우, 선택했지만 실제 포획이나 섭취에 실패한 경우를 로그에서 구분할 수 있도록 필요한 관측과 행동 계약을 같이 확인해 주세요.

- **인계물** — 후보 종과 현재 내보낼 수 있는 시점, 종 ID, 모델 버전·해시, 관측 순서·단위·정규화, 행동과 마스크 버전, 학습에 사용한 세계 조건, 검증 시드, C++·Python Golden Vector, 로드 실패 시 규칙 복귀 조건. 관측 후보는 개체가 직접 감지한 증거, 다른 개체에서 받은 신호, 서버에서만 볼 수 있는 비교용 진단을 구분한다. 실행기에서 허용·거절한 요청과 실제 결과를 매칭할 키를 적는다.
- **첫 완료 확인** — 사슴 R7e 기준 회귀와 후보 한 종의 규칙/모델 비교를 각각 기록한다. Raw Request, 실행 가능 조건, 실제 이동·접촉·섭취를 매칭하고 다른 종의 사망·출생도 함께 집계한다. 도달할 수 있는 자원과 통로가 바뀐 실행에서도 모델의 선택 근거를 비교한다.
- **함께 확인할 경계** — 행동 후보의 선택을 정책에서 인계하고 이동·피해·자원·생명주기는 기존 권위 실행기가 확정한다. 현재 다종 진단 자료는 `training_ready=false`이며 새 관측이나 학습 데이터로 쓰려면 관측 가능성과 Python 쪽 대응을 확인한다. [사슴 정책과 모델 선택](../RL_Policy/LIVE_ADAPT_SPEC.md) · [새 종의 선택 결과 인계](../조연우/JYU_EXPANDED_FAUNA_20261113.md#후속-두뇌의-먹이-선택-인계)

## 공동 검증 순서

1. 생태 담당은 기존 소유 맵의 짧은 무개입 실행을 기준으로 기록하고, 송해찬 님과 후보 맵에 같은 시드·스폰 조건·초기 먹이 예산을 적용한다. 실제 도달, 식사, 출생·사망, 이동 실패 사유를 기록한다. [공간 비교표](../Architecture/FAUNA_HABITAT_CAPACITY_20261113.md#면적배치두뇌-비교-계획)의 배치·통로·면적을 한 단계씩 시험한다.
2. 장원준 님과 정해진 이동·사냥 시나리오를 같은 맵에 추가한다. 무개입과 플레이어 개입을 대조해 차폐·발소리·피해와 동물 반응을 비교한다. 플레이어 쪽 짧은 검증과 학습 계약 준비는 맵 기준을 만드는 동안 병행할 수 있다.
3. 권신혁 님이 인계한 후보 모델은 해당 종만 켜서 비교한다. 검증된 맵·정책 조합으로 30·60 게임분을 돌리고 서로 다른 시드의 생존·섭취·포식·출생·이주를 공유한다.

공통 실행 기록에는 **담당자, 맵 패키지·Git SHA와 로컬 변경 경로, 시드·게임 시간·배속·프레임 조건, 모델 버전, 스폰과 자원 초기값, 수위·날씨, 바뀐 입력, 재현 절차, 실제 결과, 미확인 항목**을 남긴다. 각 실행의 `StableAgentId`, 지역·패치 ID, 게임 시각을 맞추면 도달 실패와 감지·선택·실행·섭취를 연결할 수 있다. 에셋이 로컬에만 있으면 필요한 패키지 경로와 작성 스크립트를 함께 적는다. [검증 파일과 재현 위치](LOCAL_TEST_EVIDENCE.md)
