# MassEntity 기반 동적 생태계 플러그인 — 상품성 및 구현 설계 검토 요청


안녕하세요. 저희는 Unreal Engine 프로젝트에 도입할 수 있는 **MassEntity 기반 동적 생태계 플러그인**을 개발하고 있으며, 상용 판매를 목표로 제품 범위와 구현 구조를 정리하고 있습니다.

제공하려는 기능은 지역의 자원·포식 위험·개체군 변화와 개체의 섭식·생존·사망·이주를 연결하는 생태계 플러그인입니다. 
게임 개발자가 이 기반을 직접 구축하는 시간을 줄이고, 자신의 환경·동물·행동 시스템을 연결해 지속적으로 변화하는 생태 콘텐츠를 제작하도록 하는 것이 해당 플러그인의 목표입니다.

### 1. 멘토링 정리
설명에 앞서 질문 드리고 싶은 것은 다음과 같습니다.
먼저, 플러그인으로 마켓에 출시하기 위해서 어떤 점을 고려해야 하는지입니다. 저희는 게임 개발 및 기능 개발을 중심으로만 수행해와서 실제로 마켓에 제품을 출시해 본 경험이 전무합니다. 이런 상황에서 실제로 어떤 지점이 상용 서비스를 출시하는데 있어 중요한 부분인지 알고 싶습니다.

두 번째로 현재 개발 현황 및 계획에 대해 전체 파이프라인을 설명드릴텐데, 눈에 띄는 문제점 또는 모순점이 있는지 궁금합니다.
혹은 프로젝트 구조 자체에 대한 의문점도 말씀해주시면 감사하겠습니다.
(예를 들어, 대규모 처리에 있어서 이 방식은 잘 안쓰이지 않나요? Player 화면에 보이지 않는 Entity들을 굳이 처리해줄 이유가 있을까요? 같은 것입니다.)

동물이 먹이를 소비하면 지역 자원이 줄고 개체 에너지가 변합니다. 이때 자원의 고갈이나 개체들의 과밀도, 포식자에 의한 위험은 각 동물들의 행동 양식을 바꾸고, 소비·피식·사망·이주 결과는 지역 자원과 종별 개체군에 반영됩니다. AI끼리의 상호작용뿐만 아니라 플레이어의 사냥·접근·자원 공급도 같은 흐름에 연결합니다. 이때, 플레이어로부터 멀어진 화면 밖 지역의 상태도 유지하여 재방문했을 때 이전 상호작용 그리고 주변 상호작용의 결과가 이어지는 구성을 목표로 합니다.


### 2. 프로젝트 구조

전체 파이프라인은 다음과 같습니다.
```text
환경·플레이어 압력 / 지역 자원·위험·개체군
        ↓
개체 관측 → 행동 의도 → 이동·상호작용
        ↓
섭식·에너지 변화·피식·사망·이주
        ↓
지역 자원·종별 개체군·위험 기록 갱신 → 다음 행동에 반영
```
이러한 연결을 여러 프로젝트에서 재사용할 수 있는 플러그인으로 제공하려 합니다. 구매자는 생태계의 공통 실행 규칙을 활용하면서 자신의 종 설정, 레벨 환경, AI, 이동, 표현, 게임플레이 이벤트를 결합하는 방식입니다.

### 2.1 타겟 고객
고려하는 고객으로는 대규모 생태계 렌더링, 순환 구조, 데이터 처리 방식을 공부하고 싶은 개발자와 자신의 프로젝트에서 생태계 환경을 직접 구현하기 위한 비용을 줄이고 싶은 개발자입니다.

### 2.2 제품에 포함하려는 기능과 산출물

| 제품 구성 | 제공하려는 내용 | 결과 |
| --- | --- | --- |
| 생태 Runtime | 지역 자원, 지역·종별 Population, 생태 압력, 생성·섭식·생존·사망·이주 | 행동 결과가 누적되는 생태계 기반 |

## 3. MassEntity를 선택한 이유

대규모 개체의 에너지·지역·행동·생명주기를 반복 계산하는 상태를 Fragment로 구성하고, 비슷한 연산을 Chunk 단위로 처리하는 MassEntity를 기반 기술로 선택했습니다.

MassEntity는 같은 구성의 Entity를 Archetype·Chunk에 모으고 Processor가 데이터를 일괄 처리하는 구조를 제공합니다. 
이를 통해 공통 생태 계산을 개체별 Actor 실행에 묶지 않고 구성하려 합니다. 
실제 성능 이점은 동일한 기능·규모·밀도의 비교 시험으로 확인할 계획입니다. 

| 제품 요구 | 선택 이유 | 제품 설계에서 확인할 사항 |
| --- | --- | --- |
| 반복되는 생존·자원·행동 계산 | 데이터 중심의 일괄 처리 | 밀집도·종 구성·World 접근을 포함한 실제 비용 |
| 논리 상태와 화면 표현의 분리 | Entity를 논리 본체로 유지 | Actor 생성·제거와 생태 생명주기의 독립성 |
| 규모에 따른 비용 제어 | Simulation·Replication·Representation LOD 연결 | 각 LOD의 예산·상태 전환·결과 오차 |

현재 팀 프로젝트에서 생태계·Mass·정책·Social·동물 표현을 연결하고 있습니다. 

| 영역 | 현재 개발 기반 | 제품으로 정리할 방향 |
| --- | --- | --- |
| 생태 상태·식별 | 권위 지역 상태, StableAgentId, 지역·종 ID와 runtime index | 공개 데이터 계약·등록/조회 API·저장 버전 |
| 자원·생존·이주 | 자원 배분·보존, 대사·기아·사망·이주·집계 경로 | 종별 설정을 유지하는 공통 실행·사건 처리 |
| 행동 연결 | C++ 네이티브 정책 추론, Utility, Social 의도·이동 인계의 팀 통합 | 기본 정책과 사용자 정의 정책의 교체 지점 |
