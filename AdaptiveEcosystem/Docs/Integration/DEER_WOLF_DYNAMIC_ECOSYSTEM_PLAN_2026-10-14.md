## 1. 원하는 결과

각 지역에서 사슴은 먹이 구역을 오가며 섭식·휴식·무리 생활을 하고, 늑대는 별도 거점에서 휴식·순찰하다 배고플 때 사냥한다. 조우하면 사슴의 경계→도주/은신→회복이 보이고, 늑대의 추적에는 실패·포기·식사·휴식이 존재한다.

최종 성공은 다음 순환의 관측이다.

`날씨/플레이어 압력 → 먹이 공급·노출 변화 → 사슴의 관측·행동 변화 → 섭식/도주/피식/이주 → 지역 Food·Population·PredationHistory 변화 → 다음 행동 변화`

생존을 항상 보장하거나 즉시 리스폰으로 사망을 상쇄하는 방식은 장기 운영 모드의 균형 근거로 사용하지 않는다. 정상 환경에서 지속성과 회복을 평가하고, 극심한 자원 고갈·포식 압력에서는 멸종도 가능한 결과로 둔다.

### 전체 피드백

현재는 종별 기능이 통합된 실행 기반은 있으나, 사슴의 평상시 생활과 늑대의 사냥 비용을 충분히 표현하지 않는다. 특히 초기 공간 배치가 바로 조우를 만들고 짧은 포획 대기가 연속 사망을 허용한다. 공간·행동·자원·개체군을 함께 구성해야 한다.

다음은 **확인할 원인 후보**이며 이번 로그만으로 확정된 사망 원인은 아니다.

1. **뒤쪽 위협과 도주 유지**: 기존 Perception의 `AwayFromPred/DistPredMin`은 현재 시야의 포식자에서 만든다. 도망가며 늑대를 등지면 기하 입력이 없어질 수 있다. Social Alarm이 행동 가중치를 올려도 실제 도주 방향이 없으면 계속 도망친다고 보장할 수 없다. 개인 기억/무리 경보의 마지막 위치를 어느 소비자가 이용하는지 확인한다.
2. **은신처로 직진**: 예약 목적지 선택은 현재 이동 벡터를 직진으로 대체한다. 늑대 쪽으로 향하는 경로·장애물·막다른 길의 위험을 따로 판단하지 않는다. 충돌 시 멈춤/실패는 우회 경로 탐색과 다르다.
3. **이주 우선순위**: 현재 SelectVelocity는 비Resident Travel을 먼저 처리한다. 긴급 도주가 이주 경로에서 보장되는지 확인한다.
4. **식사 중 지속 이동**: 기본 Steering은 영벡터를 제외하면 일정 속력으로 정규화한다. 먹이량이 줄어도 자동으로 느리게 걷거나 풀을 뜯으며 멈추는 생활 상태가 생기지 않는다.
5. **공간 자원의 약한 의미**: Food Provider는 지역 잔량과 한 지점의 매끄러운 분포를 사용한다. 먹이 지점 밖에도 지역 잔량 비율의 30% 밀도가 남는다. 실제 패치별 고갈·빈 공간의 의미는 없다.
6. **학습 환경 차이**: Python은 실제 먹이 셀과 흡수 가능량으로 먹고 사망 슬롯을 리스폰한다. Unreal은 `Forage × Density` 요청과 Energy 지급을 사용하며 사망 후 개체가 줄어든다. 짧은 포획 대기는 기존 고정 슬롯 학습 환경에서 조정한 값이므로 영구 사망 생태계의 균형값으로 바로 쓰기 어렵다.

EntityConfig의 중복 MassCustomMovementTag/EcoVitalsFragment 경고도 재현·정리 대상으로 둔다. 이를 포식의 직접 원인으로 단정하지 않는다.

## 3. 3지역의 공간 구성

coordinator는 **월드에 하나**를 유지하고 Groups에 Forest/Barren/Highland를 둔다. 지역마다 사슴 시작 구역과 늑대 시작 구역을 독립적으로 지정한다. 종별 스폰 지점은 엔티티의 초기 위치이며 지속적인 생활 거점·순찰 경로와는 구분한다.

| 지역 | 사슴 시작·생활 구역 | 늑대 시작·생활 구역 | 먹이/은신 구성 | 의도한 차이 |
| --- | --- | --- | --- | --- |
| Forest | 숲 안쪽 풀밭, 완만한 지면 | 숲 외곽 바위 거점 | 먹이 3곳, 실차폐 은신처 2~3곳, 우회 출구 | 차폐·무리 경보로 추격을 끊는 장면 |
| Barren | 식생이 남은 작은 초지 | 초지 반대편 암석 구역 | 먹이 2곳, 암석 차폐 1~2곳, 외부 이주 통로 | 먹이 부족과 개방 공간의 위험 사이 선택 |
| Highland | 완만한 분지·능선 아래 초지 | 다른 능선의 거점 | 먹이 2~3곳, 바위/지형 차폐 2곳, 검증된 경사 통로 | 지형·도달 가능성에 따른 생활 및 도주 |

위 지형과 개수는 새 배치 제안이며 현재 레벨에 모두 있다는 뜻이 아니다. 물 시스템·후각·계절·새 식물 Entity는 첫 구현의 의존성으로 두지 않는다.

배치 절차:

1. 최초 비교 실험은 기존 8/1, 4/1, 4/1 수량을 유지한다. 개체 수와 위치를 동시에 크게 바꾸지 않는다.
2. 초기 종간 최단 거리 60~100m를 후보로 삼는다. 실제 최대 시각·청각 범위보다 충분한 여유를 확보하고, 가시선/발소리 경로도 확인한다. 간격만으로 30초 평온을 보장하지 않는다.
3. 사슴 시작 위치는 먹이와 가까운 구역에 분산한다. 초기에 모든 사슴을 하나의 점으로 몰지 않는다.
4. 늑대는 거점에서 휴식/순찰을 시작하고, 일상 순찰이 먹이 구역 주변의 조우 통로와 연결되도록 한다. 서로 영구 격리되면 계획 실패다.
5. 은신처는 후보 지점에서 실제 LOS를 끊고 도달 가능한 탈출 경로가 있어야 한다. 원형 반경/슬롯 예약만으로 무적 처리하지 않는다.
6. 모든 스폰·생활·도착 지점에 지면/충돌/지역 내부 검사를 한다. 지형 로딩은 세 지역의 논리 실행을 지원하도록 구성한다.

현재 배열로 1차 분리는 가능하다. 이후 편집 편의를 위해 지역별 사슴/늑대 Spawn Marker, Food Patch Anchor, Den/Patrol Anchor를 추가하는 것을 제안한다. Marker는 배치 입력을 제공하고 별도 Mass 생성 coordinator가 되지 않는다. 모든 종·wave의 후보 지점 수와 점유/재사용 규칙도 검증한다.

## 4. 사슴: 생활과 위협 대응

PPO는 기존 7관측·4행동 Raw Action을 제공하고 Social은 비파괴 보정한다. 생활 상태는 행동 선택·섭식 자격·속도/표현을 설명하는 개체별 runtime으로 제안한다. 독립 이동 writer를 추가하지 않는다.

| 상태 | 행동과 전이 |
| --- | --- |
| Grazing | 먹이 패치 내 저속/정지 섭식. 실제 지급량만 Energy로 환산. 가까운 위협이면 즉시 중단 |
| Foraging | 배고프거나 패치가 고갈되면 다른 먹이 지점으로 이동 |
| Resting / Regrouping | 안전하고 Energy가 충분하면 쉬거나 무리로 복귀. 개인별 체류시간에 차이 |
| Alert | 개인 감지/무리 경보를 확인하고 섭식 억제·위협 위치와 탈출 경로 평가 |
| Fleeing / ShelterTravel | 유효한 위협 반대 방향 또는 안전한 은신 경로. 기억 유지시간 동안 시야 밖 위협도 처리 |
| ShelterHold / Recovering | 위협 거리·감각 신뢰도·경보 감소를 확인 후 해제. 곧바로 먹이로 돌아갔다 재추격되는 진동 방지 |
| Migrating | 자원·위험·수용 능력과 이동 생존성을 평가한 지역 간 이동. 긴급 위협 대응과 재개 규칙 명시 |

안전성 요구:

- 개인 직접 감지, 개인 기억, 무리 전달 정보를 구분한다. 기억 위치는 마지막으로 알려진 위치이며 숨은 늑대의 실시간 Transform을 조회해 보정하지 않는다.
- 기본 제안 우선순위는 `사망/불능 → 즉각적인 접촉 위험 회피 → 도달 가능하고 더 안전한 은신/도주 → 정상 이주 → 생활/PPO 의도`다. 도주 중 Travel 진행·중단·재개와 Region membership은 한 계약으로 확정한다.
- 은신 목적지 직진이 위협을 통과하면 다른 후보/우회/일시 도주를 선택한다. 실패 피드백은 예약 해제·재선정으로 연결한다.
- 현재 FleeDist의 의미는 도주 개시 거리 임계치다. 이를 도주 힘 가중치로 조용히 바꾸지 않는다.
- 사슴을 계속 달리게 만드는 대신 평상시 이동·섭식·휴식과 긴급 도주를 구분한다. 속도 변화는 아래 opt-in 행동 계약에서 평가한다.

## 5. 늑대: 제한된 사냥 기회와 비용

현재 감각 기반 이동을 확장하고, 초기에는 늑대 PPO 학습을 새 의존성으로 만들지 않는다.

`Resting → Patrolling → Investigating → Chasing → Feeding → Satiated/Resting`

실패 경로는 `Chasing → LostTarget/Search → GiveUp → Resting/Patrolling`로 둔다.

필수 규칙:

- 배고픔이 사냥 동기를 만든다. 포만 시 새로운 표적 감지와 공격 허가를 분리한다.
- 공격 허가를 포식 Processor에서도 확인한다. 이동만 멈춰도 반경 안의 사슴을 계속 죽일 수 있는 구조를 막는다.
- 추격 시간·추격 비용·휴식 회복이 존재하고 감각 정보가 오래되거나 표적을 잃으면 포기한다.
- 기초 생존 Energy와 짧은 전력 질주용 Stamina는 의미를 분리한다. 상태는 개체 Fragment, 종별 불변 설정은 Shared/프로필로 둔다.
- 포획 성공 뒤 한 마리를 먹는 상태와 포만 상태를 유지한다. 실험용 식사 대기 후보는 8~15초지만 학습 상수 0.67초를 즉시 덮어쓰지 않는다.
- 포획 에너지 보상은 공통 Death receipt의 predator ID를 통해 한 번만 지급한다. 초기에는 현재 즉사 포획을 유지해 사냥 빈도부터 검증하고, 여러 번 공격/부상/사체 자원은 후속 단계로 분리한다.
- 늑대 대사를 켜는 것만으로 사냥 중단이 생기지 않는다. 죽음에 따른 개체군 균형과 살아 있는 늑대의 포만/피로 행동을 모두 연결한다.

초기 실험 후보: 사슴 평상시 1~3m/s·도주 9m/s, 늑대 순찰 2~4m/s·추격 7~9m/s, 추격 상한 10~20초. 이는 아직 존재하지 않는 runtime 프로필 값이며 검증 후 선택한다. 한 번에 모두 바꾸지 않고 위치→사냥 허가/식사 대기→추격 비용→속도 순으로 비교한다. 사슴을 항상 빠르게 하거나 늑대를 무조건 느리게 하는 대신 도주 성공과 포식 성공이 모두 나와야 한다.

## 6. 먹이·환경·개체군의 폐루프

### 6.1 실제 먹이 위치와 회계

1차는 기존 FoodPatchPosition과 지역 잔량을 유지해 평온한 섭식 장면을 확인한다. 2차에는 다중 패치의 공간 잔량과 소진/재생을 도입한다.

- Ecology가 패치 원장과 지역 Food 집계를 같은 자원 transaction으로 소유한다. 활성 패치 합계를 Region FoodAmount로 집계하고 외부 FoodSupply/손실도 해당 원장에 분배한다. 두 독립 잔량을 별도로 갱신하지 않는다.
- World의 Patch Anchor는 위치·반경·수용량·환경 특성을 제공한다. 각 Actor가 자체 Food를 별도로 소비하지 않는다.
- Provider의 밀도·기울기와 실제 먹을 수 있는 자원은 동일 원장에서 나온다. 패치 밖은 먹을 수 없고 고갈된 패치는 공급이 회복될 때까지 비어 있다.
- 소비 요청은 패치 접촉·섭식 가능한 상태·실제 dt·에너지 흡수 가능량으로 제한한다. Forage는 탐색/행동 선호도와 분리해 학습 환경과의 차이를 명시한다.
- 지급량만 Energy에 반영하고 최대 Energy에서 버려지는 잉여 때문에 불필요한 Food 소비가 발생하지 않게 한다.
- 자원 합격 식은 `기말 = 기초 + 재생 + 외부 공급 - 소비 - 명시적 손실 ± 허용 반올림 오차`다.

### 6.2 지역별 공급과 위험

Forest는 상대적으로 풍부한 식생/차폐, Barren은 낮은 공급/긴 먹이 이동, Highland는 중간 공급/지형 제약을 실험 목표로 둔다. 현재 기본 재생은 0이므로 장기 지속성 시험에는 재생 설정이 필요하다.

재생 숫자는 실제 섭식량을 측정한 뒤 정한다. 무포식 평온 시나리오에서 사슴의 평균 대사 비용을 지급 Energy가 감당하는지 먼저 확인하고, 지역 총 Food 소비 대비 재생 비율을 달리해 유지·고갈·회복 시나리오를 만든다. 강수량 변화와 공급 변화, 먹이 고갈과 이주를 같은 seed/FPS 조건으로 비교한다.

V1에는 물/체온/계절 관측이 없다. 물이나 온도가 논리 생존에 새로운 영향을 주는 기능은 정책 계약·학습 환경을 함께 확장한 후 추가한다.

### 6.3 개체군과 이동

- 초기에는 wave off로 사망의 원인을 평가한다. 통제된 재공급 시연과 실제 번식은 구분한다.
- 번식은 사슴의 충분한 자원/에너지·안전성·cooldown·지역/전역 cap을 조건으로 후속 구현한다. 늑대 증가는 먹잇감·성공한 섭식·지역 수용 능력에 연동한다.
- 단순 사망 즉시 리스폰으로 정상 개체군 유지 성공을 주장하지 않는다.
- 이주 후보는 먹이·최근 피식·혼잡·경로 길이·도착 가능성으로 비교한다. 짧은 시간에 지역을 왕복하지 않도록 체류/재판단 조건을 둔다.
- 종별·지역별 `현재 Population = Births - Deaths + MigrationIn - MigrationOut`를 항상 유지한다. 실험적 외부 도입은 Births의 하위 사유로 별도 기록한다.
- 화면 밖/Client relevance 밖에서도 먹이·대사·포식·지역 결과를 유지한다. Representation Off는 사망이 아니다.

## 7. 정책·이동·권위 계약

- Server/Standalone이 Mass·Ecology·Social의 논리 권위를 유지한다. Client는 요약과 개체 표현만 받는다.
- `Raw Action → Social EffectiveAction/TargetPosition → 최종 Movement → Feedback`을 보존한다. Raw Action은 개체별 Fragment에 남긴다.
- 현재 사슴 Steering과 늑대 PredatorMovement의 쿼리 분리를 유지한다. 각 Entity의 Transform/Velocity 최종 작성자는 하나다. Social·생활상태·섭식·표현은 추가 위치 적분을 하지 않는다.
- Box Bootstrap 가드와 기존 테스트 경로를 유지한다. 새 동물 프로필은 명시적인 opt-in이며 기존 V1 생성 헤더를 손으로 고치지 않는다.
- V1 7→64→64→4와 기존 가중치를 우선 보존한다. 생활 속도/감각 기억/사냥 비용/공간 먹이가 바뀌면 스키마가 같아도 학습 전이가 같다고 주장하지 않는다.
- 프로필별 버전·수치 manifest·관측/행동/조향의 변경점을 기록한다. Python 평가 fixture에 새 사냥·섭식·지형 시나리오를 대응시키고 RL 담당과 계약을 확정한다. 필요하면 별도 프로필로 재학습·export한다.
- Golden Vector는 native 수치 추론/조향을 검증한다. 생활 상태와 전체 환경의 동등성은 고정 seed·동일 입력의 행동/자원 사건 비교로 별도 검증한다.

### 초기 시연 목표와 지표

- 통제된 시연에서 첫 20~30초 평상시 생활을 관찰하고, 이후 조우가 나오도록 배치/초기 휴식 상태를 구성한다. 운영 모드 전체 개체에 강제 무적 시간으로 적용하지 않는다.
- 시작 직후 Forest가 12초 안에 전멸하는 현재 재현은 제거 목표다. 단순 위치 분리로 늑대가 영원히 만나지 못하는 경우도 실패다.
- 초기 정상 조건의 5분 실행에서 3지역의 섭식→조우→도주/포획→회복을 확인한다. 지속성은 P5 이후 20~30분 실행으로 평가한다.
- 첫 조우/첫 사망 시점, 실제 사냥 시도 수, 포획 성공률, 포획 간격, 추격 길이, 포기 횟수, 사슴 상태 체류시간, 섭식 지급량, Energy, 원인별 Death, 지역 이동과 Food 잔량을 측정한다.
- 10개 고정 seed와 20/30/60FPS 조건으로 비교하되, 포획 시도 수처럼 분모가 없는 성공률을 해석하지 않는다. FPS별 사건 차이는 기록하며 현재 frame 이동의 완전 결정성을 가정하지 않는다.
- 게임 시연 기준으로 임시 포획 성공률 20~50%를 검토할 수 있으나, 무포획/즉시 전멸을 제외하는 진단 범위로만 사용한다. 관측 표본을 확보한 뒤 목표를 확정한다.
- 정상 환경의 지속성, 과도한 자원 부족에서 감소/멸종, 공급 회복 후 잔존 개체의 회복을 서로 다른 시나리오로 평가한다.

포획 로그 필드 제안: epoch/step/실제 감지·포획 시각, region/species, prey/predator stable ID, 위치·실제 거리·체감 거리, sight age/LOS, shelter radius/예약/점유, 개인·무리 위협, Raw/Effective action, 생활/사냥 상태, HP/Energy/Stamina, 공격 허가·거절 사유. 정상 틱마다 출력하지 않고 상태 전이·상호작용과 주기 요약으로 제한한다.

C++/빌드 입력 변경 시 루트 AGENTS.md의 직접 UBT 규칙을 따른다. UBT/dotnet/Editor/LiveCoding/MSBuild/ShaderCompileWorker가 실행 중이면 새 빌드를 시작하거나 기존 실행을 중단하지 않는다. 수치 계약 변경에는 Golden Vector/표적 동작 검증이 필요하며 이번 문서 작성에서 실행한 것으로 기록하지 않는다.
